## 1. 一句话定位

**Wit-HW 从一个已失败的 RTL testbench 出发，通过覆盖距离、寄存器状态轨迹距离和变异位置多样性生成“见证测试”，再用 Ochiai 谱系定位可疑语句；在 41 个 bug 上把 Top-10 定位率做到 36/41（88%），高于随机生成的 33/41 和 Tarsel 的 22/41。**

这里的“见证”不是形式验证中的 witness trace，而是与原失败测试行为相近、但能提供差异化执行谱的新增输入。方法的关键不是 LLM，也不训练模型：它用仿真反馈搜索测试，用通过/失败与语句覆盖谱给 RTL 语句排序。论文额外在 13 个真实开源 FPGA bug 上测试，6 个 bug 排到 Top-1 或并列 Top-1。

## 3. 输入 / 输出

### 3.1 输入

最小任务包含 buggy RTL、一个失败 testbench 和可逐周期比较输出的 validator。下面的 bug 会让计数器从 3 跳到 0，而规范期望从 7 回绕：

```verilog
module counter(input logic clk, rst_n, en,
               output logic [2:0] count);
  always_ff @(posedge clk) begin
    if (!rst_n) count <= 3'd0;
    else if (en && count == 3'd3) count <= 3'd0; // 可疑语句
    else if (en) count <= count + 3'd1;
  end
endmodule
```

失败测试是一串输入刺激及其期望输出。论文实验把正确 RTL 当 validator，按周期比较输出；算法不能读取正确 RTL 的内部实现。

```text
cycle:       0 1 2 3 4 5
rst_n:       0 1 1 1 1 1
en:          0 1 1 1 1 1
expected:    0 1 2 3 4 5
buggy:       0 1 2 3 0 1
first_fail:          ^
```

### 3.2 中间产物

每个候选测试产生三类信息：通过/失败标签、语句命中计数向量、寄存器值随周期变化的状态序列。搜索器保留离失败测试近、彼此又不重复的输入，并用突变位置的指数滑动平均抑制长期集中在同一输入位。

### 3.3 输出

输出是语句的 suspiciousness 排名，例如：

```text
rank  line  Ochiai  interpretation
1     5     0.913    count==3 的提前回绕分支
2     6     0.577    正常自增分支
3     3     0.204    reset 分支
```

工程师仍需检查第一名、确认根因并修改常数。Top-K 指标只问真实 bug 语句是否落在前 K 名。

## 4. 方法与架构

### 4.1 整体 Pipeline

```text
buggy RTL + failing test + validator
                  |
                  v
       mutate input signal/value
                  |
                  v
  RTL simulation -> coverage + state trace + pass/fail
                  |
                  v
 coverage/state distance + mutation-position diversity
                  |
                  v
       keep Top-10 witness tests
                  |
                  v
      Ochiai SBFL -> suspicious statements
```

流程对应论文的见证测试生成与 fault localization 两个阶段。公开实现以 Verilator 为主要仿真依赖，仓库还包含 simulator、Tarsel 和 buggy designs 等目录。

### 4.2 三个反馈信号

覆盖距离比较语句命中次数，鼓励候选测试探索与当前种子不同的控制路径。状态距离用动态时间规整比较寄存器状态转移，允许两条轨迹以不同速度出现相似变化。位置多样性记录输入信号最近被突变的频率，防止搜索反复改同一位而停滞。

候选的 seed fitness 与综合距离成反比；最终进入定位阶段的测试既要靠近原失败行为，又要带来足以区分语句的执行谱。这个平衡解释了为什么纯随机测试的 Top-10 已经不低，而完整方法仍能在 Top-1 和 Top-5 上显著领先。

### 4.3 模块职责矩阵

| 模块 | 输入 | 输出 | 工具/算法 | 训练 |
|---|---|---|---|:---:|
| 变异器 | 当前 seed、可变输入 | 新测试 | 信号/取值变异 | 否 |
| 仿真器 | RTL、新测试 | 波形、覆盖、结果 | Verilator | 否 |
| 距离计算 | 覆盖向量、状态轨迹 | 综合距离 | Euclidean、DTW | 否 |
| 多样性控制 | 突变位置历史 | 位置权重 | EWMA | 否 |
| SBFL 排名 | 测试结果与执行谱 | 可疑语句表 | Ochiai | 否 |

## 5. 关键公式

### 5.1 Ochiai 可疑度

$$
\operatorname{sus}(s)=\frac{e_f(s)}{\sqrt{(e_f(s)+n_f(s))(e_f(s)+e_p(s))}}
$$

- $s$：一条 RTL 语句
- $e_f(s)$：失败测试中执行语句 $s$ 的次数
- $n_f(s)$：失败测试中未执行语句 $s$ 的次数
- $e_p(s)$：通过测试中执行语句 $s$ 的次数

高分语句应频繁出现在失败测试、较少出现在通过测试。它是相关性排序，不是因果证明。

### 5.2 覆盖距离与综合距离

$$
D_{\mathrm{cov}}(x,y)=\sqrt{\sum_{i=1}^{m}(c_i(x)-c_i(y))^2}
$$

- $x,y$：两个测试
- $m$：被统计的语句数
- $c_i(x)$：测试 $x$ 对第 $i$ 条语句的命中次数

$$
D(x,y)=\alpha D_{\mathrm{cov}}(x,y)+\beta D_{\mathrm{state}}(x,y)
$$

- $D_{\mathrm{state}}$：寄存器状态轨迹的 DTW 距离
- $\alpha,\beta$：两种距离的归一化权重，实验设置为覆盖维度和状态维度的倒数

### 5.3 Seed 适应度

$$
F(x)=\frac{1}{1+D(x,S)}
$$

- $x$：候选测试
- $S$：当前种子集合
- $D(x,S)$：候选到种子集合的聚合距离

距离越小，候选越接近目标失败行为；多样性项再避免候选全部重复。

## 6. 训练与实验设置

### 6.1 是否需要训练

不需要训练神经网络，也不依赖 LLM。超参数包括突变概率 0.5、位置历史的衰减系数 0.1、多样性权重 1.0、100 次搜索迭代和最终 10 个 witness tests。论文设置的距离权重分别按覆盖维数与状态维数归一化。

### 6.2 Benchmark 与指标

主实验含 10 个设计、41 个 bug：12 个 easy、14 个 medium、15 个 hard。baseline 为 Tarsel、RTL-Repair 和随机测试生成。指标为 Top-1/5/10 以及 MAR；MAR 是真实 bug 语句首次出现名次的平均值，越低越好。

### 6.3 关键结果

| 方法 | Top-1 | Top-5 | Top-10 | MAR |
|---|---:|---:|---:|---:|
| Tarsel | 9 (22%) | 16 (39%) | 22 (54%) | 35.26 |
| RTL-Repair | 6 (15%) | 7 (17%) | 16 (39%) | 34.23 |
| Random | 14 (34%) | 24 (59%) | 33 (80%) | 20.80 |
| **Wit-HW** | **20 (49%)** | **30 (73%)** | **36 (88%)** | **16.90** |

消融中完整方法为 20/30/36；去掉 coverage 为 12/24/32，去掉 state 为 17/24/32，去掉多样性为 15/28/34。两类距离都贡献定位效果，位置多样性对 Top-1 尤其重要。平均运行时间为 45.7 秒，明显高于 Tarsel 的 1.7 秒和 RTL-Repair 的 2.1 秒，代价主要来自反复仿真。

## 7. 创新点

### 7.1 把“测试不足”作为定位精度瓶颈

传统 SBFL 被动使用现有测试；Wit-HW 主动构造 witness tests，让失败谱和通过谱提供更多区分信息。这比更换一个排序公式更接近验证工程的真实痛点。

### 7.2 同时比较路径和跨周期状态

仅看覆盖会忽略时序电路中“走了相同语句但状态不同”的情况。DTW 状态距离把寄存器转移纳入搜索，同时允许轨迹长度或事件时间略有错位。

### 7.3 用位置历史减轻输入变异坍缩

信号级变异很容易反复选中少数敏感输入。位置多样性为搜索提供轻量的探索约束，不需要额外训练代理。

## 9. 与芯片流程的关系

### 9.1 在全流程中的位置

上游是 testbench 已经暴露功能错误的 RTL 验证环境；Wit-HW 补充测试并给出可疑语句；下游是工程师或自动修复器验证候选根因、修改 RTL、重新回归。它可作为 LiK、RTL-Repair 一类修复方法的定位前端，但论文没有证明任意修复器都能因此提升。

### 9.2 从定位成功到可签核还有什么

Top-1 命中不等于补丁正确。修复后至少还要跑完整回归、形式或等价检查、lint/CDC、综合、STA、功耗与物理验证。论文中的 validator 是正确 RTL，真实项目往往只有规范、参考模型或不完整 checker，oracle 质量会直接限制方法。

## 10. 讨论与局限

### 10.1 论文证据支持的边界

方法对持续赋值、复杂条件依赖和复杂协议输入的处理仍有限；信号级随机变异可能产生协议非法刺激。反复仿真带来约 20 倍于轻量 baseline 的平均耗时。真实 bug 实验从原收集的 21 个问题中排除了 8 个，原因包括不支持的 SystemVerilog 特性或缺少 ground truth，因此不能把 13 个案例视为无筛选总体。

### 10.2 代码与复现门槛

公开仓库要求 Python 3.11 及 Verilator 5.027 或更高版本。当前资料包只归档论文并核对仓库入口，未重跑 41-bug 表格；因此复现状态记为 R1，而不是声称实验已复现。超大设计上保存和比较逐周期状态也可能成为内存与运行时间瓶颈。

### 10.3 本资料包的判断

这篇论文最适合作为“仿真预算如何分配给定位”的基线。后续研究可把固定的欧氏/DTW 距离升级为传播感知的时间窗或主动学习准则，但比较时必须控制相同仿真次数、相同 oracle 与相同候选语句集合，否则 Top-K 提升可能来自额外测试预算。

## 12. 一分钟复述版

Wit-HW 解决 RTL 仿真已经失败、但根因语句难找的问题。它不训练模型，而是从失败测试继续变异输入。每个新测试运行 RTL 仿真，收集语句覆盖、寄存器状态轨迹和通过/失败标签。覆盖欧氏距离、状态 DTW 距离和突变位置多样性共同选择 10 个 witness tests，最后用 Ochiai SBFL 排序。41 个 bug 上 Top-1/5/10 为 20/30/36，MAR 16.90；完整方法优于三组消融和随机测试。代价是平均 45.7 秒以及对可执行 validator 的依赖。它属于 RTL 设计与功能仿真调试，不涉及综合、PPA、芯片安全或后端签核。
