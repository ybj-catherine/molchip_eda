---

## 1. 一句话定位

**Mantra 是第一个基于真实硬件 bug 的开源 mutation testing 工具，从真实 bug 数据中提炼出 19 种硬件专用 mutation 算子（如 AOR 算术运算符替换、ASR 阻塞/非阻塞赋值混淆、LCR 逻辑连接符替换），并用时间感知的 mutation killing 机制利用硬件并行性降低测试成本，在 CirFix 和 OpenCores 数据集上实现最高 83.44% 的效率提升。**

---

## 2. 为什么重要

Mantra 是硬件 mutation testing 领域的奠基性工作。它的核心贡献是证明了「基于真实 bug 设计 mutation 算子」比传统的「通用软件 mutation 算子直接搬到硬件」更有效。

---

## 3. 19 种硬件专用 Mutation 算子

### 3.1 完整列表

| 缩写 | 全称 | 操作说明 | 硬件相关性 |
|------|------|----------|-----------|
| **AOR** | Arithmetic Operator Replacement | `+`↔`-`, `*`↔`/`, `%`↔`*` 等 | 高——数据路径常见错误 |
| **ROR** | Relational Operator Replacement | `>`↔`>=`, `<`↔`<=`, `==`↔`!=` | 高——边界条件错误 |
| **LCR** | Logical Connector Replacement | `&&`↔`\|\|`, `&`↔`\|` | 高——控制逻辑错误 |
| **ASR** | Assignment Statement Replacement | `<=`↔`=`（阻塞/非阻塞混淆） | **极高——硬件特有问题** |
| **UOI** | Unary Operator Insertion | `a`→`~a`, `b`→`!b` | 中——信号取反错误 |
| **SBR** | Statement Block Removal | 删除整个 if/case/always 块 | 高——功能缺失 |
| **BCR** | Bitwise Connector Replacement | `&`↔`\|`, `^`↔`~^` | 高——位操作错误 |
| **SCR** | Shift Connector Replacement | `<<`↔`>>` | 中——移位方向错误 |
| **CVR** | Constant Value Replacement | 常量值修改 | 中——参数配置错误 |
| **...** | （其余 10 种） | ... | ... |

### 3.2 为什么 ASR（阻塞/非阻塞混淆）是最高价值的硬件特化算子

```verilog
// 阻塞赋值（=）：立即生效，组合逻辑风格
always @(posedge clk) begin
    a = b;        // a 立刻变成 b 的值
    c = a;        // c 得到的是「新的 a」（=b）
end

// 非阻塞赋值（<=）：时钟沿后统一生效，时序逻辑风格
always @(posedge clk) begin
    a <= b;       // a 在时钟沿后变成 b 的值
    c <= a;       // c 得到的是「旧的 a」！
end
```

**真实 bug 案例**：工程师在时序逻辑中误用 `=`（阻塞赋值），导致信号更新的时序依赖出错。这是硬件设计中最常见的 bug 之一，在软件 mutation testing 中完全不存在。

## 4. 时间感知的 Mutation Killing

### 4.1 为什么需要时间感知

软件是顺序执行的，硬件是并行的。在同一个时钟周期内，多个信号同时变化。传统的 mutation killing 判断「输出是否不同」不适用于硬件——需要考虑时序。

### 4.2 Mantra 的做法

```
传统方法：比较 golden 和 mutant 的「最终输出」
  → 问题：如果错误被后续周期覆盖，可能漏判

Mantra 方法：比较 golden 和 mutant 的「每个时钟周期的输出」
  → 利用硬件并行性，在同一仿真中检测多个周期的差异
  → 更准确地识别 mutant 是否被 testbench 检测到
```

---

## 5. 与相关公开工作的区别

Mantra 用 19 类硬件专用 mutation 算子和时间感知 killing 判据评价验证环境。它属于固定算子 mutation testing，不等同于真实缺陷挖掘或通用 RTL 修复；引用时应保持这一任务边界。

## 6. 复现与使用边界

复现应固定每种算子的注入位置、可编译率、可激活率、被测试环境检出的比例以及时间窗口。若把这些算子用于别的数据集，应重新检查算子分布是否代表目标项目的真实缺陷。
