# OrderPlace 论文深度讲解

> **Order Matters: Unveiling the Hidden Impact of Macro Placement Sequences via Proxy-Guided LLM Evolution**
> Shibing Mo, Jing Liu, Jianchu Xu, Ruilin Wu
> ICML 2026 · arXiv:2606.08904
> 原文：[2606.08904_Order-Matters.pdf](./2606.08904_Order-Matters.pdf) · [2606.08904_Order-Matters.txt](./2606.08904_Order-Matters.txt)
> 代码：https://github.com/Explorermomo/OrderPlace

## 1. 一句话定位

**OrderPlace 用 LLM 演化“宏放置顺序策略”而不是直接搜索坐标，并用 wire-mask greedy proxy 降低评估成本；ISPD2005 上相对 WireMask-EA 和 EGPlace 分别降低 34.04% 和 14.08% HPWL。**

这句话里的三个承重点：

1. **顺序是独立优化维度** — 早期错误顺序会造成不可逆的可行域收缩，论文用贪心探测器放大顺序对 HPWL 的影响。
2. **LLM 生成代码级策略** — 搜索空间包括静态评分、连接权重、动态物理启发式，而非只调参数。
3. **proxy 评估** — wire-mask-guided greedy placement 只执行一次或少数 seed，快速筛选候选。

## 3. 输入 / 输出

### 3.1 输入

- 宏集合 $M$、尺寸、面积和 degree。
- 网表超边 $E$。
- 离散网格 $G$。
- 初始手工策略池和 LLM backend。

```text
instance = {
  macros: [(w,h,degree), ...],
  nets: [[m1,m3,m7], [m2,m5], ...],
  grid_size: 512,
  seeds: [0,1,2]
}
```

### 3.2 中间产物

- LLM 生成的排序策略代码。
- wire mask $W_m(i,j)$。
- 每个候选的 proxy HPWL、best/worst HPWL 和 runtime。

```text

std = 0.06e5
```

### 3.3 输出

```text

```

## 4. 方法与架构

### 4.1 整体 Pipeline

```text
Initial strategies
       │
       ▼
LLM generates/evolves ordering code
       │
       ▼
Syntax and executability check
       │
       ▼
Wire-mask-guided greedy proxy
       │
       ▼
Parallel evaluation
       │
       ▼
Top-K elite selection
       │
       ▼
Next generation
       │
       ▼
Final ordering strategy
```

### 4.2 核心模块逐个详解

- **策略生成器**：LLM 输出排序函数，可包含静态指标、连接强度或动态物理量。
- **Wire-mask greedy**：对每个候选网格点估计 HPWL 增量，快速决定当前宏的放置位置。
- **Fitness evaluator**：多种子运行 greedy placement，取平均 HPWL，降低单 seed 噪声。
- **Evolution loop**：用 top-K 精英和 LLM 重新生成下一代。

### 4.3 模块职责矩阵

| 模块 | 输入 | 输出 | 工具/模型 | 是否需训练 |
|---|---|---|---|---|
| Strategy proposal | 当前策略池 | candidate code | GPT/Claude/Qwen 等 LLM | 否 |
| Validation | candidate code | accepted/rejected | Python syntax check | 否 |
| Proxy evaluation | strategy | HPWL, runtime | greedy placer + wire mask | 否 |
| Evolution | proxy scores | next population | LLM + top-K | 否 |

## 5. 关键公式

### 5.1 Greedy 位置选择

$$
p_t=\arg\min_p \Delta HPWL(\pi_t,p,B)
$$

- $p_t$：第 $t$ 个宏的最优位置
- $\pi_t$：当前要放置的宏
- $B$：已放置宏的边界集合

### 5.2 HPWL

$$
HPWL(P)=\sum_{e\in E}\left(\max_{i\in e}x_i-\min_{i\in e}x_i+\max_{i\in e}y_i-\min_{i\in e}y_i\right)
$$

- $P$：当前 placement
- $E$：net 集合
- $x_i,y_i$：pin 坐标

### 5.3 Fitness

$$
fitness(\Pi)=\frac{1}{K}\sum_{i=1}^{K}HPWL(\Pi,seed_i)
$$

- $\Pi$：放置顺序策略
- $K$：seed 数量
- $HPWL(\Pi,seed_i)$：第 $i$ 个 seed 下得到的 HPWL

## 6. 训练与实验设置

### 6.1 是否需要训练

不训练。使用 inference-time LLM 生成和演化策略。LLM 只负责生成排序函数，模型权重不变；主要成本来自 proxy greedy evaluation 和 API 调用。

### 6.2 实验设置

- 主基准：ISPD2005。
- baseline：MaskPlace、ChiPFormer、WireMask-EA、EfficientPlace、EGPlace。
- 评估：多 seed mean ± std；完整实验 time limit 1000 分钟。

### 6.3 关键实验结果

| 方法 | 相对 OrderPlace 的 HPWL 差异 |
|---|---:|
| WireMask-EA | +34.04% |
| EGPlace | +14.08% |
| OrderPlace | baseline |

OrderPlace 在多个 ISPD2005 circuit 上取得更优 HPWL，且在混合尺寸任务中与 DREAMPlace 组合后仍有提升。

## 7. 创新点

1. 把“宏放置顺序”从静态预处理升级为可学习、可演化的策略维度。
2. 用低不确定贪心探测器放大顺序信号，避免完整 placement 搜索的高成本。
3. 用 wire-mask proxy 并行筛选，使 LLM evolution 能扩展到标准 benchmark。

## 9. 与芯片流程的关系

### 9.1 在全流程中的位置

OrderPlace 位于宏 placement 的输入层，把排序策略交给下游 greedy placer 或 analytical placer。它不影响 RTL、综合、CTS 和 routing 工具本身，但会改变 placement 的搜索起点。

### 9.2 从“HPWL 改善”到“能做成芯片”之间还缺什么

最终 placement 仍需 detailed placement、CTS、routing、DRC/LVS 和 signoff；论文在 ChipBench 上补做了 post-route PPA，但未覆盖工业全流程。

## 10. 讨论与局限

### 10.1 论文自述的局限

LLM API 调用和 greedy probing 仍有成本；不同 LLM backend 的策略多样性和收敛速度不同。

### 10.2 代码/复现层面的问题

仓库开源，但复现需要配置 LLM API、benchmark 和运行时间预算。论文中的 LLM backend、seed 和 time limit 会影响最终策略和 HPWL。

### 10.3 本资料包的批判性分析

proxy 的质量决定了搜索是否可靠；如果 greedy probe 与真实 placer 行为不一致，排名信号可能失效。论文的收益依赖顺序维度，但并非所有 placer 都对输入顺序同样敏感。

## 12. 一分钟复述版

传统宏放置通常只决定坐标，宏的进入顺序往往被固定为面积、度或 netlist 顺序。OrderPlace 让 LLM 生成排序算法，用 wire-mask greedy 作为便宜代理，并行评估后保留 top-K，再继续演化。最终发现的最优顺序策略接入 greedy 或 DREAMPlace，能在 ISPD2005 上显著降低 HPWL。
