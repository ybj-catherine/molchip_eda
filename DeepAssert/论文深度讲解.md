## 1. 一句话定位

**DeepAssert 是一个「四步走」的 LLM 辅助细粒度断言生成框架：先用一个 LLM 从 golden RTL 里提取模块间关系（调用关系 + 端口 + 信号传播变化），再据此把顶层规格拆成「每个子模块自己的功能规格」，然后为每模块挖出「条件 + 期望结果」的验证项，最后生成模块级「深断言」——解决「spec 方法只写顶层断言、RTL 方法又需要昂贵 golden 模型」的双重痛点，断言更靠近 bug 源头、能更早报错。**

这句话里的四个承重点：

1. **关系提取 RE（第一步）** — 用「LLM① Relationship Extractor」从 golden RTL 提取三类关系：模块调用关系（L^r）、端口信息（L^p）、跨接口的信号传播变化（L^s）。
2. **子模块规格抽取 SE（第二步）** — 用顶层规格 S + 关系 L，推每个模块的功能规格 F(m_i)，**不依赖其内部 RTL 实现细节**（和 AssertMiner 同一条「解耦」原则）。
3. **验证项抽取 IE（第三步）** — 为每模块挖出「触发条件 + 期望结果」的验证项 V(m_i)。
4. **深断言生成 DGen（第四步）** — 用 S + R + L + F(m_i) + V(m_i) 生成每模块的深断言 A(m_i)。

## 3. 输入 / 输出

### 3.1 输入

| 输入项 | 说明 |
|---|---|
| **golden RTL（R）** | 正确参考 RTL |
| **顶层规格（S）** | 自然语言高层规格 |
| **LLM** | 现成 LLM（多个角色：关系提取器 + 规格抽取 + 断言生成） |

### 3.2 中间产物

- **关系集 L = {L^r, L^p, L^s}**：模块调用关系、端口信息、信号传播变化；
- **每模块功能规格 F(m_i)**；
- **每模块验证项 V(m_i)**（条件 + 期望结果）。

### 3.3 输出

- 每模块的**深断言 A(m_i)**（比 AssertLLM / Spec2Assertion 更细粒度、更靠近 bug 源头）。

## 4. 方法与架构

### 4.1 整体 Pipeline（四步）

```text
golden RTL (R)  +  顶层规格 (S)
        │
        ▼
① 关系提取 RE：LLM① → L = {L^r 调用关系, L^p 端口, L^s 信号传播变化}
        │
        ▼
② 子模块规格抽取 SE：S + L → F(m_i)（不依赖内部 RTL 实现）
        │
        ▼
③ 验证项抽取 IE：每模块 → V(m_i)（条件 + 期望结果）
        │
        ▼
④ 深断言生成 DGen：S + R + L + F(m_i) + V(m_i) → A(m_i)
```

### 4.2 关键设计点

**（1）LLM 多角色分工** — 至少一个「关系提取器」专门负责从 RTL 提取三类关系（L^r / L^p / L^s），后续步骤消费这些关系，形成结构化中间表示。

**（2）规格抽取与 RTL 实现解耦** — SE 阶段只用顶层规格和模块关系，不用模块内部 RTL 实现推导功能规格，避免照着可能有 bug 的实现写规格，与 AssertMiner 的独立规格推理原则一致。

**（3）「深断言」的含义** — 不是只对顶层 I/O 写，而是下沉到模块内部功能，让断言在**更靠近 bug 源头**的地方触发，缩短调试定位时间。

## 6. 训练与实验设置

### 6.1 是否需要训练

**不需要。** 纯推理时 LLM 提示 + 结构化中间表示，不微调模型。

### 6.2 关键结果（摘要级，待核）

- 深断言质量**显著优于 AssertLLM、Spec2Assertion**；
- 可**无缝集成**到现有自动断言生成方法，提升整体断言质量与覆盖率；
- 断言在**更靠近 bug 源头**处触发，缩短调试时间。

## 7. 创新点

### 创新点 1：四步框架（关系提取 → 规格抽取 → 验证项抽取 → 深断言）

把「细粒度断言生成」拆成四个可独立复用的步骤，中间用显式关系集 L 和验证项 V 做结构化衔接。

### 创新点 2：模块级深断言（相对顶层断言）

把断言从顶层 I/O 下沉到模块内部功能，让断言更早、更精确地报错。

### 创新点 3：规格抽取与 RTL 实现解耦

SE 不用内部 RTL 推规格，呼应「oracle 独立」原则。

> ⚠️ **研究边界**：DeepAssert 已覆盖模块级目标定位、关系提取和深断言，但没有评估带困难负例的监督排序、完整的可控到可观察路径证明或真实历史缺陷终局。

## 9. 与芯片流程的关系

DeepAssert 落在“写断言之前”的模块级目标定位环节，横跨 ② 仿真与 ⑥ 形式验证。其目标粒度是模块级，证据来自调用、端口和信号传播关系提取，而不是完整的因果路径证明。

## 10. 讨论与局限

### 10.1 论文自述局限（摘要级）

1. 依赖**准确的模块端口配置与模块间关系**——规格里这些未必显式给出；
2. 效果依赖**顶层规格和 RTL 质量**。

### 10.2 本资料包的批判性分析

1. **「信号传播变化 L^s」并非完整因果证明**：它提取的是信号跨接口如何变化，而不是“可控输入—关键状态—可观察输出”的显式路径证明。
2. **终局是「更高质量断言 + 更早报错」**，不是「模型没见过的真实历史 Bug」。
3. **依赖 golden RTL**：关系提取需要读取实现，不适用于只有规格而无法查看实现的场景。
4. **实现细节待核**：本讲解基于摘要，四步的 LLM 角色划分、实验 benchmark、评价指标数值均需原文确认。

## 12. 一分钟复述版

DeepAssert（arXiv 2025）用四步生成模块级「深断言」：① 关系提取（LLM 从 golden RTL 抽调用关系 + 端口 + 信号传播变化）；② 子模块规格抽取（顶层规格 + 关系 → 每模块功能规格，不用内部 RTL）；③ 验证项抽取（条件 + 期望结果）；④ 深断言生成。优于 AssertLLM / Spec2Assertion，断言更靠近 bug 源头。

**研究定位**：DeepAssert 是模块级目标定位、关系提取与深断言生成的代表工作；精读时应重点核对其信号传播表示是否包含明确的可控性与可观察性论证。
