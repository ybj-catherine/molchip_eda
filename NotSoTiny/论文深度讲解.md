## 1. 一句话定位

**NotSoTiny 是从 Tiny Tapeout 真实提交中自动构建的“活” RTL module-completion benchmark**：从 TT06 到 TTsky25a 共收集 1,572 个项目，过滤后保留 1,034 个、聚合后 1,021 个，先生成 5,309 个模块补全任务，再做时间感知去重到 3,062 个唯一任务，最终用通用 Yosys formal equivalence 流程验证出 1,114 个可直接评测的任务；模型必须从周围真实设计上下文推断缺失模块的功能与接口。SOTA LLM 的语法通过率虽超过 85%，formal equivalence 下的功能正确率仍只有约 20%，Min-K 分析显示基准比 RTLLM 等静态 RTL benchmark 更不容易被训练数据污染。

这句话里的五个承重点：

1. **不是 standalone 单模块题** — 每个任务隐藏一个真实设计中的模块，其余模块、顶层连接和上下文保留在 prompt 中；模型没有显式 I/O spec，必须理解系统集成关系。
2. **规模比旧 benchmark 高一个量级** — NotSoTiny-25-12 含 1,114 个去重任务，平均每任务 118.07 LOC，复杂度分 21.90；论文称比 RTLLM、VerilogEval、CVDP、VeriGen 等既有集更复杂。
3. **验证协议刻意做严** — 作者先用代码覆盖率/断言分析展示 Tiny Tapeout 原生 testbench 的局限（中位覆盖率约 67%、中位断言仅 1 个），再采用 Yosys `equiv_simple` + `equiv_induct` 的 formal equivalence 作为主判据。
4. **“Living benchmark”以发布时间排去重** — 去重时保留最早 shuttle 的版本，后续重复提交被移除；每轮 Tiny Tapeout shuttle 发布后可重新生成任务，避免模型记忆旧题。
5. **功能正确仍是瓶颈** — STX 高但 EQV 低说明语法和窄 testbench 会严重高估模型能力；NotSoTiny 将评测信号转向可证明等价。

## 2. EDA 阶段映射（①-⑰）

参照 [芯片流程.md](../芯片流程.md) 的 17 阶段标准编号：

| 阶段 | 覆盖 | 说明 |
|------|:---:|------|
| ① RTL 设计 | ✅ **核心** | benchmark 要求 LLM 在真实 RTL 项目上下文中补全缺失模块。 |
| ② RTL 功能仿真 | ✅ **辅助评测** | 论文先分析 testbench pass，但证明其会把功能错误误判为通过。 |
| ③ 逻辑综合 / HLS | ❌ | 不优化或比较综合结果；Yosys 仅用于形式化等价检查。 |
| ④ 门级仿真 | ❌ | 不跑 SDF 门级仿真。 |
| ⑤ STA | ❌ | 不评估时序。 |
| ⑥ 形式验证 | ✅ **核心评测** | 用 miter + SAT combinational equivalence 和 bounded induction 判定生成模块与 golden 模块功能等价。 |
| ⑦ 布局规划 | ❌ | 不涉及物理设计。 |
| ⑧ 标准单元摆放 | ❌ | 不涉及 placement。 |
| ⑨ 时钟树综合 | ❌ | 不涉及 CTS。 |
| ⑩ 布线 | ❌ | 不涉及 routing。 |
| ⑪ 后仿真 | ❌ | 不涉及。 |
| ⑫ 物理验证 | ❌ | 不涉及 DRC/LVS。 |
| ⑬ 签核 | ❌ | 不产生 signoff。 |
| ⑭-⑰ 流片到芯片到手 | ❌ | 输入来自已 tape-out 的 Tiny Tapeout 社区项目，但论文不制造新芯片。 |

**覆盖率：3/17（① 核心生成任务，⑥ 核心正式验证，② 作为测试协议对照）。** NotSoTiny 是一个评测基准，而不是综合或物理实现工具；它落在数字流程的“写 RTL + 验证 RTL 是否正确”一段。

> ⚠️ “正式等价通过”不等于“任何时钟周期、任何 reset 风格下都等价”：论文的 sequential proof 是 bounded induction（$k=30$），并假设两个设计从可比较 reset 状态出发。

## 3. 输入 / 输出

### 3.1 输入

NotSoTiny prompt 由“完整设计上下文 + 缺失模块 stub”组成。示意结构如下（不是原始题目逐字内容）：

```verilog
// 上下文：周围模块与顶层连线保持完整
module pwm_top(input clk, input rst_n, input [7:0] duty,
               output reg pwm_out);
    wire pwm_ready;
    reg [7:0] counter;

    pwm_counter u_ctr(
        .clk(clk), .rst_n(rst_n),
        .period(duty), .count(counter)
    );

    // TODO: 模型需要补全 pwm_output_gen
    pwm_output_gen u_out(
        .clk(clk), .rst_n(rst_n),
        .counter(counter), .pwm(pwm_out)
    );
endmodule

module pwm_counter(
    input clk, input rst_n,
    input [7:0] period, output reg [7:0] count
);
    always @(posedge clk or negedge rst_n)
        if (!rst_n) count <= 0;
        else if (count == period) count <= 0;
        else count <= count + 1;
endmodule

// 模型输出应补全：
module pwm_output_gen(...);
```

### 3.2 中间产物

构建阶段有三类关键中间产物：

1. 每个项目的统一单文件 Verilog，由 `vppreproc` 展开 include 和 macro；
2. 基于模块切分的 task 对 `(context, missing module, golden module)`；
3. MinHash shingle（word $k=5$）与 LSH 近重复候选，用于跨 shuttle 时间去重。

### 3.3 输出

评测输出是按 shuttle 和全集的四类分数：

```text
{
  "model": "Qwen3-Coder-A35B",
  "dataset": "NotSoTiny-25-12",
  "stx": 86.8,
  "eqv": 23.4,
  "cov_mu": 66.8,
  "per_shuttle": {
    "TT06":  {"stx": 86.3, "eqv": 18.0, "cov_mu": 68.4},
    "TT07":  {"stx": 85.2, "eqv": 28.4, "cov_mu": 67.7}
  }
}
```

`EQV` 是 formal equivalence 完整通过率，`Cov_mu` 是 partition coverage 平均分，可区分“完全错误”和“实现了部分逻辑 partition”。

## 4. 方法与架构

### 4.1 整体 Pipeline

```text
  Tiny Tapeout shuttles
  TT06/TT07/TT08/TT09/TT10-IHP02/TT10-IHP25a/TTsky25a
        │
        ▼
  1. Filtering           ├─ 需要 src/、test/、Makefile、info.yaml
                         └─ 1,572 projects -> 1,034 valid projects
        │
        ▼
  2. Module Aggregation  ├─ vppreproc 展开 include/macro
                         └─ 1,021 self-contained Verilog projects
        │
        ▼
  3. Task Building       ├─ 对每个 module 生成一个 completion task
                         └─ 5,309 tasks before dedup
        │
        ▼
  4. Temporal Dedup      ├─ MinHash + LSH, Jaccard threshold 0.70
                         └─ keep oldest shuttle version -> 3,062 unique tasks
        │
        ▼
  5. Self-Verification   ├─ Yosys formal equivalence on golden solution
                         └─ 1,114 validated tasks
```

### 4.2 核心模块逐个详解

#### 模块 1：Filtering and Module Aggregation

原始 Tiny Tapeout 项目良莠不齐。论文要求项目具备可构建的 `src/`、测试目录、Makefile 和能列出依赖的 `info.yaml`，过滤掉不完整或无法定位源文件的提交。之后用 Verilog-Perl 的 `vppreproc` 展开跨文件 include/macro，合并成单文件 RTL。

#### 模块 2：Task Building

一个含 $n$ 个模块的工程生成 $n$ 个任务：每个任务删除一个模块的 body，其他模块作为上下文。这种做法的关键是上下文里没有“功能说明”，模型只能从使用方、测试结构和顶层连线推断模块应该做什么。

#### 模块 3：Temporal Deduplication

同一设计常被重新提交或小改后提交到多个 shuttle。论文先用 word 5-gram MinHash 做 compact representation，再用 LSH 找 Jaccard 阈值 0.70 以上的候选，最后只保留最早 shuttle 版本。该策略让 benchmark 可以增量加入新 shuttle 而不让旧题重复污染未来训练。

#### 模块 4：Verification

最终任务必须先用“golden 对 golden”通过通用 Yosys 流程，避免 benchmark 内混入依赖手工 testbench 特判的任务。正式评测则把 LLM 输出与 golden module 建 miter：先 `equiv_simple` 处理组合等价，再 `equiv_induct` 做 $k=30$ 的 bounded induction 处理时序状态机。

### 4.3 模块职责矩阵

| 模块 | 输入 | 输出 | 用到的模型/工具 | 是否需训练 |
|---|---|---|---|---|
| Filtering | Tiny Tapeout 项目仓库 | 1,034 个合格项目 | GitHub crawler、结构检查 | 否 |
| Module Aggregation | 多文件 RTL | 单文件 RTL | vppreproc | 否 |
| Task Building | 单文件 RTL | context-module completion task | Verilog parser | 否 |
| Temporal Dedup | 全部 task | 3,062 个去重任务 | MinHash、Datasketch LSH | 否 |
| Self-Verification | 去重任务 | 1,114 个可评测任务 | Yosys | 否 |
| LLM Evaluation | prompt | STX/EQV/Cov_mu | 被测 LLM、Yosys formal flow | 被测模型有训练 |

## 5. 关键公式

### 5.1 Partition Coverage

论文为允许“部分正确”给出的公式：

$$
\text{Partition Coverage}
=
\frac{\sum_{n\in\text{equivalent partitions}} \text{partitions}(n)}
{\sum_{m\in\text{all partitions}} \text{partitions}(m)}
\times 100\%
$$

- `equivalent partitions`：与 golden 对应 partition 等价的 Yosys logic partition 集合。
- `partitions(n)`：partition $n$ 的大小或权重。
- `all partitions`：golden 设计中用于等价比较的全部 partition。
- 当 LLM 只正确实现若干子模块时，该指标仍能给出部分分数。

### 5.2 近重复判定阈值

论文在正文没有给出额外编号公式，但说明使用 MinHash Jaccard 相似度：

$$
\hat{J}(A,B) \geq T, \qquad T=0.70
$$

- $A,B$：两个设计对应的 shingle 集合。
- $\hat{J}(A,B)$：MinHash 估计的 Jaccard 相似度。
- $T$：判定近重复的阈值。

### 5.3 正式等价判据

对 golden 实现 $G$ 与生成实现 $M$ 构造 miter，要求：

$$
\forall x \in \{0,1\}^{|\text{PI}|}, \quad G(x) = M(x)
$$

- $x$：组合输入向量或可达状态下的输入。
- $\text{PI}$：顶层模块输入集合。
- 组合部分用 SAT UNSAT 证明；时序部分用 bounded $k$-induction，$k=30$。

## 6. 训练与实验设置

### 6.1 是否需要训练

NotSoTiny 本身不需要训练，它是评测集与评测管线。实验评测 11 个公开 LLM，模型参数从 7B 到 1T，包括 domain-specific、coding-focused 与 general-purpose 模型。

### 6.2 实验设置

- 构建输入：Tiny Tapeout shuttle TT06、TT07、TT08、TT09、TT10 IHP-02、TT10 IHP-25a、TTsky25a。
- 规模漏斗：1,572 projects → 1,034 valid → 1,021 merged → 5,309 tasks → 3,062 unique → 1,114 validated tasks。
- 指标：STX（Verilog 编译成功）、FNC-Test（testbench 通过）、FNC-EQV（formal equivalence 通过）、Cov_mu（平均 partition coverage）。
- 正式验证工具：Yosys `equiv_simple`、`equiv_induct`。
- 原生 testbench 质量：中位代码覆盖率约 67%，中位断言数 1；约 26% 的 testbench 含超过 1 个断言且覆盖率达到 80%。

### 6.3 关键实验结果

**Table 1：与既有 RTL benchmark 的规模/复杂度对比**

| Benchmark | Samples | LOCs | Complexity | Living |
|---|---:|---:|---:|:---:|
| VeriGen | 17 | 17.05 | 2.12 | No |
| VerilogEval | 158 | 16.58 | 2.22 | No |
| RTLLM | 53 | 37.73 | 6.01 | No |
| CVDP cid02 | 94 | 71.09 | 6.52 | No |
| RealBench | 67 | 192.03 | 50.90 | No |
| **NotSoTiny** | **1,114** | **118.07** | **21.90** | **Yes** |

**Table 2 汇总：NotSoTiny-25-12 上 11 个 LLM 的总体性能（%）**

| Model | Params | Context | STX | EQV | Cov_mu |
|---|---:|---:|---:|---:|---:|
| Kimi-K2-0905 | 1000 B | 262,144 | 76.6 | 19.0 | 58.0 |
| DeepSeek-R1-0528 | 685 B | 163,840 | 77.7 | 20.7 | 59.2 |
| Qwen3-Coder-A35B | 480 B | 262,144 | **86.8** | **23.4** | **66.8** |
| gpt-oss-120b | 120 B | 131,072 | 77.0 | 20.9 | 57.9 |
| Qwen2.5-72B | 72 B | 32,768 | 62.4 | 14.7 | 43.0 |
| Qwen2.5-Coder-32B | 32 B | 32,768 | 60.2 | 11.8 | 40.7 |

论文结论：

- 规模是功能正确率最强预测因素：480B/685B/1T 级模型 EQV 约 20–23%，中规模约 10–15%，7B–13B 级低于 5%。
- 相同参数类中，更大 context window 通常带来更高 EQV，说明长上下文跨模块依赖是任务难点。
- STX 与 EQV 差距超过 60 个百分点，语法/测试通过会严重高估模型能力。
- 即使 EQV 失败，模型通常仍能复现 golden 中 30–60% 的 logic partition。
- 对三个代表性模型，NotSoTiny 上“语法有效即可通过原生 testbench”的比例为 95–97%，但 formal EQV 只有约 20% 上下。

## 7. 创新点

### 创新点 1：contextual module completion 替代 standalone RTL generation

旧 benchmark 给显式 I/O spec，容易退化成代码记忆/翻译；NotSoTiny 把缺失模块放进真实系统上下文，模型必须从周边使用关系推断接口与行为。

### 创新点 2：可扩展 formal equivalence pipeline

论文用 Yosys miter + SAT + bounded induction 对 1,000+ 题目做自动验证，并以 golden-to-golden 自检过滤不可评测任务。相比只跑 testbench，它降低窄激励造成的高估。

### 创新点 3：living benchmark 的时间感知去重

保留最早 shuttle 版本、移除跨 shuttle 重复，再跟随 Tiny Tapeout 发布周期更新，使数据集天然具备抗 contamination 的持续更新机制。

## 9. 与芯片流程的关系

### 9.1 在全流程中的位置

NotSoTiny 评测的是“工程师把新模块接入现有 RTL 系统”的能力。其输入对应 ① RTL 设计阶段，其输出验证部分对应 ② RTL 功能仿真与 ⑥ 形式验证；它不参与逻辑综合后的物理设计。

### 9.2 从“formal EQV 通过”到“能做成芯片”之间隔着什么

NotSoTiny 只证明模块与 golden 在 reset 序列和 bounded depth 下的等价，不检查可综合性、时钟约束、面积/功耗/时序、物理设计规则或系统级软件契约。一个能通过 NotSoTiny 的模块仍可能不可综合或无法满足时钟周期。

## 10. 讨论与局限

### 10.1 论文自述局限

- 时序等价证明的 induction 深度为 $k=30$，需要更长初始化序列或更深状态机的问题可能漏报。
- 方法假设两个设计从可比较 reset 状态出发；不同 reset 极性/初始化风格可能需要特殊处理。
- formal equivalence 为“功能等价”但不检查 microarchitecture 风格，因此适合 benchmark 判分，不等同于项目验收。

### 10.2 代码/复现层面问题

- 完整数据更新依赖 Tiny Tapeout 社区发布的仓库与依赖管理；当项目删除或迁移时，长线可复现性会受影响。
- 正式验证工具链依赖 Yosys 特定 pass，不同 Yosys 版本可能影响可解性与运行时间。
- Table 2 中模型按论文原始文本记录；模型名中的 `A35B`/参数量均保持原文写法，避免自行换算。

### 10.3 本资料包的批判性分析

NotSoTiny 的最大改进是验证严格性，但仍存在两个评测盲区：第一，题目保留完整上下文时，模型可能通过复制类似模块模式“蒙对”，未必证明真推理；第二，formal equivalence 只能比较一个 golden 行为，无法奖励同样正确但接口/时序风格更工程化或更易综合的实现。Living 策略解决了重复题污染，但没有完全解决“新题训练数据可能在发布前泄露”的供应链风险。

## 12. 一分钟复述版

1. 旧 RTL benchmark 规模小、模块孤立、验证浅、容易 contamination。
2. NotSoTiny 从 Tiny Tapeout 真实项目抓取 RTL 并生成 module completion 任务。
3. 任务隐藏一个模块，保留系统上下文，要求模型自行推断接口和功能。
4. 流水线包括过滤、单文件聚合、任务生成、MinHash/LSH 时间去重。
5. 1,572 个项目最终变成 1,114 个经过 golden 自验证的题目。
6. 平均任务约 118 LOC，复杂度 21.90，比多数旧 benchmark 更复杂。
7. 评测用 Yosys 做组合 SAT 等价和 $k=30$ 时序 induction。
8. SOTA 模型 STX 可超过 85%，formal EQV 只有约 20%。
9. 原生 testbench 中位覆盖率约 67%、中位断言仅 1，因此不可作为主判据。
10. 数据集按 Tiny Tapeout 发布周期更新，设计为“living benchmark”以缓解污染。
