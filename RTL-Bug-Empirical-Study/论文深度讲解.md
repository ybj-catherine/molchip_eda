## 论文 1：RTL Design Flaws Revisited（2025）

> **RTL Design Flaws Revisited: A Data-Driven Study of Systematic Bug Patterns in Verilog Code**
> Meng, Ji, Zhang 等
> Journal of Supercomputing, Vol.81, Issue 14, Article 1321, 2025
> DOI: 10.1007/s11227-025-07811-9

### 1. 一句话定位

**目前最大规模的 RTL Verilog bug 实证研究：开发 AST 自动化分析工具，扫描 300+ 个开源 Verilog 项目、分析 15,000+ commits、提取 1,000+ bug-fix commits，做 statement-level 和 expression-level 的 bug 模式统计分析。**

### 2. 方法

```
Step 1: 项目收集
  从 GitHub 收集 300+ 个活跃的 Verilog 开源项目

Step 2: Commit 过滤
  用关键词过滤 bug-fix commits：
  "fix", "bug", "correct", "repair", "patch", "resolve" 等
  从 15,000+ commits 中筛选出 1,000+ bug-fix commits

Step 3: AST 差分分析
  用自定义的 Verilog AST 工具分析 buggy↔fixed 的语法差异
  自动分类到 statement-level 和 expression-level 模式

Step 4: 统计分析
  统计各类 bug 模式的分布频率、涉及模块类型、修复复杂度等
```

### 3. 核心发现

| 发现 | 细节 |
|------|------|
| 赋值语句是最常见 bug 位置 | 和软件 bug 研究一致 |
| if/case 条件错误第二常见 | 边界条件、优先级错误 |
| 位宽不匹配是硬件特有 | 软件没有位宽概念 |
| 阻塞/非阻塞混淆 | 时序逻辑中误用 `=` 代替 `<=` |
| 状态机错误 | FSM 状态转移遗漏或错误 |



|---|---|---|
| 分类维度 | 语法模式（代码长什么样） | 机制模式（bug 怎么工作） |
| 回答的问题 | 「bug 在代码中是什么样子？」 | 「bug 的工作机制是什么？」 |
| 对下代的启发 | 提供了语法层面的 baseline | 深化到机制层面 |

## 论文 2：Understanding Bug Fix Patterns in Verilog（2024）

### 1. 一句话定位

**手动分析 4 个硬件项目的 bug fix 历史，定义 25 种 bug 修复模式（fix patterns），发现 29-55% 涉及赋值语句、18-25% 涉及 if 语句。**

### 2. 25 种 Bug 修复模式（部分）

| 修复模式 | 频率 | 含义 |
|----------|:----:|------|
| 赋值语句修改 | 29-55% | 修改 `assign` / `always` 中的赋值逻辑 |
| if 条件修改 | 18-25% | 修正 if/case 的判断条件 |
| 信号连接修正 | ~10% | 修正模块间信号连接 |
| 状态机转移修正 | ~8% | 修正 FSM 的状态转移逻辑 |
| 位宽修正 | ~7% | 修正信号位宽声明或运算位宽 |
| 时序修正 | ~5% | 修正 `posedge`/`negedge` 或时钟域 |
| ... | ... | ... |

### 3. 「修复模式」≠「Bug 机制」——这是关键区别

同一个「修复模式」（比如改一行赋值语句的右边表达式）可以修复完全不同机制的 bug：

**例子 1**：`assign y = a + b` → `assign y = a - b`
- 这可能是「运算符写错」的简单 typo（activation=unconditional, propagation=0周期）
- 也可能修复了一个跨 5 个模块的长传播链 bug（propagation=12周期）

## 两篇论文的公开对照

两篇工作都从真实 Verilog 变更中归纳缺陷现象：一篇侧重 RTL design flaw 分类，另一篇侧重 bug-fix pattern。它们提供的是经验分类与修复模式，不直接给出自动缺陷生成、跨项目检测或完整验证闭环。

公开使用时应分别核对数据来源、提交筛选条件和标注一致性，避免把语法修复模式直接解释为缺陷根因。
