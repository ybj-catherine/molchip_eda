## 1. 一句话定位

VeriRAG 是**首个 LLM 辅助的 DFT-EDA 框架**，使用检索增强生成（RAG）自动修复 RTL 代码中的 DFT（可测性设计）合规问题。它通过 autoencoder 结构相似度检索 + 迭代式编译器/DFT 诊断反馈修复，在 GPT-o1 上实现 **53.76% 修复成功率**，比 zero-shot 基线（6.96%）提升 **7.72 倍**。

---

## 2. EDA 阶段映射（①-⑰）

VeriRAG 位于 EDA 流程中**综合之前**的 DFT 验证与修复环节：

```
① RTL 设计 → [VeriRAG: DFT 合规修复] → ③ 逻辑综合 → ... → ⑯ 封装+ATE测试
                    ↑
              在 RTL 阶段提前发现并修复 DFT 违规
              （scan readiness, clock/reset 可控性等）
```

传统 DFT 在门级综合后插入 scan chain，但 RTL 阶段引入的 DFT 违规（内部生成时钟、不可控复位等）无法在门级可靠修复。VeriRAG 实现了 **Shift-Left DFT**：在 RTL 阶段就修复 DFT 问题，避免反复的综合-ATPG 迭代。

**覆盖率：2/17**（① RTL 设计 + ③ 逻辑综合前验证）

---

## 3. 输入 / 输出

### 输入
- **待修复的 Verilog RTL 代码**（含 DFT 违规，如内部生成时钟、不可控异步复位等）
- **VeriDFT 参考库**（35 个已验证的 RTL 修复对：原始代码 + 人工修复版）

### 输出
- **DFT 合规的 Verilog RTL 代码**（满足三个条件：可综合 + 无 DFT 违规 + LEC 逻辑等价）

### 例子

**输入（含 DFT 违规 — 内部生成时钟）：**
```verilog
module bad_design(clk, rst_n, d, q);
  input clk, rst_n, d;
  output reg q;
  wire gated_clk = clk & enable;  // CLKNPI: 内部生成/门控时钟
  always @(posedge gated_clk or negedge rst_n)
    if (!rst_n) q <= 0; else q <= d;
endmodule
```

**输出（修复后 — 时钟来自主输入）：**
```verilog
module fixed_design(clk, rst_n, enable, d, q);
  input clk, rst_n, enable, d;
  output reg q;
  always @(posedge clk or negedge rst_n)
    if (!rst_n) q <= 0; else if (enable) q <= d;
endmodule
```

## 4. 方法与架构

### 4.1 整体流程

```
┌──────────────┐    ┌─────────────────┐    ┌──────────────────┐
│ 输入 RTL 代码 │ → │ Autoencoder 编码 │ → │ 余弦相似度检索     │
│ (含 DFT 违规) │    │ (Yosys JSON拓扑) │    │ Top-1 最相似参考  │
└──────────────┘    └─────────────────┘    └──────┬───────────┘
                                                   │
                                          ┌────────▼──────────┐
                                          │ VeriDFT 参考库     │
                                          │ (原始代码+修复对)   │
                                          └────────┬──────────┘
                                                   │
┌──────────────┐    ┌─────────────────┐    ┌──────▼───────────┐
│ 输出修复代码  │ ← │ LEC 逻辑等价检查 │ ← │ LLM 迭代修复      │
│ (DFT 合规)   │    │ (Cadence Conformal)│ │ (RAG prompt +    │
└──────────────┘    └─────────────────┘    │  编译器/DFT 诊断) │
                                           └──────────────────┘
```

### 4.2 三个核心组件

**组件 1：Autoencoder 结构相似度检索**

- 用 Yosys 将 Verilog → JSON（保留拓扑连接关系，去除变量命名等无关信息）
- Autoencoder 用对比学习训练，将 RTL 设计映射到向量空间
- 余弦相似度检索最相近的参考 RTL 设计及其人工修复方案

**组件 2：VeriDFT 数据集**

- 从 108,971 个开源 Verilog 文件清洗得到 437 个含 DFT 违规的设计
- 覆盖 4 种 RTL 级 DFT 错误类型：
  - **ACNCPI**：异步 set/reset 不可从主输入控制
  - **CLKNPI**：内部生成或门控时钟
  - **CDFDAT**：时钟网络用作数据
  - **FFCKNP**：触发器驱动时钟
- 训练集 85 个（20%）、参考集 35 个（8%）、测试集 317 个（72%）

**组件 3：迭代式 LLM 修复管线**

- LLM 接收：(1) 原始 RTL 代码 (2) 检索到的参考修复对 (3) EDA 工具报错/DFT 诊断
- 迭代修复直到满足三个条件：
  1. Xcelium 编译通过（可综合）
  2. DFT 违规消除
  3. Cadence Conformal LEC 通过（逻辑等价）

### 4.3 EDA 工具链

| 工具 | 用途 |
|------|------|
| Yosys | Verilog → JSON 结构表示 |
| Xcelium | 编译检查、synthesizability 验证 |
| Cadence Conformal | 逻辑等价性检查（LEC） |
| HAL | 生成定制约束文件 |

## 5. 关键公式

### 5.1 相似度度量

Autoencoder 将 RTL 设计 $x$ 映射为嵌入向量 $\mathbf{z} = f_\theta(x)$。两个设计的相似度用余弦相似度：

$$
\text{sim}(x_i, x_j) = \frac{\mathbf{z}_i \cdot \mathbf{z}_j}{\|\mathbf{z}_i\| \|\mathbf{z}_j\|}
$$

- $x_i, x_j$：两个 RTL 设计
- $\mathbf{z}_i, \mathbf{z}_j$：autoencoder 输出的嵌入向量
- $f_\theta$：对比学习训练的 autoencoder 编码器

### 5.2 对比学习损失

训练 autoencoder 使用对比损失，使 DFT 结构相似的设计在嵌入空间中靠近：

$$
\mathcal{L}_{\text{contrast}} = -\log \frac{\exp(\text{sim}(x, x^+) / \tau)}{\sum_{k} \exp(\text{sim}(x, x_k) / \tau)}
$$

- $x^+$：正样本（相同 DFT 错误类型）
- $\tau$：温度参数

### 5.3 修复成功判据

一次修复被视为成功当且仅当：

$$
\text{Success}(x_{\text{repaired}}) = 
\begin{cases}
1, & \text{synthesizable} \land \text{DFT-clean} \land \text{LEC-pass} \\
0, & \text{otherwise}
\end{cases}
$$

## 7. 创新点

1. **首个 LLM + DFT EDA 框架**：此前 LLM4EDA 工作聚焦功能验证/生成/综合，无人做 DFT 自动化修复
2. **结构感知 RAG 检索**：不同于文本级 RAG，用 autoencoder 捕捉 DFT 相关拓扑结构相似度
3. **EDA 工具闭环验证**：编译器诊断 + DFT 报错 + LEC 三重检查，保证修复质量
4. **VeriDFT 数据集**：首个 DFT 合规修复专用数据集，填补了硬件可测性研究的数据空白
5. **迭代式修复管线**：单轮 LLM 修复不够，利用 EDA 工具反馈多次迭代直至合规

## 9. 与芯片流程的关系

```
① RTL 设计 ────→ VeriRAG 在此介入 ────→ ③ 逻辑综合
     │                                        │
     │  DFT 违规：                              │ 传统 DFT 插入
     │  · 内部生成时钟、门控时钟                  │ (scan chain, BIST)
     │  · 异步复位不可控                         │
     │  · 时钟网用作数据                          │
     │  · 触发器驱动时钟                          │
     │                                        │
     └── VeriRAG 在综合前修复 ──────────────────→  清洁 RTL 送入综合
```

传统流程中 DFT 在综合后门级处理，RTL 遗留的 DFT 违规会导致反复的综合-ATPG 迭代。VeriRAG 实现了 **Shift-Left DFT** 策略，将 DFT 修复提前到 RTL 阶段。

## 10. 讨论与局限

1. **仅支持 4 种 DFT 违规类型**：当前只覆盖 ACNCPI、CLKNPI、CDFDAT、FFCKNP，其他 DFT 违规类型（多时钟域、测试压缩等）待扩展
2. **仅处理单类型违规**：VeriDFT 过滤掉了含多种 DFT 违规的设计，真实设计中常同时存在多种问题
3. **成功率仍有上限**：即使最强模型 GPT-o1 完整流程也仅 53.76%，近一半的 DFT 违规仍无法自动修复
4. **依赖商业 EDA 工具**：Xcelium 和 Conformal LEC 是 Cadence 商业工具，开源替代方案（Yosys+开源 LEC）的可靠性待验证
5. **参考集规模有限**：仅 35 个参考修复对，覆盖度有限
6. **未考虑物理设计影响**：DFT 修复可能影响时序、面积和功耗，文中未做 PPA 评估

## 12. 一分钟复述版

1. VeriRAG 是首个用 LLM 自动修复 RTL 代码中 DFT（可测性设计）违规的框架
2. 核心思路是 RAG：autoencoder 检索结构相似的历史修复案例 → LLM 参考案例迭代修改代码
3. 修复需满足三个条件：可综合、无 DFT 违规、与原设计逻辑等价（LEC 验证）
4. 配套构建了 VeriDFT 数据集：437 个 Verilog 设计，4 类 DFT 违规，含人工验证修复
5. GPT-o1 + VeriRAG 完整流程达到 53.76% 成功率，比 zero-shot 基线 6.96% 提升 7.72 倍
6. 论文来自香港中文大学，ISQED 2026，代码和数据集完全开源
