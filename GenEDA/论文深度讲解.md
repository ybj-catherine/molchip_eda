## 一、一句话定位

**GenEDA 将 NetTAG 网表编码器与 LLM 解码器做跨模态对齐，从综合后网表生成自然语言功能说明和实现细节，并在算术电路上生成字级 RTL；其最佳 Task 1 GPT-Score 为 0.62，Task 3 在给定 testbench 上的功能通过率为 69%、Pass@5 为 78%。**

这句话有三个承重点：

1. **不是纯文本读网表**：Paradigm 1 把 NetTAG 的图级 embedding 经 MLP 投影后注入可训练 LLM。
2. **兼容冻结的商业 LLM**：Paradigm 2 把逐门功能预测写成网表文本注释，再交给 GPT-4o 或 DeepSeek-V3 推理。
3. **“正确”有严格边界**：Task 3 只覆盖算术电路，69% 指论文给定 testbench 的有限仿真通过率，不是形式等价证明，也不代表可恢复原始 RTL 的唯一写法。

## 二、EDA 阶段映射①-⑰

参照 [芯片流程.md](../芯片流程.md) 的统一编号，GenEDA 接收阶段③产生的综合后网表，尝试生成阶段①的高层描述或算术 RTL，并用阶段②的 testbench 仿真评估生成 RTL。

| 阶段 | 覆盖 | 说明 |
|---|:---:|---|
| **① RTL 设计** | ✅ **核心** | Task 3 从算术门级网表生成采用字级运算符的 RTL；Task 1/2 生成其自然语言功能说明与实现细节。 |
| **② RTL 功能仿真** | ✅ | 论文用 VCS 和预置 testbench 检查生成 RTL 的语法与有限输入下的功能。 |
| **③ 逻辑综合** | ✅ | Task 1/2 数据由 RTL 经 Yosys 增强后用 Design Compiler 与 NanGate 45 nm 库综合；Task 3 也以综合后网表为输入。 |
| ④ 门级仿真 | ❌ | 论文没有对带 SDF 的门级时序网表做仿真。 |
| ⑤ STA（静态时序分析） | ❌ | 不评估时序约束或路径延迟。 |
| ⑥ 形式验证 | ❌ | 没有用 SAT/SMT 或等价检查工具证明生成 RTL 与输入网表等价。 |
| ⑦ 布局规划（Floorplan） | ❌ | 不处理 floorplan。 |
| ⑧ 标准单元摆放（Placement） | ❌ | 不生成或优化 placement。 |
| ⑨ 时钟树综合（CTS） | ❌ | 不处理时钟树。 |
| ⑩ 布线（Routing） | ❌ | 不处理 routing。 |
| ⑪ 后仿真 | ❌ | 不使用布局布线后的 SDF/SPEF。 |
| ⑫ 物理验证 | ❌ | 不涉及 DRC/LVS。 |
| ⑬ 签核（Signoff） | ❌ | 不做时序、功耗或 IR-drop 签核。 |
| ⑭ 流片 | ❌ | 不输出流片数据。 |
| ⑮ 制造 | ❌ | 不涉及制造。 |

| ⑰ 芯片到手 | ❌ | 没有硅后验证。 |

**覆盖率：3/17。** ①是反向生成目标，②是论文采用的验证手段，③提供模型的输入网表和数据构造流程。

### 2.1 逻辑综合的信息损失边界

逻辑综合是数字 IC 设计流中的 **信息损失瓶颈**。从 RTL 变成门级网表时，多种高层表达信息会丢失或被改写：

| 损失信息 | 描述 | 影响 |
|---|---|---|
| 变量名/信号名 | `enable_pipe_stage_3` 可能变成 `n137` | 人类可读性下降 |
| 注释/语义标签 | 寄存器用途、状态机含义 | 不能直接从网表文本读取 |
| 抽象层级 | `if-else` 控制流 → 多路选择器 (MUX) 网络 | 原始语法结构通常不再保留 |
| 算术操作 | `a*b` 被位爆破为 AND/OR 阵列 | 字级算术被拆解为位操作 |
| 字长结构 | `reg[7:0]` 边界在网表中无显式标记 | 字级信息消失 |

GenEDA 借助 **NetTAG** 聚合门与连线中的结构、功能信号，再让 LLM 生成一种可能的高层解释。该过程是有损表示上的推断，不保证恢复原始源码，也不保证生成结果与原网表形式等价。

## 三、输入输出

### 3.1 输入

三个任务都从综合后 Verilog 网表出发，但问题提示与目标不同：

| 任务 | 问题提示 | 目标 |
|---|---|---|
| Task 1 | 询问接口、目的、功能和约束 | 自然语言功能说明 |
| Task 2 | 询问组合逻辑、时序行为和控制流 | 自然语言实现细节 |
| Task 3 | 先推断字级算术功能，再写 RTL | 使用字级运算符的算术 RTL |

下面用一个可直接交给 Verilog 编译器的全加器网表说明 Task 3 的首尾数据形态；这是教学用最小例子，论文 benchmark 的电路更大。

```verilog
module full_adder_netlist(
    input  wire a, b, cin,
    output wire sum, cout
);
    wire x1, c1, c2;
    xor (x1,  a,  b);
    xor (sum, x1, cin);
    and (c1,  a,  b);
    and (c2,  x1, cin);
    or  (cout, c1, c2);
endmodule
```

对应提示的核心要求是：先概括网表实现的字级算术，再生成保持模块接口一致的 RTL，并避免逐位照抄门级表达式。

### 3.2 中间产物

Paradigm 1 产生图级表示 $N_g$，再由 connector 投影为与 LLM 词嵌入同维的 $H_g$。Paradigm 2 则产生逐门功能标签 $T_{\mathrm{pred}}$，并把标签作为文本注释写回网表。例如：

```verilog
xor (x1,  a,  b);    // [pred: adder]
xor (sum, x1, cin);  // [pred: adder]
and (c1,  a,  b);    // [pred: adder]
and (c2,  x1, cin);  // [pred: adder]
or  (cout, c1, c2);  // [pred: adder]
```

这些标签是门功能分类器的预测，不是原网表自带的真值标注。

### 3.3 输出与端到端贯通

Task 3 的理想输出不是复述五个门，而是恢复出字级加法关系：

```verilog
module full_adder_netlist(
    input  wire a, b, cin,
    output wire sum, cout
);
    assign {cout, sum} = {1'b0, a} + {1'b0, b} + cin;
endmodule
```

对论文 benchmark，生成代码还要保留预定义的模块名和 I/O 端口，再由 VCS 编译并运行随数据提供的 testbench。通过该 testbench 只构成有限功能验证，不等同于对所有输入和状态进行形式证明。Task 1/2 走同一输入端，但分别输出“接口/目的/功能/约束”和“组合逻辑/时序行为/控制流”的自然语言段落。

### 3.4 模态对比

| 模态 | 任务 1&2 | 任务 3 |
|---|---|---|
| Graph (`G_N`) | ✔ 编码器主输入 | ✔ 编码器主输入 |
| Text (Netlist Verilog `T_N`) | ✔ 信号名输入 | ✔ 含门注释输入 |
| Text (Instruction `T_in`) | ✔ Prompt | ✔ Chain-of-Thought Prompt |
| Embedding (`H_g`) | ✔ 通过 connector 注入 LLM | ✘ |
| Gate Prediction (`T_pred`) | ✘ | ✔ 作为 LLM 文本输入 |

这张表说明，两种范式共享网表图与文本提示，但进入 LLM 的电路信息载体不同：Paradigm 1 传入连续 embedding，Paradigm 2 传入可读的门功能注释。因此，前者需要训练 connector 与开源 LLM，后者可以保留闭源 LLM 冻结。

## 四、方法与架构

### 4.1 整体框架 (Overview)

GenEDA 框架将网表编码器 **NetTAG**（Fang et al., DAC 2025）$f_{\mathrm{enc}}$ 与 LLM 解码器 $f_{\mathrm{dec}}$ 对齐。论文提出 **两种范式**，分别适配可训练的开源 LLM 与冻结的商业 LLM。

### 4.2 范式 1：基于 Embedding 的对齐 (Embedding-Based Alignment, Paradigm 1)

```text
  ┌─────────────────────────────────────────────┐    ┌──────────────────────────────────┐
  │            Circuit Netlist (N)              │    │      Text Instruction (T_in)     │
  │  ┌───────────────┐    ┌────────────────┐    │    │  • Instruction Prompt            │
  │  │ Graph G_N     │    │ Netlist Verilog│    │    │  • Signal Names                  │
  │  │ (Text-Attr.)  │    │ Text T_N       │    │    └─────────────┬──────────────────┘
  │  └───────┬───────┘    └────────────────┘    │                  │ tokenize
  │          │                                  │                  ▼
  │          ▼                                  │            ┌──────────┐
  │  ┌────────────────────┐                     │            │  H_t     │  Text Embed.
  │  │ Pretrained Netlist │                     │            │ (Word)   │
  │  │ Encoder f_enc      │                     │            └────┬─────┘
  │  │ (NetTAG)           │                     │                 │
  │  └─────────┬──────────┘                     │                 │
  │            │ N_g  (graph-level embed.)      │                 │
  │            ▼                                │                 │
  │  ┌────────────────────┐                     │                 │
  │  │ Modality Connector│                     │                 │
  │  │ MLP  f_c           │                     │                 │
  │  │ (3-layer: 768→2048 │                     │                 │
  │  │           →4096)   │                     │                 │
  │  └──────────┬──────────┘                     │                 │
  │            │ H_g  (text-alike tokens)       │                 │
  │            ▼                                │                 ▼
  │  ┌───────────────────────────────────────────────────────────────┐
  │  │    LLM Decoder f_dec (DeepSeek-Coder 1.3B/6.7B, trainable)    │
  │  │                                                               │
  │  │  f_dec( H_g , H_t )  ⇒  Generative Reasoning                  │
  │  └───────────────────────────────────────────────────────────────┘
  │                                       ▼
  │                            ┌──────────────────────────┐
  │                            │ Task 1: Description      │
  │                            │ Task 2: Implementation   │
  │                            │      Details             │
  │                            └──────────────────────────┘
  └─────────────────────────────────────────────┘
```

### 4.3 范式 2：基于预测的对齐 (Prediction-Based Alignment, Paradigm 2)

```text
  ┌──────────────────────────────────────────────┐
  │           Circuit Netlist (N)                │
  │  ┌────────────────┐  ┌─────────────────────┐ │
  │  │ Graph G_N      │  │ Netlist Verilog T_N │ │
  │  │ (Text-Attr.)   │  │                     │ │
  │  └────────┬───────┘  └─────────────────────┘ │

  │  ┌────────────────────┐                       │
  │  │ Pretrained Netlist │                       │
  │  │ Encoder f_enc      │                       │
  │  │ (NetTAG, frozen)   │                       │
  │  └─────────┬──────────┘                       │
  │            │ N_i  (per-gate embed.)           │
  │            ▼                                  │
  │  ┌────────────────────┐                       │
  │  │ Function Predictor │                       │
  │  │ MLP f_p            │                       │
  │  │ (3-layer, dim 256) │                       │
  │  └─────────┬──────────┘                       │
  │            │ T_pred  (gate function labels)   │
  │            ▼                                  │
  │  ┌─────────────────────────────────────────┐  │
  │  │ Netlist Text + Gate Annotations        │  │
  │  │   e.g. AOI22 adder_U1 ...              │  │
  │  │        NOR3  multiplier_U2 ...         │  │
  │  │        OAI21 comparator_U3 ...         │  │
  │  │        MUX2  controller_U6 ...          │  │
  │  └────────────────┬────────────────────────┘  │
  │                   ▼                           │
  │  ┌─────────────────────────────────────────┐  │
  │  │ Frozen LLM Decoder f_dec                │  │
  │  │ (GPT-4o / DeepSeek-V3)                 │  │
  │  │                                         │  │
  │  │ Chain-of-Thought:                       │  │
  │  │  Step1: Reason word-level arithmetic    │  │
  │  │  Step2: Generate RTL code               │  │
  │  └────────────────┬────────────────────────┘  │
  │                   ▼                           │
  │         ┌─────────────────────────┐           │
  │         │ Task 3: Arithmetic RTL  │           │
  │         └─────────────────────────┘           │
  └──────────────────────────────────────────────┘
```

### 4.4 训练流程 (两阶段)

1. **模态对齐预训练 (Pre-training for Modality Alignment)**
   - 编码器 `f_enc` 与解码器 `f_dec` 均 **冻结**
   - 仅训练 connector MLP `f_c` —— 最大化自回归损失
   - 作用：将电路 embedding `H_g` 对齐到 LLM 词嵌入 `H_t`，相当于 LLM 的"电路 tokenizer"

2. **端到端微调 (Fine-tuning End-to-End)**
   - 编码器 `f_enc` 仍 **冻结**
   - connector `f_c` 与 LLM `f_dec` 同时训练
   - 使用 LoRA + DeepSpeed ZeRO

### 4.5 两种范式的步骤拆解

#### 4.5.1 Paradigm 1

**Step 0 - 双模态输入构造：** 给定一个门级网表 `N`，同时构造两种模态的表示：
- `G_N` (Text-Attributed Graph)：保留门间连接 + 每门的文本化布尔符号表达式
- `T_N` (Netlist Verilog Text)：仅保留信号名 (signal name)，把结构性细节留给 encoder

**Step 1 - 编码：** `f_enc(G_N) → N_g` (graph-level embedding)。该 embedding 蕴含结构与功能双重信息。

**Step 2 - 模态投影：** `f_c(N_g) → H_g`。3 层 MLP 把 768 维电路 embedding 升到 4096 维，使其与 DeepSeek-Coder 的词嵌入空间同维。

**Step 3 - 文本指令编码：** `T_in` (指令 + 信号名) → tokenize → `H_t` (词嵌入)。

**Step 4 - 拼接生成：** `f_dec(H_g ⊕ H_t)` → 自回归生成规格说明/RTL 描述。

#### 4.5.2 Paradigm 2

**Step 0 - 编码器冻结：** NetTAG 编码器 `f_enc` 完全冻结。

**Step 1 - 逐门嵌入：** 对每个门 `i` 提取嵌入 `N_i`。

**Step 2 - 门功能分类：** `f_p(N_i) → y_i ∈ {adder, multiplier, comparator, subtractor, controller}`。

**Step 3 - 文本注释注入：** 把 `y_i` 翻译成 `T_pred` (例如 `Adder`, `Multiplier`)，插入到原网表 Verilog 的对应位置作为注释：

```verilog
AOI22 adder_U1(.A(n0), .B(n1), ...);     // [注释: adder]
NOR3 multiplier_U2(.A(n2), .B(n3), ...);  // [注释: multiplier]
OAI21 comparator_U3(.A(n4), ...);         // [注释: comparator]
MUX2 controller_U6(.S(n10), ...);         // [注释: controller]
```

**Step 4 - CoT 两步推理：** Frozen LLM 接收带注释的网表，按"先推理 word-level 功能、再生成 RTL 代码"的两步 CoT prompt 输出最终 RTL。

### 4.6 关键技术细节

- **指令微调 (Instruction Tuning)：** 论文正文称数据增强后得到 50k 个样本；这一口径与 Table II 的来源计数存在矛盾，详见 §6.1。
- **模态 Connector 的关键作用：** MLP connector 相当于 LLM 的"电路 tokenizer"，把离散电路信号转换为 LLM 可理解的 token-like 序列。
- **两阶段训练策略：** 先对齐(只训练 connector)，再端到端微调(connector + LLM)，避免破坏 LLM 预训练知识。
- **Chain-of-Thought 提示：** Task 3 先推断 word-level 算术功能，再用 word-level 运算符生成 RTL，并明确要求避免 bit-level 展开。

### 4.7 两种范式对比

| 维度 | Paradigm 1 (Embedding) | Paradigm 2 (Prediction) |
|---|---|---|
| LLM 状态 | 可训练 (trainable) | 冻结 (frozen) |
| LLM 典型代表 | DeepSeek-Coder 1.3B/6.7B（文中简称 1B/7B） | GPT-4o / DeepSeek-V3 |
| 信息粒度 | 粗粒度 graph-level embedding | 细粒度 gate-level textual prediction |
| Connector 类型 | MLP (`768→2048→4096`) | 无显式 connector |
| 输入到 LLM | `H_g + H_t` 拼接 | `T_pred + T_N` 文本 |
| 适配任务 | Task 1、Task 2（spec 推理） | Task 3（算术 RTL） |
| 额外技术 | LoRA + 自回归指令微调 | Chain-of-Thought (CoT) |

两条路线不是同一模型的可互换解码选项：它们针对不同任务、不同 LLM 可训练性约束。实验结果也应分别在 Task 1/2 与 Task 3 的口径下解读，不能横向拼成一个统一成功率。

## 五、关键公式

### 5.1 Eq. (1)：Embedding-based 生成路径

$$
\begin{aligned}
f_{\mathrm{dec}}(H_g,H_t)&\Rightarrow \text{Generative Reasoning},\\
H_g&=f_c(N_g),\qquad N_g=f_{\mathrm{enc}}(G_N).
\end{aligned}\tag{1}
$$

- $G_N$：输入网表的文本属性图。
- $f_{\mathrm{enc}}$：预训练 NetTAG 编码器。
- $N_g$：编码器得到的图级网表表示。
- $f_c$：可训练的 MLP 模态连接器。
- $H_g$：投影到语言模态维度后的电路 token。
- $H_t$：问题提示和信号名形成的文本 embedding。
- $f_{\mathrm{dec}}$：可训练的 LLM 解码器。

**工程直觉**：connector 把 768 维电路表示变成 4096 维的“类文本 token”，使其可与文本 embedding 一起输入解码器。Eq. (1) 描述的是信息流，不是损失函数。

### 5.2 Eq. (2)：Paradigm 1 自回归对齐损失

$$
\mathcal{L}_{\mathrm{align}}^{1}
=-\sum_{i=1}^{L}\log p\!\left(y_i\mid y_{<i},G_N\right).
\tag{2}
$$

- $\mathcal{L}_{\mathrm{align}}^{1}$：Paradigm 1 的自回归训练损失。
- $L$：目标规格文本的 token 数。
- $y_i$：第 $i$ 个目标 token。
- $y_{<i}$：生成 $y_i$ 前的所有目标 token。
- $G_N$：由编码器提供电路信息的网表图。
- $p(\cdot)$：解码器给出的条件 token 概率。

**工程直觉**：训练目标仍是 next-token prediction，但预测条件里加入了网表图表示，因此 connector 与 LLM 必须学会利用电路信息。

### 5.3 Eq. (3)：Paradigm 2 逐门功能分类损失

$$
\mathcal{L}_{\mathrm{align}}^{2,\mathrm{pred}}
=-\sum_i y_i\log\!\left(f_p(N_i)\right).
\tag{3}
$$

- $\mathcal{L}_{\mathrm{align}}^{2,\mathrm{pred}}$：逐门功能分类的交叉熵损失。
- $i$：网表中的门索引。
- $N_i$：NetTAG 为第 $i$ 个门生成的 embedding。
- $f_p$：三层、隐藏维度 256 的功能预测 MLP。
- $y_i$：第 $i$ 个门的真实功能类别标签；论文采用 adder、multiplier、comparator、subtractor、controller 五类。

**工程直觉**：冻结 NetTAG，只训练轻量分类头，把难以直接送入商业 LLM 的向量信息转成可读的门功能标签。

### 5.4 Eq. (4)：Prediction-based 生成路径

$$
\begin{aligned}
f_{\mathrm{dec}}(T_{\mathrm{pred}}+T_N)&\Rightarrow \text{Generative Reasoning},\\
T_{\mathrm{pred}}&=f_p\!\left(f_{\mathrm{enc}}(G_N)\right).
\end{aligned}\tag{4}
$$

- $T_N$：原始门级网表的 Verilog 文本。
- $T_{\mathrm{pred}}$：逐门功能预测转成的文本注释。
- $G_N$：同一网表的文本属性图。
- $f_{\mathrm{enc}}$：冻结的 NetTAG 编码器。
- $f_p$：经过 Eq. (3) 训练的门功能分类器。
- $f_{\mathrm{dec}}$：冻结的 GPT-4o 或 DeepSeek-V3。
- $+$：论文图式中的文本组合，而非数值加法。

**工程直觉**：Paradigm 2 不修改闭源 LLM，而是把编码器知识外显成 prompt。Eq. (2) 与 Eq. (3) 才是两条训练目标；Eq. (1) 与 Eq. (4) 是对应的生成数据流。

- GenEDA 在 Table III 报告的各项自动指标上均高于所列通用 LLM baseline。

- Task 3 中 GenEDA (w. DeepSeek-V3) 将功能通过率从 16% 提升至 69% (**4.3 倍**)

### 6.7.1 Task 1 案例研究 (Fig. 6)

论文给出 GenEDA 在 RISC-V CSR 模块上的功能描述生成对比：
- GenEDA 正确识别"处理 CSR (Control and Status Register) 与 PMP (Physical Memory Protection)"等关键概念
- 输出与 Ground Truth 在"功能描述"段落高度对齐，涵盖 CSR 读写、内存保护配置、地址解码、控制信号生成等
- "约束"段落正确识别时钟和复位信号
- 关键优势：GenEDA 能捕捉"csr_reg_pmp_3_addr"等信号名中的领域语义(这是单纯基于文本的 LLM 难以做到的)

### 6.7.2 Task 3 案例研究 (Fig. 8)

GenEDA 处理一个 4-bit 输入 `a, b`，8-bit 输出 `Result` 的算术电路：
- GenEDA 正确识别三个组件：adder、multiplier、comparator
- 输出 word-level RTL：`assign Result_1 = a + b;` `assign Result_2 = a * b;` `assign Result = n1 ? Result_2 : Result_1;`
- 而 GPT-4o 单独仅能产生 bit-level 表达式 (例如 `assign Result_1[5] = a[1] + b[1] + (a[2] & b[2]);`)，无法还原高层 word-level 操作
- 这一对比清楚展示了 GenEDA 在 Paradigm 2 中"门级功能注释"如何引导 LLM 完成高层语义重建

### 6.8.1 消融实验的具体解读

**实验 1：移除对齐 (SFT w/o encoder alignment)**
- 仅对 LLM 做监督微调 (使用相同的 prompt 与标签)，不注入电路 embedding
- Task 1 GPT-Score 从 0.62 跌至 0.32 (约 -48%)
- Task 2 GPT-Score 从 0.51 跌至 0.21 (约 -59%)
- 在这组设置中，对齐信息带来明显增益；该消融不等于证明任何数据与模型下都不可替代

**实验 2：替换为弱编码器 (Less effective encoder)**
- 将 NetTAG (97% 分类精度) 替换为 GNN-RE (83% 分类精度)
- Task 3 Function Pass Rate 从 69% 跌至 40% (约 -42%)
- 结果与“更高质量的门功能预测有助于下游生成”一致；论文没有给出“编码器精度 × LLM 能力”的定量乘法模型

## 七、创新点

1. **跨模态编码器-解码器对齐框架：** 作者将其定位为首个把 GNN 类电路编码器与 LLM 类电路解码器统一用于生成式网表功能推理的框架。这里的“首个”是论文作者的文献定位。

2. **双范式设计 (Two Paradigm Design)：** 同一框架下支持
   - 范式 1：基于 embedding 的对齐 (适配开源可训练 LLM)
   - 范式 2：基于预测的对齐 (适配商业冻结 LLM)
   因而既能训练开源模型，也能在不修改权重的前提下调用冻结模型。

3. **从网表预测走向生成：** 相较以逐门分类或电路属性预测为主的网表编码器，GenEDA 把编码结果用于生成规格说明、实现细节和算术 RTL。论文称其为生成式网表基础模型，但实验范围不等于通用网表理解。

4. **三个生成式网表功能推理任务：**
   - Task 1: Function Description Generation
   - Task 2: Implementation Detail Generation
   - Task 3: Arithmetic RTL Code Reasoning
   前两项面向自然语言规格，第三项限定为算术电路 RTL。

5. **公开 benchmark 与训练脚本：** 后续 GitHub 仓库公开了三个任务的 benchmark、部分训练/推理脚本和模型组件；完整 50k 训练数据与锁定环境没有随仓库发布。

6. **实验支持对齐有效：** Table III、Table IV 与消融实验均显示，加入编码器信息后自动指标与给定 testbench 通过率提高；结论限于论文数据、模型与评测协议。

## 九、芯片流程关系

### 9.1 在全流程中的位置

```text
① RTL 设计 ──③逻辑综合/DC──> 综合后门级网表
     ▲                              │
     │                              ▼
     └── 算术 RTL / 自然语言说明 ─ GenEDA
                │
                └──② VCS + testbench：论文采用的有限功能评估
```

GenEDA 接手阶段③的输出，却沿相反方向生成阶段①常见的高层表示。它缓解的是“综合后高层语义不再显式可见”，而不是把逻辑综合变成数学上的可逆函数：多个 RTL 可以综合到相同或等价的网表，原始命名、注释和写法通常无法唯一恢复。

### 9.2 “仿真通过”和“能进入芯片流程”之间隔着什么

| 仍缺的检查 | 为什么论文结果不能替代它 |
|---|---|
| 形式等价 | testbench 只覆盖有限向量；论文没有证明所有输入与状态都等价。 |
| 综合与门级检查 | 生成 RTL 虽要求可综合，但还需重新综合、检查库映射并做门级仿真。 |
| STA 与 PPA | Table IV 不测时序、面积或功耗，功能通过的 RTL 可能质量很差。 |
| 物理实现与签核 | 没有 placement、routing、DRC/LVS、IR-drop 或硅后结果。 |

论文 Discussion 提到等价检查、硬件木马检测和数据通路优化等潜在用途，但这些都不是本文已经完成评测的下游系统。类似地，扩展到 RTL 结构感知生成与 layout 图像/网表对齐属于未来方向。

## 十、讨论局限

### 10.1 论文给出的范围与未来方向

论文没有单列“Limitations”一节，不能把资料包的判断冒充作者自陈。原文能够直接确认的范围是：Task 3 从算术模块起步；Task 1/2 测试集为 400 个子电路；参考规格由 GPT-4o 生成并经人工审核；实验使用 8 张 A800 80G PCIe GPU。消融还显示，把门分类准确率 97% 的 NetTAG 换成 83% 的 GNN-RE 后，Task 3 功能通过率从 69% 降到 40%。

作者在 Discussion 中明确提出三类后续方向：

1. 把对齐框架扩展到 RTL 结构感知生成，以及 layout 图像与网表图的跨模态任务。
2. 用 Q-Former、cross-attention 等结构替换当前简单 MLP connector。
3. 探索更强的开源 LLM，减少对商业冻结模型的依赖。

工业级 SoC 扩展、形式验证闭环等是合理的研究问题，但不是论文明确完成或验证的工作。

### 10.2 代码与复现层面的问题

以下结论固定到公开仓库 commit `0a19fde3f1c1e56f49a367bf5f1914de84e1c951`：

1. **数据没有完整闭环**：仓库公开了 Task 1/2 JSON、Task 3 数据与评测代码，但未见论文所述完整 50k 训练样本；训练脚本仍引用 `/home/usr/...` 等绝对数据或 checkpoint 路径。
2. **论文与发布 benchmark 规模不同**：论文正文/Table IV 是 9 个 Task 3 设计，Table II 写 8；发布目录与 `auto_run.py` 又列出 12 个输入。
3. **训练配置并非完全一致**：论文称全任务数据 instruction tuning 1 epoch；发布的 detail/code 脚本为 1 epoch，summary 脚本为 3 epochs。
4. **只给出 1.3B 的明确命令**：发布训练脚本显式指向 `deepseek-ai/deepseek-coder-1.3b-instruct`，未见论文 6.7B 配置对应的独立命令或 checkpoint。
5. **环境不可锁定**：仓库未提供 requirements、environment 或 lockfile；脚本能看出使用 Transformers、DeepSpeed 与 LoRA，但不能据此补写未经作者声明的精确版本。

### 10.3 本资料包的批判性分析

1. **功能正确性的证据有限**：Syntax/Function Pass 都来自 VCS 与给定 testbench，没有形式等价证明；“exact RTL”应理解为任务目标，而非实验保证。
2. **自然语言参考与评判共享 LLM 依赖**：Task 1/2 的参考规格由 GPT-4o 生成，GPT-Score 又由 GPT-4o 评判。人工审核能过滤明显错误，但仍可能保留风格偏置。
3. **规模外推尚无证据**：论文数据平均网表规模远小于完整 SoC，也没有报告百万门级上下文、吞吐或分块推理实验，因此不应断言方法已支持或一定不能支持工业规模。
4. **训练分布有限**：Task 1/2 主要来自 ITC99、OpenCores、Chipyard、VexRiscv，Task 3 只覆盖少量算术电路；对非算术控制、工业 IP 和混合信号设计的泛化尚未验证。

### 11.2 可执行范围与工具边界

1. 若只检查已发布 benchmark 和数据格式，不需要重新运行 Design Compiler。
2. 若要重建论文 Task 1/2 数据流水，需要收集源 RTL、执行 Yosys 增强，并使用论文的 Design Compiler/NanGate 45 nm 综合设置。
3. 官方 Task 3 评测脚本调用 VCS；换用开源仿真器需要改脚本，结果也不能自动视为论文同口径。
4. GPT-Score 与两个冻结 LLM baseline 依赖外部模型/API，其版本变化会影响精确复现。

## 十二、一分钟复述

1. GenEDA 的问题意识是：网表编码器擅长提取图结构，LLM 擅长生成文本与代码，但二者通常没有接口。
2. Paradigm 1 用 MLP 把 NetTAG 图级 embedding 注入可训练的 DeepSeek-Coder；Paradigm 2 把逐门功能预测写成文本注释，供冻结的 GPT-4o/DeepSeek-V3 使用。
3. 三个任务分别生成网表功能说明、实现细节与算术 RTL；第三项不覆盖一般 RTL 恢复。
4. Task 1 的 GPT-Score 最佳为 0.62；Task 2 为 0.51。
5. Task 3 中，GenEDA + DeepSeek-V3 的 Function Success Rate 从 baseline 16% 提升到 69%，Function Pass@5 为 78%。
6. 这些功能数字来自 VCS 与给定 testbench，不是形式等价结果。
7. 论文内部有三个需保留的冲突：Task 1/2 的 50k/100k 数据口径、Task 3 的 8/9 设计数、Table IV 表格的 96%/69% 与正文的 97%/60%。
8. 发布仓库提供 benchmark 与部分脚本，但缺完整训练数据、依赖锁定和可移植路径，因此当前复现等级为 R1。
9. 论文提出向 RTL/layout 跨模态任务扩展，这属于 Discussion 中的未来方向。
10. 最准确的表述是“从门级网表做生成式功能推理”，而不是“精确逆转综合”。
