## 1. 一句话定位

**STG 是一个完全不用 LLM 写 testbench、靠「Icarus Verilog 模块 DAG + FSM 模式检测 + 信号角色分类 + 确定性模板渲染」生成 testbench 的结构化框架**：相比纯 LLM 迭代生成（92.4 s），STG 仅需 0.13 s 即可生成 VerilogEval 上的 testbench，行覆盖从 93.97% 提升到 95.88%、翻转覆盖从 85.40% 提升到 95.77%，并把 LLM-generated testbench 在 3,046 个 DUT 上的假阳性率从 7.8% 压低到 0.9%；同时作为「数据策展引擎」用 115k 候选 → 43k 高质量训练样本蒸馏出 SiliconMind 系列模型，在 VerilogEval/RTLLM/CVDP 三基准平均 pass@10 上以单阶段 SFT 取得 56~77 的 Z-分（Z-score），并在 test-time scaling 后端把搜索节点数压缩 14~47%。

这句话里的五个承重点，后面逐一拆解：

1. **「完全不用 LLM 写 testbench」的极端立场** — 与 [HAVEN](../HAVEN/论文深度讲解.md)「LLM 写 spec→JSON、规则写 HDL」相比，STG 更激进：LLM 完全不参与 testbench 生成，只参与两个轻量任务（FSM 检测的辅助 + 数据策展的 oracle）。testbench 全部由确定性分析 + 模板渲染生成。
2. **三类 DUT 分类 + 策略选择** — 组合逻辑（枚举所有 $2^{b_c}$ 控制向量 × $N_s$ 数据样本）、通用时序（两遍 pass + 多相位比较点，区分 Moore/Mealy）、FSM 主导（DFS 状态转换图 + AST 约束求解）。这一分类是 STG 设计的核心骨架。
3. **VerilogEval race condition 修复** — 论文发现 VerilogEval 原始 testbench 中 stimulus 与 checker 在同一时钟沿触发、无序保证，**插入 `#1` 延迟**修复。这是论文对社区的实际贡献。
5. **数据策展三步流程** — 难度过滤（小模型能解的剔除）→ Teacher 生成 + STG 验证（592k PyraNet → 115k 候选 → 43k 留 92% SFT 效果提升）；下游 Qwen2.5-Coder-7B/3-4B-Thinking/3-8B 学生模型 pass@10 全面优于 VeriRL 复现、CodeV-R1、SiliconMind-V1。
4. **720× 生成速度优势** — 纯 LLM 迭代 92.4 s vs STG 0.13 s，能耗 70.9 kWh vs 0.56 kWh（127× 更少），硬件成本 $60,000 vs $4,000。这是把 LLM 出局后的工程红利。

## 2. EDA 阶段映射（①-⑰）

STG 是一个 **确定性 testbench 自动生成** 工具，运行在 RTL 功能仿真阶段，输出可执行 SystemVerilog/Verilog testbench。

参照 [芯片流程.md](../芯片流程.md) 的 17 阶段标准编号：

| 阶段 | 覆盖 | 说明 |
|------|:---:|------|
| ① RTL 设计 | ❌ | 不修改 RTL；只读 DUT（Verilog 源码 + golden reference）生成 testbench |
| **② RTL 功能仿真** | ✅ **核心** | STG 的输出是 testbench，搭配 golden reference 在 Verilator 上跑；论文数据收集 11.1 s 总时长（5.6 h / 115k 问题） |
| ③ 逻辑综合 | ❌ | 不调用综合工具 |
| ④ 门级仿真 | ❌ | 无 SDF 反标；Verilator 零延迟模型 |
| ⑤ STA | ❌ | 不做时序分析 |
| ⑥ 形式验证 | ❌ | **关键区分**：STG 是动态仿真——跑 testbench，比对 golden vs DUT 输出。它不是形式验证。但 STG 可与 [AssertionForge](../AssertionForge/论文深度讲解.md) 生成的 SVA 互补 |
| ⑦ 布局规划 | ❌ | — |
| ⑧ 标准单元摆放 | ❌ | — |
| ⑨ CTS | ❌ | — |
| ⑩ 布线 | ❌ | — |
| ⑪ 后仿真 | ❌ | 无 SPEF |
| ⑫ 物理验证 DRC + LVS | ❌ | — |
| ⑬ 签核 Signoff | ❌ | — |
| ⑭-⑰ 流片→制造→封装测试→芯片 | ❌ | — |

**覆盖率：1/17。** STG 是 ② RTL 功能仿真阶段的 testbench 自动生成工具，与 [VerilogReader](../VerilogReader/论文深度讲解.md)、[HAVEN](../HAVEN/论文深度讲解.md) 同档但更激进（完全无 LLM 介入）。

> ⚠️ **最容易误读的边界**：(1) "0.13 s" 是 STG 生成单个 testbench 的速度，不包括仿真运行时间——后者取决于 DUT 复杂度和测试向量数。(2) "720× faster" 是相对「纯 LLM 迭代生成」的速度比，而非相对其他方法。(3) STG 假设「trusted golden reference」——若没有 reference，框架不能直接用（论文 §3.3 提供 silver-reference 扩展，但承认 oracle 可靠性降低）。

## 3. 输入 / 输出

### 3.1 输入

| 输入项 | 数据类型/格式 | 具体说明 |
|--------|--------------|---------|
| **DUT HDL 源码** | Verilog / SystemVerilog | Icarus Verilog 解析；论文用 VerilogEval（156 题）、RTLLM-v2（50 题）、CVDP cid02+cid03（172 题） |
| **Golden reference** | Verilog / SystemVerilog（trusted） | known-reference verification 的对照实现；论文也提供 silver-reference 扩展（LLM 生成 C++/SystemC 行为模型） |
| **DUT 顶层模块** | 自动识别 | Icarus Verilog 构建模块实例化 DAG，根 = top module（多根时取子节点最多者） |
| **DUT 端口列表** | 自动识别 | width + role（LCS 模糊匹配 + 宽度启发式） |
| **设计类型** | 自动分类 | Combinational / General Sequential / FSM-Dominated |
| **仿真器** | Verilator | 论文用 Verilator 跑生成的 testbench + golden reference |
| **运行预算** | 用户配置 | 总向量数 ≤ $2^{b_{\max}}$；FSM DFS 最大步数用户可配 |

**最小可运行输入例子**（VerilogEval `mux_2to1`）：

```verilog
// DUT
module mux_2to1 (
    input  wire sel,
    input  wire [3:0] a, b,
    output wire [3:0] out
);
    assign out = sel ? b : a;
endmodule

// Golden reference
module mux_2to1_ref (
    input  wire sel,
    input  wire [3:0] a, b,
    output wire [3:0] out
);
    assign out = sel ? b : a;
endmodule
```

STG 自动分类：Combinational（无 clock）→ 控制信号（sel，1 bit）枚举 $2^1 = 2$ 个值 × 数据信号（a/b 各 4 bit）随机 $N_s$ 个样本。

### 3.2 中间产物

**(a) 模块实例化 DAG**

```
top: tb_<module>
  ├── <DUT>      (top module)
  ├── <ref>      (golden reference)
  └── helper modules (clock, reset, scoreboard)
```

**(b) 信号分类表**

| 信号 | 名称 | 宽度 | 角色 | 启发式 |
|------|------|:---:|------|--------|
| clk | 1b | Clock | 名称含 "clk"/"clock" |
| rst_n | 1b | Reset | 名称含 "rst"/"reset"/"rst_n" |
| sel | 1b | Control | 宽度 ≤ 8b，名称含 "sel"/"en"/"start" |
| a, b | 4b | Data | 宽度 ≥ 8b，名称含 "a"/"b"/"data" |

**(c) 状态转换图（仅 FSM 模式）**

```
[S0] --{data_in==A}--> [S1]
[S1] --{data_in==B}--> [S2]
[S2] --{valid==1}--> [S3]
...（自动提取自 always_ff + case 语句）
```

**(d) 确定性 testbench 模板（C++ / Verilator）**

由 Jinja2-like 模板引擎渲染：
- 时钟生成器
- 复位序列
- 激励驱动器（按 DUT 类型选择策略）
- 多相位比较点（Mealy：intra-cycle + clock edge；Moore：clock edge only）
- 覆盖率钩子（Verilator coverage API）

### 3.3 输出

**(1) 可执行的 testbench（C++ + Verilator）**

```cpp
// 自动生成：tb_mux_2to1.cpp
#include "Vmux_2to1.h"
#include "Vmux_2to1_ref.h"
#include "verilated.h"
#include <random>

int main(int argc, char** argv) {
    Verilated::commandArgs(argc, argv);
    auto* dut = new Vmux_2to1;
    auto* ref = new Vmux_2to1_ref;
    std::mt19937 rng(42);
    std::uniform_int_distribution<int> data_dist(0, 15);

    // 控制信号枚举 + 数据随机
    for (int sel_v = 0; sel_v < 2; sel_v++) {
        for (int s = 0; s < 16; s++) {
            int a_v = data_dist(rng);
            int b_v = data_dist(rng);
            dut->sel = sel_v; dut->a = a_v; dut->b = b_v;
            ref->sel = sel_v; ref->a = a_v; ref->b = b_v;
            dut->eval(); ref->eval();
            // 比较
            if (dut->out != ref->out) {
                printf("MISMATCH at sel=%d a=%d b=%d: dut=%d ref=%d\n",
                       sel_v, a_v, b_v, dut->out, ref->out);
                return 1;
            }
        }
    }
    delete dut; delete ref;
    return 0;
}
```

**(2) 覆盖率报告**

论文 VerilogEval 上：
- STG: 95.88% 行覆盖 / 95.77% 翻转覆盖
- Pure-LLM: 93.97% / 85.40%

**(3) Pass/Fail + 不匹配位置**

每次仿真失败打印 DUT 端口当时的值，便于人工根因分析。

**(4) 蒸馏训练数据集（用于 LLM 微调）**

692k PyraNet 样本 → 115k 候选 → 43k 高质量样本（SFT 用）。论文开放 SiliconMind 系列 distilled 模型。

### 4.2 核心模块逐个详解

**(1) 模块解析（Icarus Verilog）**

用 Icarus Verilog 构建模块实例化 DAG；识别 top module：
- 单根 → 唯一根
- 多根 → 取子节点最多的根（典型情况是 testbench wrapper）

**(2) 设计类型分类（Table 1）**

| 分类 | 判定标准 | 策略 |
|------|---------|------|
| Combinational | 端口列表无 clock | 控制枚举 + 数据随机 |
| General Sequential | 有 clock，无 FSM | 两遍 pass + 多相位比较 |
| FSM-Dominated | 有 clock 且 FSM 检测 | DFS 状态转换图 + AST 约束 |

**(3) FSM 检测（双路径）**

| 路径 | 方法 | 适用场景 |
|------|------|---------|
| **确定性模式匹配** | `always_ff` + `case`/`casez` + 索引变量为状态寄存器 | 标准 FSM 编码 |
| **LLM 辅助** | 结构化 prompt 请求 JSON：状态变量、编码、转换、条件 | 自定义/非标准 FSM |

**(4) 信号分类（Table 2）**

基于 LCS（最长公共子序列）模糊名称匹配 + 宽度启发式：
- Clock: 名称含 `clk`/`clock`，宽 1b
- Reset: 名称含 `rst`/`reset`/`rst_n`，宽 1b
- Control: 名称含 `en`/`sel`/`start`/`load`/`valid`/`op`...，宽 ≤ 8b
- Data: 名称含 `d`/`data`/`din`/`addr`...，宽 ≥ 8b

平局时默认 Control。

**(5) Combinational Testbench 生成（§3.2.1）**

控制信号枚举所有 $2^{b_c}$ 个组合；数据信号每组合随机 $N_s$ 个样本；总向量数 ≤ $2^{b_{\max}}$（用户配置上限）。

**(6) General Sequential Testbench 生成（§3.2.2）**

两遍 pass：
- Pass 1：无复位，累积状态
- Pass 2：概率性复位

**多相位比较点**：
- Moore：仅在时钟沿比较
- Mealy：在 intra-cycle 变化后 + 时钟沿都比较——避免漏掉 Mealy-style 输出

激励顺序：随机数据 → 控制赋值 → 随机数据。

**(7) FSM-Guided Testbench 生成（§3.2.3）**

两阶段：
- **Generation**：提取状态转换图；将边守卫拆分为 input conditions（可驱动端口）+ wait conditions（内部运行时状态）；C++ testbench + Verilator 编译。
- **Simulation**：DFS 遍历；解析 input conditions 为 AST；确定性约束提取；驱动赋值；前进时钟直到 wait condition 满足或超时；不可行转换时 reset/backtrack。扩展 Verilator coverage API 收集每行执行计数。

**(8) Silver-Reference 扩展（§3.3）**

Golden HDL 替换为 LLM 生成的 C++/SystemC 软件 reference；STG 生成 skeleton interface，LLM 填充行为逻辑。**承认 oracle 可靠性降低**。

## 5. 关键公式

STG 论文未给独立编号公式。以下对核心机制做形式化表达。

### 5.1 组合逻辑测试向量数

$$
N_{\text{vectors}}^{\text{comb}} = \min\left(2^{b_c} \times N_s, \; 2^{b_{\max}}\right)
$$

- $b_c$：控制信号位宽之和
- $N_s$：每个控制向量的数据样本数（用户配置）
- $b_{\max}$：最大允许位宽（防止爆炸）

**工程直觉**：组合逻辑 DUT 只需枚举所有控制组合 + 数据随机即可达到高覆盖。论文 VerilogEval 上 $N_{\text{vectors}}^{\text{comb}}$ 通常远小于纯 LLM 迭代生成的向量数。

### 5.2 FSM-Guided 状态覆盖率

$$
\text{Transition Coverage}_{\text{FSM}} = \frac{\sum_{e \in E} \mathbb{1}[\text{DFS reaches } e]}{|E|}
$$

- $E$：FSM 状态转换图的所有边集合
- $\mathbb{1}[\cdot]$：指示函数

**工程直觉**：DFS 遍历保证所有可达转换被覆盖（假设 oracle 正确）。

### 5.3 速度优势（论文核心数据）

$$
\text{Speedup}_{\text{STG}} = \frac{T_{\text{Pure-LLM}}}{T_{\text{STG}}} = \frac{92.4 \text{ s}}{0.13 \text{ s}} \approx 720\times
$$

- $T_{\text{Pure-LLM}}$：纯 LLM 迭代生成 testbench 的平均时间
- $T_{\text{STG}}$：STG 生成 testbench 的平均时间

### 5.4 能耗与硬件成本（论文 Table 6，115k Problems）

| 指标 | Pure-LLM (GB200) | STG (CPU core) | 比值 |
|------|:---:|:---:|:---:|
| Runtime | 59.1 h | 5.6 h | 10.6× |
| Hardware power | 1,200 W | ≈100 W | 12× |
| **Total energy** | **70.9 kWh** | **0.56 kWh** | **127× less** |
| Hardware cost | $60,000 | $4,000 | 15× |
| Compilation rate | 71.3% | 100% | +28.7 pp |

### 5.5 DUT 分类准确率（论文 Table 4，3,046 DUTs）

| 配置 | 数量 | 比例 |
|------|----:|:---:|
| Both correct | 2,734 | 89.8% |
| LLM ✓, STG ✗ | 27 | 0.9% |
| LLM ✗, STG ✓ | 236 | **7.8%**（其中 193/236 是 LLM testbench 对错误 DUT 误判 PASS） |
| Both wrong | 49 | 1.6% |
| Agreement | — | 91.4% |

**工程直觉**：STG 在错误 DUT 上的 false-positive 显著低于纯 LLM（7.8% vs 0.9% LLM 优 STG 差的情况）。这是论文核心安全论点。

### 5.6 数据策展漏斗

$$
692\text{k PyraNet} \xrightarrow{\text{难度过滤}} 115\text{k 候选} \xrightarrow{\text{Teacher + STG 验证}} 43\text{k 高质量}
$$

- 难度过滤：剔除小模型能直接解决的问题
- Teacher 生成：GPT-OSS-120B 推理 + Verilog 代码
- STG 验证：testbench 编译通过 + DUT 与 reference 输出一致

**最终**：43k 样本用于 SFT。

### 5.7 Test-Time Scaling 节点压缩

$$
\text{Node Reduction} = 1 - \frac{\text{nodes}_{\text{w/ STG}}}{\text{nodes}_{\text{w/o STG}}} \in [0.14, 0.47]
$$

**工程直觉**：用 STG 作为 test-time scaling oracle 后，MCTS/VFlow 搜索所需节点数下降 14-47%，因为 STG 给出 per-output-port pass rate 作为更精细的反馈。

## 7. 创新点

### 创新点 1：完全无 LLM 生成 testbench 的极端立场

**已有方法的问题**：[VerilogReader](../VerilogReader/论文深度讲解.md) 让 LLM 写 JSON 刺激，[AssertionForge](../AssertionForge/论文深度讲解.md) 让 LLM 写 SVA，[HAVEN](../HAVEN/论文深度讲解.md) 让 LLM 写 spec→JSON——所有工作都让 LLM 参与 HDL 生成。

**STG 的突破**：LLM **完全不参与** testbench 生成，只在两个边缘任务（FSM 检测辅助 + 数据策展的 oracle）中轻量介入。testbench 全部由确定性分析 + 模板渲染生成。

**论文明示**：生成速度从 92.4 s 提升到 0.13 s（720×），能耗从 70.9 kWh 压到 0.56 kWh（127×）。这是 LLM 出局的工程红利。

### 创新点 2：DUT 三分类 + 策略匹配

**已有方法的问题**：传统 random testing 一刀切，不区分设计类型；LLM 迭代生成随机性强。

**STG 的突破**：
- Combinational：控制枚举 × 数据随机
- General Sequential：两遍 pass + Moore/Mealy 比较点区分
- FSM-Dominated：DFS over STG + AST 约束求解

每个类型都有针对性的策略，不是「一种生成方法试所有 DUT」。

### 创新点 3：Moore/Mealy 多相位比较点

**已有方法的问题**：传统 testbench 只在时钟沿检查输出，对 Mealy 机器的 intra-cycle 输出变化漏检。

**STG 的突破**：明确区分 Moore（仅 clock edge 比较）和 Mealy（intra-cycle + clock edge 比较）。这一区分看似细节，实则影响覆盖率——Mealy DUT 的 early-output 是覆盖盲区。

### 创新点 4：VerilogEval race condition 修复

**已有方法的问题**：VerilogEval 原始 testbench 中 stimulus 和 checker 在同一时钟沿触发，无序保证。

**STG 的修复**：在 stimulus block 时钟沿后插入 `#1` 延迟。这一看似小的工程修复对社区有实际贡献。

### 创新点 5：STG 作为数据策展 oracle

**已有方法的问题**：训练 LLM-for-HDL 模型需要大量 (prompt, verilog) 样本对，但验证样本对质量需要可靠的 oracle。

**STG 的突破**：作为「trusted oracle」过滤 LLM 生成样本——692k PyraNet → 115k 候选 → 43k 高质量。蒸馏出的 SiliconMind 系列在三基准平均 Z-score 上全部最优。

### 创新点 6：Test-Time Scaling 后端

**已有方法的问题**：MCTS / VFlow 搜索循环需要 oracle 给反馈，传统 oracle（reference matching）反馈粒度粗。

**STG 的突破**：报告 per-output-port pass rate——更细粒度的搜索反馈使 MCTS 收敛更快（节点数 -14~47%）。

## 9. 与芯片流程的关系

### 9.1 在全流程中的位置

```text
芯片流程                              STG 的位置
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
① RTL 设计                           ← 不参与（不修改 RTL）
② RTL 功能仿真                       ← ★ STG 在这里
    │                                   - Icarus Verilog 解析模块 DAG
    │                                   - 自动分类 DUT 类型
    │                                   - 确定性模板生成 testbench
    │                                   - Verilator 仿真 + golden ref 比对
    │                                   - 收集覆盖率 / pass-fail
    │                                   - 0.13 s 生成 / 单 DUT
    │                                   - 720× faster than Pure-LLM
③ 逻辑综合 ~ ⑰ 芯片到手              ← 完全不涉及
```

**解决的痛点**：在 ② RTL 功能仿真阶段，testbench 编写极耗时（数天到数周）。LLM 迭代生成虽自动化但速度慢（92.4 s/DUT）、能耗高。STG 用确定性分析 + 模板渲染，0.13 s/DUT，能耗降低 127×。

**端到端具体例子**（VerilogEval `mux_2to1`）：

- **传统手工**：工程师读 RTL；写 driver（控制 sel、随机 a/b）；写 monitor；写 scoreboard；编译 Verilator；跑仿真；通常 30 分钟到一个小时。
- **Pure-LLM**：LLM 迭代生成 testbench，92.4 s；可能因语法错误重试多次；能耗高。
- **STG**：Icarus Verilog 解析 → top = mux_2to1 → Combinational（无 clock）→ sel 控制 1 bit 枚举 2 值 × a/b 数据 4 bit 随机 16 样本 = 32 vectors → 模板渲染 C++ testbench → Verilator 编译 → 仿真 0.13 s → 100% pass（golden 一致）。

### 9.2 「Testbench 通过」和「DUT 正确」之间隔着什么

STG 的 "0.13 s 生成 + 95.88% 行覆盖" 只保证**testbench 框架正确 + DUT 大部分代码被执行过**。以下维度都不在评估范围内：

1. **覆盖率 ≠ bug 检出**：与 [ChipFuzzer](../ChipFuzzer/论文深度讲解.md)（用 Spike 做 golden model 差分）相比，STG 假设「trusted golden reference」——reference 错了，STG 不会发现。但 STG 比纯 LLM 生成的 testbench 更少假阳性（7.8% vs 0.9% 优势方）。
2. **Silver-Reference 降级**：当没有 trusted golden reference 时，论文 §3.3 让 LLM 生成 C++/SystemC 行为模型——**论文明确承认 oracle 可靠性降低**。这一降级不是无代价的。
3. **无门级时序信息**：Verilator 零延迟模型看不到毛刺、建立/保持违例、X 传播——只能通过 SDF（④）或 SPEF（⑪）发现。
4. **缺乏真实 Bug 检出评估**：与 [ChipFuzzer](../ChipFuzzer/论文深度讲解.md) 的 Encarsia 90-bug benchmark 不同，STG 没有在已知带 bug 的 DUT 上验证「能否找到 bug」。**STG 主要评价指标是覆盖率 / 编译率 / 速度，没有独立 bug 检出率**。
5. **DUT 分类天花板**：3/19 设计（15.8%）在 [HAVEN](../HAVEN/论文深度讲解.md) 触发 DSL 表达天花板；STG 在 FSM 检测失败时退化为 Sequential 模式，可能导致覆盖率下降。
6. **依赖 golden reference 存在**：STG 的核心假设是「存在 trusted golden reference」。这一假设对工业 IP 不一定成立——很多 RTL 是「第一个写出来」的，没有 reference 可比。

## 10. 讨论与局限

### 10.1 论文自述的局限

1. **FSM 检测需要 LLM 辅助**：确定性模式匹配只覆盖标准 FSM（`always_ff` + `case` 索引变量）；自定义 FSM 需 LLM 辅助分析（增加成本/复杂度）。
2. **Both-fail case（1.6%）**：需要超越结构化或随机刺激的穷举状态空间枚举。
3. **Silver-Reference 折衷**：当没有 trusted golden reference 时，LLM 生成 reference 降低 oracle 可靠性。
4. **未来工作**：可靠 FSM 提取（复杂生产 RTL）、连续学习 pipeline、speculative-decoding draft models from STG-curated distilled small LMs。

### 10.2 代码/复现层面的问题

1. **代码部分开源**：模型权重公开（HuggingFace `AS-SiliconMind/siliconmind-v12`），但 STG 框架本身未公开仓库。
2. **依赖特定 CPU**：Verilator + Intel Xeon w9-3475X CPU core；其他平台可能性能差异。
3. **GPT-OSS-120B 闭源 + 行为漂移**：策展阶段用 GPT-OSS-120B 作为 teacher，复现时若模型下架需替换。

### 10.3 本资料包的批判性分析

1. **「完全无 LLM 写 testbench」的天花板**：STG 在 VerilogEval（156 题，标准教学级）上 0.13 s / 100% 编译通过，看似完美。但工业 RTL 的复杂度远高于 VerilogEval——含自定义协议、跨时钟域、复杂 FSM、嵌套状态机时，确定性模板可能不够用。论文未在工业 IP 上验证。
2. **「覆盖率 ≠ 找到 bug」的关键缺失**：与 [ChipFuzzer](../ChipFuzzer/论文深度讲解.md) 的 Encarsia 90-bug 61.1% 检出率对比，STG 没有给出「在带已知 bug 的 DUT 上能否检出」的评估。论文反复强调"fewer false-pass verdicts on incorrect DUTs"——这只是在**已有 DUT 集合上比较 oracle 可靠性**，而非**主动找 bug 的能力**。
3. **数据策展的循环依赖**：STG 用 GPT-OSS-120B 作为策展 teacher，再用策展数据训练 SiliconMind 系列。**如果 teacher 的 reference model 错了怎么办？** 论文承认 silver-reference 折衷，但 trusted golden reference 在工业中并不总是可用。
4. **「720× 更快」是相对纯 LLM 而言**：与 [HAVEN](../HAVEN/论文深度讲解.md) 的"Stage 1 用预定义 sequence 不用 LLM"对比，HAVEN 的 Stage 1 也能在 0 次 LLM 调用下达到 84.6% 行覆盖。两者方向类似——**通过减少 LLM 介入降低延迟**——但 STG 更彻底（完全无 LLM）。
5. **与 [AssertionForge](../AssertionForge/论文深度讲解.md) 的互补潜力**：STG 生成 dynamic testbench + golden 比对；AssertionForge 生成 static SVA + 形式证明。两者天然互补——但论文未明确组合。
6. **Moore/Mealy 区分的实际影响**：论文强调 Mealy DUT 需要 intra-cycle 比较点——但论文实验涉及的多为 Moore 或同步 DUT，Mealy 案例的覆盖提升数据不显著。
7. **论文定位的诚实性**：STG 不声称 "find bugs"，只声称 "generate reliable testbenches"。这种诚实定位是优点——不夸大——但也意味着它**与 bug 检测工作的可比性弱**。要在 [ChipFuzzer](../ChipFuzzer/论文深度讲解.md) 的框架下评估 STG，需要把 STG 作为「激励生成器」插入 Encarsia-style 评测平台。
8. **同 [HAVEN](../HAVEN/论文深度讲解.md) 的对照**：HAVEN 让 LLM 写 spec→JSON（结构化提取），其余 HDL 由 Jinja2 模板生成；STG 让 LLM 完全不参与 testbench。两者都"减少 LLM 写 HDL"，但 STG 进一步限制 LLM 参与。STG 更适合"已知 golden reference 的回归测试"场景；HAVEN 更适合"无 golden、需要 reference-driven testbench"的场景。

## 12. 一分钟复述版

STG（NTU + Academia Sinica + Harvard，arXiv 2026）是 **「LLM 完全不写 testbench」** 立场的 deterministic testbench 生成框架。核心五招：

1. **结构化分析器**：Icarus Verilog 构建模块 DAG，自动识别 top + 分类 Combinational / General Sequential / FSM-Dominated；信号按 Clock/Reset/Control/Data 自动分类（LCS 模糊匹配 + 宽度启发式）。

2. **三类针对性 testbench 策略**：组合（$2^{b_c} \times N_s$ 控制枚举 × 数据随机）/ 时序（两遍 pass + Moore/Mealy 多相位比较）/ FSM（DFS over STG + AST 约束求解 + Verilator coverage API）。每类都有针对性，不是「一种方法试所有」。

3. **720× 速度优势**：Pure-LLM 92.4 s/DUT vs STG 0.13 s/DUT；能耗 70.9 kWh vs 0.56 kWh（127× 更少）；硬件 $60k vs $4k。VerilogEval 行覆盖 95.88% / 翻转 95.77%（vs Pure-LLM 93.97% / 85.40%）。

4. **数据策展三步漏斗**：692k PyraNet → 难度过滤（小模型能解的剔除）→ 115k 候选 → Teacher (GPT-OSS-120B) 生成 + STG 验证 → 43k 高质量样本。Qwen2.5-C-7B / 3-4B-Thinking / 3-8B 学生模型 SFT 后，pass@10 Z-score 分别 56 / 68 / 77（全最优），单阶段 SFT 压过 SFT+RL 的 CodeV-R1 / VeriRL。

5. **Test-Time Scaling 后端**：STG 作为 MCTS oracle，per-output-port pass rate 比传统 reference matching 反馈更精细，节点数压缩 14-47%；VerilogEval race condition 修复（stimulus `#1` 延迟）。

**边界**：只覆盖流程阶段 ②（1/17）；依赖 trusted golden reference；**没有真实 bug 检出率评估**（与 [ChipFuzzer](../ChipFuzzer/论文深度讲解.md) 的 Encarsia 90-bug 61.1% 对比缺失）；DUT 分类对工业级自定义 FSM 鲁棒性未知；both-fail case 1.6% 仍存在；silver-reference 降级论文自己承认 oracle 可靠性下降。同期的 [HAVEN](../HAVEN/论文深度讲解.md)（LLM 写 spec→JSON，其余 Jinja2 渲染 UVM）走了类似的"减少 LLM 写 HDL"路线但仍保留 LLM；STG 更彻底。整体方向：**「确定性 > 生成式」** 的工程哲学。
