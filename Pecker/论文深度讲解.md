## 1. 一句话定位

**Pecker 针对时序 RTL 中“bug 在早期激活、错误在若干周期后才被观察”的错位，构建设计依赖图并估计最小传播周期（EMPC），从首次失败周期反推候选激活周期、裁掉其后的噪声轨迹，再用双分量谱排序；在 41 个 bug 上达到 Top-1/3/5 为 21/33/35、平均首个排名 9.0。**

它不生成修复，也不靠大语言模型。与普通 SBFL 把整条失败轨迹混在一起不同，Pecker 先问“这条语句最早需要多少个寄存器边界才能影响失败输出”，再只保留因果上可能有用的执行片段。论文报告的 EMPC 激活周期与 ground truth 平均匹配率为 88%。

## 3. 输入 / 输出

### 3.1 输入

输入包含 RTL、能产生通过和失败运行的 testbench，以及判断首次错误输出周期的 oracle。例如下面的 pipeline 在第二级错误地复用了旧的 `valid_q`：

```verilog
always_ff @(posedge clk) begin
  if (rst) begin
    data_q <= '0; valid_q <= 1'b0; out_valid <= 1'b0;
  end else begin
    data_q <= in_data;
    valid_q <= in_valid;
    out_data <= data_q;
    out_valid <= valid_q & enable; // 候选根因
  end
end
```

仿真器记录语句执行和输出差异：

```text
cycle       8  9 10 11 12
in_valid    1  0  0  0  0
enable      1  0  1  1  1
expected       1  0  0  0
observed       0  0  0  0
first observed failure = cycle 9
```

### 3.2 中间产物

Pyverilog 解析 HDL AST，框架据此构造硬件程序依赖图。与普通 PDG 相比，寄存器被显式表示为带一周期延迟的节点；组合节点延迟为零。对每条可能影响失败输出的语句，图搜索估计最少跨越多少个寄存器，即 EMPC，并从首次观测失败周期反推出候选激活周期。

### 3.3 输出

输出是过滤后的语句排名及其双分量分数：

```text
rank  statement                  aef  aep  score tuple
1     out_valid<=valid_q&enable   9    1   (9, 1.000)
2     valid_q<=in_valid            8    4   (8, 0.250)
3     data_q<=in_data              3   12   (3, 0.083)
```

先按激活周期内失败执行数 `aef` 降序，再按激活周期前通过执行数的倒数降序；未在失败激活周期执行的语句先被过滤。

## 4. 方法与架构

### 4.1 整体 Pipeline

```text
RTL + testbench + first observed failure cycle
                     |
                     v
          AST -> hardware PDG
                     |
                     v
        register-aware EMPC propagation
                     |
                     v
 candidate activation cycle = observed cycle - EMPC
                     |
                     v
       truncate post-activation noisy trace
                     |
                     v
       (aef, 1/aep) ranking -> Top-K statements
```

### 4.2 因果链重建

核心不是恢复精确动态因果链，而是用静态设计结构给动态轨迹加时间约束。一个组合逻辑节点不会增加周期；跨过寄存器节点增加一周期。若输出在周期 20 首次错误，而某语句到输出的 EMPC 是 3，那么该语句最值得检查的激活时间是周期 17。

这种对齐把“失败输出出现后仍被大量执行的语句”从统计中裁掉。论文进一步区分激活周期内与激活周期前的执行：前者与失败直接对齐，后者若在通过轨迹里也频繁出现，就应降低优先级。

### 4.3 模块职责矩阵

| 模块 | 输入 | 输出 | 工具/机制 | 训练 |
|---|---|---|---|:---:|
| HDL 前端 | Verilog | AST | Pyverilog | 否 |
| 依赖图构建 | AST | hardware PDG | 数据/控制依赖、寄存器节点 | 否 |
| EMPC | PDG、输出节点 | 最小传播周期 | 加权图传播 | 否 |
| 轨迹对齐 | 首次失败周期、EMPC | 激活周期/截断谱 | 时间反推 | 否 |
| 排名器 | 对齐后的通过/失败谱 | 语句排名 | 双分量排序 | 否 |

## 5. 关键公式与判据

### 5.1 最小传播周期更新

$$
\operatorname{EMPC}_{\mathrm{new}}=\operatorname{EMPC}_{\mathrm{node}}+\operatorname{Delay}_{\mathrm{node}}
$$

- $\operatorname{EMPC}_{\mathrm{node}}$：到当前图节点的累计最小周期
- $\operatorname{Delay}_{\mathrm{node}}$：寄存器节点取 1，组合节点取 0

它近似的是最短时序边界数。实际 bug 可能因条件未满足而传播更久，所以 EMPC 不是精确动态延迟。

### 5.2 候选激活周期

$$
C_{\mathrm{act}}(S)=C_{\mathrm{obs}}-\operatorname{EMPC}(S)
$$

- $S$：候选语句
- $C_{\mathrm{obs}}$：输出首次观测到错误的周期
- $C_{\mathrm{act}}(S)$：候选语句应被检查的激活周期

该式把所有语句按其到错误输出的结构距离投影到不同时间点，避免用同一失败周期统计全部语句。

### 5.3 双分量可疑度

$$
\operatorname{Suspiciousness}(S)=\left(aef(S),\frac{1}{aep(S)}\right)
$$

- $aef(S)$：语句在其激活周期中、失败执行下出现的次数
- $aep(S)$：语句在激活周期之前、通过执行下出现的次数

候选先按 $aef$ 降序，再按 $1/aep$ 降序。原文还先移除 $aef=0$ 的语句。实现时必须定义 $aep=0$ 的平滑或无穷大排序规则；论文正文的数学写法没有展开这一工程细节。

## 6. 训练与实验设置

### 6.1 是否需要训练

Pecker 不训练模型。论文实现使用 Python 3.8、Pyverilog 与 Synopsys VCS-2016，在 Ubuntu 20.04 和 Intel Xeon Platinum 服务器上运行。商业 VCS 是当前复现门槛之一。

### 6.2 Benchmark 与 baseline

实验包含 12 个设计和 41 个 bug，按组合 easy、时序 medium、时序 hard 分组。对比 Tarsel、基于学习的 Detraque 和见证测试增强的 Wit-HW。Top-K 统计根因是否落在前 K 名；论文表中总体验证使用 Top-1/3/5。MFR/MAR 表示真实 bug 第一次出现的平均名次，越低越好。

### 6.3 关键结果

| 方法 | Top-1 | Top-3 | Top-5 | 平均首个排名 |
|---|---:|---:|---:|---:|
| Tarsel | 11 (27%) | 17 (41%) | 24 (59%) | 12.2 |
| Detraque | 13 (32%) | 24 (59%) | 27 (66%) | 12.9 |
| Wit-HW | 16 (39%) | 18 (44%) | 20 (49%) | 14.8 |
| **Pecker** | **21 (51%)** | **33 (80%)** | **35 (85%)** | **9.0** |

| 变体 | Top-1 | Top-3 | Top-5 |
|---|---:|---:|---:|
| **Pecker** | **21 (51%)** | **33 (80%)** | **35 (85%)** |
| w/o activation localization | 18 (43%) | 27 (65%) | 28 (68%) |
| w/o noisy-trace pruning | 13 (32%) | 22 (53%) | 28 (68%) |

移除激活定位使 Top-1 下降 8 个百分点，移除噪声裁剪下降 19 个百分点。EMPC 与真实激活周期的总体匹配率为 88%；easy 为 100%，medium 为 83%，hard 为 82%。

## 7. 创新点

### 7.1 把寄存器延迟显式写进依赖图

软件 PDG 常忽略硬件时钟语义。Pecker 把寄存器视为一周期节点，使静态结构能回答某语句最早几周期影响输出。

### 7.2 把观察周期反投影到每个候选语句

传统方法按整条失败轨迹累计覆盖；Pecker 为每条语句计算不同的候选激活周期，因而能处理根因和症状错位。

### 7.3 先去时序噪声，再做谱排序

排序公式本身很轻量，主要收益来自统计口径改变。消融结果也显示 noisy-trace pruning 对 Top-1 的影响最大。

## 9. 与芯片流程的关系

### 9.1 在全流程中的位置

上游必须已经有可执行 testbench、失败 oracle 和可识别的首次失败周期。Pecker 读取 RTL 结构与仿真谱，输出疑似根因语句；下游由工程师或修复器产生补丁并重新验证。它与 Wit-HW 互补：前者改进时间因果对齐，后者增加测试的区分度，但论文没有实现二者的统一系统。

### 9.2 到真实项目落地的距离

真实 SoC 存在跨时钟域、异步复位、协议握手、黑盒 IP 和不完整 trace，简单的 0/1 周期节点可能不够。定位后仍需回归、形式验证、综合和后端签核。Top-K 的候选集合还受 HDL 展开、宏和生成块映射影响，源代码行级可解释性需要额外工程。

## 10. 讨论与局限

### 10.1 论文证据支持的局限

EMPC 是最短传播近似，不保证等于动态传播时间。论文的 trace 实验也承认：完全不裁剪时虽噪声最大，但 Top-5 略好于“裁一半”，说明后段轨迹仍可能含有有用信息。未来工作需选择性保留，而非一刀切删除。

### 10.2 复现层面

公开论文页未给出稳定官方代码链接；实现依赖较旧的 Python 3.8、Pyverilog 和商业 VCS-2016。资料包仅归档 PDF 并核对原文表格，未复现实验，不能把算法伪代码等同于可运行实现。

### 10.3 本资料包的判断

最值得延伸的是“传播感知的时间窗”，不是简单再叠一个 LLM。严谨的新实验应报告：EMPC 误差分布、不同 trace 截断策略、组合环/多时钟处理、在相同测试预算下的 Top-K，以及候选语句总数变化。否则准确率可能只是过滤器缩小了排名空间。

## 12. 一分钟复述版

Pecker 面向时序 RTL bug 定位。它观察到 bug 的激活周期和输出失败周期常隔着多个寄存器，因此整条 trace 的 SBFL 会混入大量后续噪声。方法从 HDL 构造含寄存器节点的 PDG，用 EMPC 估计每条语句到症状的最少周期数，再由首次失败周期反推该语句的候选激活周期。裁掉不相关 trace 后，以 `(aef, 1/aep)` 排名。41 个 bug 上 Top-1/3/5 为 21/33/35，平均首个排名 9.0，EMPC 对齐平均 88%。它不训练模型，也不生成修复；公开代码和数据入口仍不完整，商业 VCS 是复现障碍。
