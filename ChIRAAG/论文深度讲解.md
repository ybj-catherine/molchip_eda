## 1. 一句话定位

**ChIRAAG 是「只用自然语言规格、不碰 RTL」的 GPT-4 断言生成框架：先把规格结构化成 JSON（信号 + 功能参数 + 设计上下文），让 GPT-4 据此生成 SVA，再把仿真日志（如 VCS）自动喂回 LLM 迭代纠错（时序错误、缺信号），直到错误清空或到迭代上限——在 OpenTitan RV Timer 上，原始断言仅 27%~33% 出错，几轮反馈即修正。**

这句话里的四个承重点：

1. **只吃 NL 规格** — 与从 RTL 或注释生成断言的方法刻意区分，避免从可能有 bug 的实现中照抄断言，是规格独立生成验证工件的早期工程实践。
2. **规格 → JSON** — 把规格拆成标准 JSON（信号、功能参数、设计上下文），结构化后再喂 LLM，而不是直接甩一段自然语言。
3. **仿真日志反馈闭环** — 断言写错（时序错、漏信号）时，把仿真报错喂回 LLM 改，while 循环直到清空或到上限 T；仍错就转人工排查。
4. **「三 C」评价框架** — 断言验证（ABV）的 Consistency（一致性）、Correctness（正确性）、Completeness（完备性）。

## 3. 输入 / 输出

### 3.1 输入

| 输入项 | 说明 |
|---|---|
| **自然语言设计规格** | 唯一输入（**不喂 RTL**） |
| **GPT-4** | 生成 SVA 的 LLM |
| **仿真工具** | VCS（产生反馈日志） |

### 3.2 中间产物

- **规格 JSON**：信号列表 + 功能参数 + 设计上下文；
- **仿真日志**：断言违反/时序错误/缺信号等报错。

### 3.3 输出

- 修正后的 **SVA 断言**（经反馈闭环纠错）。

## 4. 方法与架构

### 4.1 整体 Pipeline（两阶段）

```text
自然语言规格 D
      │
      ▼
① 规格格式化：D → UnFmt（拆解）→ JSON → I（结构化）
      │
      ▼
② 断言生成 + 反馈闭环：
   GPT-4 → SVA → 仿真(VCS) → 有错? ──Yes──▶ 日志喂回 GPT-4 改 → 再仿
                            │                        ▲
                            └──── 循环直到错误清空 / 到上限 T ──┘
                            │
                            ▼ 仍错
                          人工排查（断言错 / 实现有 bug / 无法自动修）
```

### 4.2 关键设计点

**（1）反馈闭环的「错误分类」** — 论文 Algorithm 1 里把常见仿真错误分成**时序错误**和**缺信号**两类，用对应报错信息引导 LLM 改断言（Line 20）；循环到错误清空或达上限 T；仍错就转人工（Line 29–33）；若断言正确但**实现有 bug**，则转去人工查设计实现（Line 23）——这一句很关键：它**承认断言 vs 实现的判责边界**，不会盲目把实现 bug 当断言 bug 去「修」。

**（2）RV Timer 案例** — OpenTitan 的 RV Timer：初始 10 条功能断言，7 条裸跑即过仿真；剩 3 条经反馈闭环自动修正，最终得到 11 条（比如从仿真日志发现缺 `rst_ni` 信号，补上并把一条断言拆成两条）。

## 5. 关键公式

论文无核心编号公式。可提炼的机制：

- 规格格式化：$D \rightarrow \text{UnFmt} \rightarrow I$（规格 → 拆解 → 结构化 JSON）
- 反馈循环：$\text{while}\ (\text{errors exist} \land n < T)\ \text{refine}$（错误未清且未达上限，则继续迭代纠错）

> 无独立公式，本节以定性描述代替。

## 7. 创新点

### 创新点 1：只吃规格、不抄 RTL（oracle 独立原则的早期实践）

与从 RTL/注释生成断言的方法区分，ChIRAAG 只用 NL 规格，避免从可能有 bug 的实现中照抄断言，体现了答案从规格独立推导的原则。

### 创新点 2：仿真日志反馈闭环

把仿真报错自动喂回 LLM 迭代纠错，形成「生成 → 仿真 → 纠错」闭环，并明确「断言错 vs 实现 bug」的判责边界。

### 创新点 3：规格结构化 JSON

把 NL 规格拆成 JSON（信号 + 参数 + 上下文）再喂 LLM，降低幻觉、提高可解析性。

> ⚠️ **研究边界**：ChIRAAG 不做目标选择，但它是规格独立生成断言和工具反馈闭环两个机制的早期代表。

## 10. 讨论与局限

### 10.1 论文自述局限（摘要级）

1. 依赖人工核对最终断言正确性（LLM 断言可能错）；
2. 反馈闭环有迭代上限 T，超过则转人工（部分错误无法自动修）。

### 10.2 本资料包的批判性分析

1. **不选目标**：给定设计，不决定优先验证哪个模块或信号，因此不能替代目标选择方法。
2. **「只吃规格」有利有弊**：避免了抄 RTL，但也失去了结构信息，深模块级断言能力弱（这正是 AssertMiner / DeepAssert / AgileAssert 后来补的方向）。
3. **规模小**：RV Timer 案例规模小，泛化性待验证。
4. **实现细节待核**：本讲解基于摘要，Algorithm 1 具体行号、JSON schema 细节、迭代上限 T 取值需原文确认。
