# VeoPlace 论文深度讲解

> **See it to Place it: Evolving Macro Placements with Vision-Language Models**
> Ikechukwu Uchendu, Swati Goel, Karly Hou, Ebrahim Songhori, Kuang-Huei Lee, Joe Wenjie Jiang, Vijay Janapa Reddi, Vincent Zhuang
> arXiv:2603.28733
> 原文：[2603.28733_See-it-to-Place-it.pdf](./2603.28733_See-it-to-Place-it.pdf) · [2603.28733_See-it-to-Place-it.txt](./2603.28733_See-it-to-Place-it.txt)

## 1. 一句话定位

**VeoPlace 用不微调的 VLM 指导底层 placer，把宏或动作限制到芯片上更有前景的子区域，并通过进化搜索持续优化 VLM proposal；在 9/10 个 benchmark 上优于 ChiPFormer，峰值 HPWL 降低超过 32%。**

这句话里的三个承重点：

1. **视觉空间推理** — VLM 从 placement 图像和 HPWL 历史中提取人类设计师常用的空间模式。
2. **双层控制** — VLM 只给高层区域建议，底层 placer 保持原有的搜索和优化能力。
3. **两种实例化** — action masking 适配学习型 policy，soft anchor constraints 适配解析型 placer。

## 3. 输入 / 输出

### 3.1 输入

- 未见芯片的宏、网表和布局 canvas。
- 当前 placement 图像、历史 placement 和性能指标。
- base placer：ChiPFormer 或 DREAMPlace。
- 在线尝试预算 $B$。

```text
veoplace_input = {
  benchmark: "superblue5",
  base_placer: "DREAMPlace",
  rollouts: 2000,
  vlm: "Gemini",
  mode: "soft_anchor_constraints"
}
```

### 3.2 中间产物

- VLM 输出的子区域 proposal 或 anchor 集合。
- 受约束 placement 的 HPWL。
- 进化种群中的 proposal 配置。

```text
proposal = {
  region_for_macro_group_A: [x_min,y_min,x_max,y_max],
  hpwl: 5.2e7,
  generation: 12
}
```

### 3.3 输出

```text
veoplace_output = {
  hpwl_best: "5.2e7",
  improvement_vs_base: "4.3%",
  benchmarks_improved: "8/8"
}
```

## 4. 方法与架构

### 4.1 整体 Pipeline

```text
Unseen chip + base placer
          │
          ▼
VLM proposes subregions / anchors
          │
          ▼
Low-level placer executes constrained placement
          │
          ▼
Evaluate HPWL
          │
          ▼
Evolutionary population update
          │
          ▼
Return best placement
```

### 4.2 核心模块逐个详解

- **VLM planner**：接收 placement 图像和指标，生成结构化 proposal。
- **Action masking**：对学习型 policy，只允许 VLM 认可的区域动作。
- **Soft anchor constraints**：对 analytical placer，把宏拉向 VLM 建议区域，同时保留 density/wirelength 优化。
- **Evolution**：以最终 HPWL 为 fitness，保留和变异 proposal。

### 4.3 模块职责矩阵

| 模块 | 输入 | 输出 | 工具/模型 | 是否需训练 |
|---|---|---|---|---|
| VLM planner | layout images, HPWL | region proposal | Gemini VLM | 否 |
| Action masking | proposal, state | masked action set | policy wrapper | 否 |
| Analytical guidance | proposal, placer | anchor cost | DREAMPlace wrapper | 否 |
| Evolution | HPWL | next proposals | population update | 否 |

## 5. 关键公式

### 5.1 HPWL

$$
HPWL(P)=\sum_{e\in E}\left(\max_{i\in e}x_i-\min_{i\in e}x_i+\max_{i\in e}y_i-\min_{i\in e}y_i\right)
$$

- $P$：placement
- $E$：net 集合
- $x_i,y_i$：pin 坐标

### 5.2 Anchor cost

$$
L_{\text{anchor}}=\sum_i w_i \cdot d(m_i,R_i)
$$

- $m_i$：宏 i
- $R_i$：VLM 给宏 i 的建议区域
- $d(m_i,R_i)$：宏到区域的距离
- $w_i$：anchor 权重

### 5.3 Action mask

$$
a_t \in \mathcal{A}_{VLM}(s_t)\subseteq \mathcal{A}
$$

- $a_t$：第 t 步动作
- $\mathcal{A}_{VLM}(s_t)$：VLM 允许的动作集
- $\mathcal{A}$：底层 placer 的完整动作空间

## 6. 训练与实验设置

### 6.1 是否需要训练

VLM 不微调。底层 placer 可用预训练模型，但 VeoPlace 不重新训练。

### 6.2 实验设置

- ChiPFormer 在 ISPD2005、ICCAD2004、Ariane 上评测。
- DREAMPlace 在 ICCAD2015 Superblue 上评测。
- 固定 rollouts，报告 mean ± standard error。

### 6.3 关键实验结果

| Base placer | 改善 |
|---|---:|
| ChiPFormer | 9/10 benchmark 更优，峰值 HPWL 降低超过 32% |
| DREAMPlace | 8/8 benchmark 改善，最高 4.3% |

结果表明 VLM 区域指导可以跨 learning-based 和 analytical placer 生效。

## 7. 创新点

1. 首次把无微调 VLM 作为 macro placement 高层空间推理器。
2. 统一支持 action masking 和 soft anchor constraints。
3. 用进化搜索持续优化视觉 proposal，避免单次建议的局部性。

## 9. 与芯片流程的关系

### 9.1 在全流程中的位置

VeoPlace 位于 placement 阶段，是可插拔的 high-level guidance 层。它不改变 placer 的核心算法，而是限制搜索区域，提升有限 rollouts 下的搜索效率。

### 9.2 从“HPWL 改善”到“能做成芯片”之间还缺什么

论文没有系统报告 post-route timing、power、congestion 和 DRC；需要把 VLM 建议接入完整 P&R 流程并验证 signoff 指标。

## 10. 讨论与局限

### 10.1 论文自述的局限

主要关注 placement HPWL，跨 unseen chip 的泛化依赖 VLM 的少样本上下文能力。

### 10.2 代码/复现层面的问题

未公开完整代码，VLM prompt 和图像表示细节不足以精确复现。论文说明使用 Gemini 和进化框架，但 proposal 的文本格式、图像生成与 anchor 权重未完整公开。

### 10.3 本资料包的批判性分析

若 VLM 区域建议过强，会过度限制 placer；若过弱，则收益有限。不同 base placer 的超参需要重新调整。

## 12. 一分钟复述版

VeoPlace 让 VLM 看 placement 图像和历史 HPWL，提出宏应该去的区域；底层 placer 在这个限制下执行布局。对学习型 placer 用 action mask，对解析型 placer 用 anchor cost。进化算法不断筛选 proposal，最终在不微调模型的情况下改善 ChiPFormer 和 DREAMPlace 的 HPWL。
