## 1. 一句话定位

**Dr. RTL 是一个基于 Claude Code 的多 Agent RTL 时序优化框架：它以商业综合、静态时序分析和顺序等价检查为反馈，在每轮并行改写 5 个 RTL 候选，并把搜索轨迹提炼成可复用 skill；在 20 个设计上平均改善 WNS 21.3%、TNS 16.9%，面积降低 5.8%，SEC 通过率为 86%。**

这句话里的四个技术承重点，后面逐一拆解：

1. **优化对象是已有 RTL，而非从自然语言生成 RTL** -- 输入是人写、可综合的设计，目标是在保持功能等价和流水级数不变的条件下继续改善综合后时序与面积。
2. **Claude Code 承担 Agent 编排** -- 公开仓库通过 `CLAUDE.md`、`.claude/agents/` 和 `.claude/skill/rtl-opt/` 组织总控规则、专职 Agent 与优化经验库，没有另行实现通用 Agent 运行时。
3. **商业 EDA 结果决定候选去留** -- Synopsys Design Compiler 提供综合、WNS、TNS 和面积结果，Cadence JasperGold SEC 检查原始 RTL 与候选 RTL 的顺序等价性。
4. **搜索经验被外化为 skill** -- 系统比较同一父设计下的并行候选，将有效、条件有效和应避免的变换整理成 47 个 pattern-strategy 条目，用于后续设计。

论文中的 skill 是项目内的 Markdown 优化知识库，不等同于某个跨 Agent 宿主的通用技能标准。

## 2. EDA 阶段映射（①-⑰）

参照 [芯片流程.md](../芯片流程.md) 的 17 阶段标准编号：

| 阶段 | 覆盖 | 说明 |
|------|:---:|------|
| ① RTL 设计 | ✅ | Agent 读取并改写已有 Verilog/SystemVerilog，执行条件预计算、逻辑重构和信号复制等变换 |
| ② RTL 功能仿真 | ❌ | 论文不以 testbench 仿真或覆盖率闭合为主要正确性判据 |
| ③ 逻辑综合 | ✅ | Synopsys Design Compiler 综合每个候选，并输出门级面积和时序结果 |
| ④ 门级仿真 | ❌ | 未进行 SDF 反标门级仿真 |
| ⑤ STA（静态时序分析） | ✅ | 从综合后时序报告提取 WNS、TNS、关键路径、起止点和扇出信息 |
| ⑥ 形式验证 | ✅ | Cadence JasperGold SEC 检查候选 RTL 与原始 RTL 的顺序等价性 |
| ⑦ 布局规划（Floorplan） | ❌ | 主优化闭环不生成或修改 floorplan |
| ⑧ 标准单元摆放（Placement） | ⚠️ 仅评估 | 论文报告 Innovus post-P&R 结果，但未单独描述 placement 流程或让 Agent 操作 placement |
| ⑨ 时钟树综合（CTS） | ❌ | 未披露 CTS 配置或专项优化 |
| ⑩ 布线（Routing） | ⚠️ 仅评估 | Innovus post-route 结果用于检查 RTL 优化收益能否传递到后端，不属于候选搜索环 |
| ⑪ 后仿真 | ❌ | 未进行 SPEF/SDF 反标后仿真 |
| ⑫ 物理验证（DRC + LVS） | ❌ | 未报告 DRC 或 LVS 结果 |
| ⑬ 签核（Signoff） | ❌ | 未完成多角多模 STA、功耗、IR Drop 等完整签核 |
| ⑭ 流片 | ❌ | 未向晶圆厂交付 GDSII |
| ⑮ 制造 | ❌ | 不涉及制造流程 |
| ⑯ 封装 + 测试 | ❌ | 不涉及封装或 ATE 测试 |
| ⑰ 芯片到手 | ❌ | 不涉及硅后测量 |

**覆盖率：4/17。** Dr. RTL 直接覆盖 ① RTL 设计、③ 逻辑综合、⑤ STA 和 ⑥ 形式验证；⑧ 与 ⑩ 只出现在后端迁移性实验中，不计入覆盖率。

> ⚠️ Dr. RTL 的主任务是综合反馈驱动的 RTL 时序优化，不是完整 RTL-to-GDS 自动设计。Innovus 结果只能说明部分收益传递到了 post-route 阶段，不能等同于完成物理签核或流片。

## 3. 输入 / 输出

### 3.1 输入

一次优化任务至少需要以下输入：

- 一份原始、可综合并被视为功能基准的 RTL 设计；
- 时钟、I/O delay、library 等综合和时序约束；
- 能运行综合、STA 与 SEC 的脚本和工具环境；
- 当前轮基准候选及其 WNS、TNS、面积、关键路径等结构化记录；
- 历史 skill library，包括推荐模式、适用条件、风险和应避免的改写；
- coding-agent 宿主的工程指令，例如仓库中的 `CLAUDE.md` 和专职 Agent 提示文件。

论文处理的不是故意打坏的 toy RTL。20 个设计平均约 812 行 RTL、3 个模块、6230 个门和 760 个寄存器，最小约 128 行，最大约 4615 行。作者把时钟周期设成很激进的 0.1 ns，使综合后普遍存在负 slack，目的是给优化器制造足够明显的时序压力。

### 3.2 中间产物

论文图 7 给出“条件预计算”类 skill。下面是按照其结构重写的示意，而不是仓库源码逐字摘录。

```verilog
// 改写前：多个分支重复执行相同的宽比较，容易形成重复逻辑和较深控制路径
always @(*) begin
  next_state = state;
  if ((src_id == dst_id) && (opcode == OP_A)) begin
    next_state = S_A;
  end else if ((src_id == dst_id) && (opcode == OP_B)) begin
    next_state = S_B;
  end
end
```

候选改写把重复条件显式抽出，让综合器更容易共享逻辑，也让后续 Agent 能定位关键控制信号：

```verilog
wire same_id;
wire is_op_a, is_op_b;

assign same_id = (src_id == dst_id);
assign is_op_a  = (opcode == OP_A);
assign is_op_b  = (opcode == OP_B);

always @(*) begin
  next_state = state;
  if (same_id && is_op_a) begin
    next_state = S_A;
  end else if (same_id && is_op_b) begin
    next_state = S_B;
  end
end
```

这种改写并不保证每次都好。结果取决于综合器是否已经完成公共子表达式消除，以及显式拆分对扇出和工艺映射的影响。因此 Dr. RTL 不把语言模型的解释当结论，而是对每个候选重新综合、重新 STA、重新 SEC。

#### 3.2.1 结构化轨迹记录

公开仓库采用结构化文件保存每轮结果。字段可抽象成下面这种记录：

```json
{
  "iteration": 4,
  "parent": "iter_03_best",
  "candidate": "cand_02",
  "strategy": "replicate_high_fanout_control",
  "wns": -0.041,
  "tns": -3.27,
  "area": 18432.8,
  "sec_pass": true,
  "score": -0.163,
  "critical_paths": ["u_ctrl/state_reg -> u_alu/result_reg"]
}
```

结构化状态有两个用途：一是让总控在上下文窗口之外仍能恢复搜索轨迹；二是让 skill 学习 Agent 对“同一个父设计、同一套工具条件、同一轮生成的多个候选”做可比的归因，而不是把跨设计、跨约束的绝对 PPA 数字硬拼在一起。

### 3.3 输出

最终输出不是一句建议，而是一组可验证工件：

1. 经过若干轮改写后的最佳 RTL；
2. 与原始 RTL 的 SEC 通过结果；
3. 最佳候选及各轮候选的 WNS、TNS、面积与综合报告；
4. 关键路径诊断和修改日志；
5. 更新后的 skill library，包含高/中/低置信度技能及 avoid list；
6. 可供下一设计复用的 Agent 配置与工具脚本。

所以它的任务可以概括为：在功能等价约束下，在可综合 RTL 的等价变换空间里搜索更好的 PPA 点，同时把搜索中反复出现的 pattern-strategy 经验整理为显式技能。

## 4. 方法与架构

### 4.1 整体 Pipeline（对应论文 Figure 2-3）

```text
原始 RTL + 约束
       │
       ▼
商业综合/STA ──► Timing Analysis Agent ──► 关键路径与结构诊断
       ▲                                      │
       │                                      ▼
Evaluation Agent ◄── N 个候选 RTL ◄── RTL Optimization Agent
       │                 ▲                    │
       │                 └──── Skill Library ┘
       ▼
SEC 过滤 + PPA 评分
       │
       ├── 选出本轮最佳候选，进入下一轮
       └── Skill Learning Agent 比较同组成功/失败候选并更新技能
```

系统通常执行 10 个大轮次，每轮并行产生 5 个候选，也就是每个设计最多约 50 次尝试。候选可以并行跑 EDA，因此墙钟时间更接近“轮数 × 一次 EDA 评估时间”，而不是“轮数 × 候选数 × EDA 时间”。

### 4.2 核心模块逐个详解

#### Orchestrator

Claude Code 负责调用专职 Agent、读写文件、发起工具脚本和维护当前最优状态。它不是一个只输出单次 patch 的聊天机器人，而是一个长时任务执行器：

- 把每轮的父设计、候选目录、报告路径和分数写入共享 JSON；
- 在上下文过长时依靠文件状态恢复，而不是只靠对话记忆；
- 控制候选并行和 EDA 作业提交；
- 汇总 SEC 状态和 PPA 指标，并按固定规则计算候选分数；
- 将最低 score 的合法候选晋升为下一轮基线；
- 在 10 轮后汇总最佳 RTL 与 skill 更新。

这一选择很有现实意义：研究者没有为了论文重新实现一套 IDE、Agent runtime 或网页界面，而是把研究创新集中到 EDA 闭环与记忆机制上。代价是系统会受到 Claude Code 版本、模型服务、计费与接口行为变化影响。

#### Timing Analysis Agent

综合报告本身往往只告诉工程师某条路径很慢。Timing Analysis Agent 继续完成四步：

1. 找出 top-k 关键路径的 startpoint、endpoint、逻辑层级、cell delay 和 fanout；
2. 把网表级路径映射回 RTL 模块、寄存器和表达式；
3. 判断瓶颈属于组合深度过大、高扇出、控制/数据耦合、重汇聚逻辑或算术链；
4. 输出一份可执行的修改假设，而不是泛泛地说“优化时序”。

论文消融显示，去掉细粒度寄存器 slack 反馈后，平均 WNS/TNS/面积收益从约 21%/17%/6% 降到约 9%/9%/3%，说明可定位到寄存器和关键路径的工具反馈对优化有效性影响明显。

#### RTL Optimization Agent

优化 Agent 根据诊断生成 5 个相互有差异的候选。它先检索 skill library：如果当前结构与已有模式匹配，就套用带条件的策略；如果没有，就提出新假设。

并行候选非常关键。RTL 等价变换具有强烈的非单调性：看似相似的两个重写会因映射、扇出或优先级语义而得到不同的综合结果。单次生成容易把偶然失败误判成策略无效，也容易把偶然成功误判成普遍规律。同父候选提供了一个小型“受控实验组”。

#### Evaluation Agent

Evaluation Agent 的职责被刻意限制为：

- 检查 RTL 是否能被工具解析和综合；
- 运行 SEC；
- 采集 WNS、TNS、面积等指标；
- 返回原始报告路径和状态。

它不负责替候选辩护，也不根据自然语言解释修改评分。这种角色隔离减轻了“生成者自己给自己打分”的偏差。特别是 SEC 是硬门槛：一个 PPA 再好的候选，只要等价检查失败，就不能晋级。

#### Skill Learning Agent

Skill Learning Agent 不只收集成功 patch，而是比较同一父设计下的候选组：

- 哪些候选改变了同一种结构；
- 哪些通过 SEC，哪些破坏了状态、位宽、符号或优先级语义；
- 哪些让 WNS/TNS 变好但面积恶化；
- 成功是否能由明确的结构条件解释；
- 该策略应进入高、中、低置信度还是 avoid 类别。

论文最终得到 47 项技能：12 项高置信度、16 项中置信度、6 项低置信度和 13 项 avoid。高置信度例子包括条件预计算、carry-select adder transformation、寄存器或信号复制；中置信度包括 mux-select 与无条件计算、mux-before-adder、公共子表达式消除；avoid 中既有综合器通常已经会做的低收益重写，也有经常恶化时序或破坏等价性的重写。

这里的关键不是“把所有过去 patch 拼进上下文”，而是把经验压缩为**模式、适用条件、动作、预期收益、风险和反例**。这比无边界的聊天记忆更接近工程知识库。

#### 三层优化轨迹

论文把轨迹分成三层：

- **iteration 层**：当前最佳设计如何沿 10 轮逐步演化；
- **candidate 层**：同一轮 5 个候选之间的相对表现；
- **critical-path 层**：每个候选具体针对哪条路径、哪类结构和哪项工具反馈。

这三层分别回答“搜索往哪里走”“这轮哪个动作更好”“指标为什么发生变化”。只有 patch，没有父子关系与工具报告，就无法可靠提炼 skill。

### 4.3 模块职责矩阵

| 模块 | 输入 | 输出 | 模型/工具 | 是否训练 |
|---|---|---|---|:---:|
| Orchestrator | 当前最佳 RTL、候选记录、工具结果 | 候选分数、晋级版本、迭代历史 | Claude Code + Claude Opus | 否 |
| Timing Analysis Agent | RTL、`timing_word.json`、关键路径报告 | 路径到 RTL 的映射、瓶颈类型和根因 | Claude Agent | 否 |
| RTL Optimization Agent | 当前 RTL、路径分析、skill library | 每轮 5 个 RTL 候选 | Claude Agent | 否 |

| Skill Learning Agent | 多轮轨迹、PPA/SEC 结果、RTL 差异 | pattern-strategy 条目和置信度 | Claude Agent | 否 |

## 5. 关键公式

### 5.1 带功能等价约束的优化目标（Eq. 1）

$$
D^{*}=\arg\min_D f(\operatorname{WNS},\operatorname{TNS},\operatorname{Area}),
\quad \text{s.t. } D\equiv D_0
$$

- \(D_0\)：原始人写 RTL。
- \(D\)：由 Agent 产生的候选 RTL。
- \(D^{*}\)：满足等价约束时的最佳候选。
- \(f\)：由 WNS、TNS 和面积组成的优化目标。
- \(D\equiv D_0\)：候选与原始设计通过顺序等价检查。

**工程直觉**：SEC 是硬约束，不是可用 PPA 收益抵消的软惩罚。候选只要不等价，就不能进入下一轮。

### 5.2 并行候选与版本晋级（Eq. 2）

$$
D_t\rightarrow\left\{D_t^{(i)}\right\}_{i=1}^{N}\rightarrow D_{t+1}
$$

- \(D_t\)：第 \(t\) 轮的父设计。
- \(D_t^{(i)}\)：从同一父设计生成的第 \(i\) 个候选。
- \(N\)：每轮候选数，论文实验取 5。
- \(D_{t+1}\)：本轮晋级后成为下一轮起点的设计。

**工程直觉**：同一父设计、同一约束和同一工具设置使 5 个候选构成可比较的小组，避免直接比较不同设计的绝对 PPA。

### 5.3 PPA 归一化与候选分数（Eq. 3-4）

论文 Eq. 3 对每项 PPA 指标采用同一归一化写法：

$$
\operatorname{PPA}_{i}^{norm}=\frac{\operatorname{PPA}_{i}-\operatorname{PPA}_{baseline}}{\operatorname{PPA}_{baseline}}
$$

候选综合分数为：

$$
\operatorname{Score}_{i}=\alpha\operatorname{WNS}_{i}^{norm}
+\beta\operatorname{TNS}_{i}^{norm}
+\gamma\operatorname{Area}_{i}^{norm}
+\operatorname{penalty}_{i}
$$

- \(\operatorname{PPA}_{baseline}\)：原始设计的 WNS、TNS 或面积。
- \(\operatorname{PPA}_{i}\)：候选 \(i\) 的对应指标。
- \(\alpha,\beta,\gamma\)：WNS、TNS、面积权重，分别为 0.50、0.35、0.15。
- \(\operatorname{penalty}_{i}\)：面积归一化增幅超过 0.10 时取 0.5，否则取 0。

由于实验中的基准 WNS/TNS 为负数，候选 slack 向 0 改善时，论文公式会得到负的归一化变化；面积下降同样得到负值，因此“分数越低越好”与论文表 3 的负百分比方向一致。

下一轮父设计选择为：

$$
D_{t+1}=\arg\min_{D_t^{(i)}}\operatorname{Score}_{i},
\quad \text{s.t. }\operatorname{SEC}_{i}=1
$$

- \(\operatorname{SEC}_{i}\)：候选 \(i\) 的顺序等价检查结果，通过时为 1。

> ⚠️ 公开仓库的 `CLAUDE.md`/`README.md` 把 WNS/TNS 分母写成基准绝对值，但其数值示例仍把改善记为负数；直接按该展示公式代入会得到相反符号。论文 Eq. 3、仓库公式与仓库示例三者并不完全一致，复现时必须固定实际采用的计算式。

### 5.4 组内相对优势（Eq. 5）

$$
A_t^{i}=\frac{\operatorname{Score}_{i}-\mu_t}{\sigma_t}
$$

- \(A_t^i\)：候选 \(i\) 在第 \(t\) 轮中的相对优势值。
- \(\mu_t\)：该轮候选分数均值。
- \(\sigma_t\)：该轮候选分数标准差。

**工程直觉**：score 越低越好，因此更负的 \(A_t^i\) 表示候选优于同组平均水平。每组只有 5 个候选，单轮相对值仍需跨轮、跨设计证据才能形成高置信度 skill。

### 5.5 并行评估的墙钟时间

$$
T_{wall}\approx K\times T_{EDA}
$$

- \(T_{wall}\)：完整优化任务的墙钟时间。
- \(K\)：迭代轮数，论文实验取 10。
- \(T_{EDA}\)：一轮并行候选的综合与 SEC 时间。

论文报告 EDA 执行是主要耗时；实际时间还受许可证数量、作业队列、最慢候选和远程传输影响。

## 6. 训练与实验设置

### 6.1 是否需要训练

Dr. RTL 不微调 Claude，也不训练专门的 RTL policy 或 reward model。所谓 self-improvement 指的是：

1. 在当前设计上通过工具反馈搜索；
2. 从候选相对结果中提炼显式 skill；
3. 在后续轮次和未见设计中检索这些 skill；
4. 继续用 SEC 与 PPA 证据修订技能置信度。

因此它更像“有实验记录和工程手册的自动化优化团队”，而不是传统强化学习训练。

### 6.2 实验设置

| 项目 | 设置 |
|---|---|
| 设计数 | 20 个 RTL 设计 |
| RTL 规模 | 平均约 812 LoC；范围约 128–4615 LoC |
| 结构规模 | 平均约 3 个模块、6230 个门、760 个寄存器 |
| 工艺库 | NanGate 45 nm |
| 时钟 | 0.1 ns，刻意制造强时序压力 |
| 搜索预算 | 10 轮 × 每轮 5 候选，约 50 次尝试/设计 |
| 主 Agent 模型 | Claude Opus，Claude Code CLI 编排 |
| EDA 工具 | Synopsys Design Compiler + Cadence JasperGold SEC |
| 泛化评估 | 4-fold cross-validation；每折 15 个设计学 skill，5 个未见设计测试 |

四折交叉验证很重要：每折都会重置 skill library，测试设计的 prompt 与示例不泄漏到训练折。这比“先在全部 20 个设计上总结经验，再在同一批设计上展示效果”更能支持技能迁移结论，但样本量仍然有限。

### 6.3 关键实验结果

#### 总体结果（Table 2）

20 个设计的平均结果为：

- WNS 改善 **21.3%**；
- TNS 改善 **16.9%**；
- 面积降低 **5.8%**；
- SEC 平均通过率 **86%**；
- 20/20 设计的时序均有改善；
- 9/20 同时获得时序与面积的 Pareto 改善；
- 8/20 的面积代价低于 5%；
- 3/20 出现较明显面积增长。

代表性个案如下：

| 设计 | WNS 改善 | TNS 改善 | 面积变化 | SEC 通过率 | 解读 |
|---|---:|---:|---:|---:|---|
| cpu_pipe | 71.1% | 88.4% | -11.8% | 90% | 时序和面积同时显著改善 |
| pcie | 44.3% | 17.1% | -33.9% | 100% | 强 Pareto 改善，所有候选均等价 |
| lstm | 25.3% | 30.3% | -67.9% | 83% | 面积收益极大，说明原 RTL 有较多可重构空间 |
| vending | 66.7% | 51.0% | +0.2% | 77% | 以几乎零面积代价换取显著时序收益 |
| controller | 13.2% | 9.8% | +18.0% | 94% | 时序改善伴随明显面积增长 |

百分比改善不等于 timing closure。Table 2 中各设计优化后的 WNS 仍为负值；在 0.1 ns 这种极端约束下，从 -0.10 ns 改到 -0.08 ns 可以记作约 20% 改善，但设计依旧违例。阅读结果时必须同时看绝对 WNS/TNS。

#### 与基线比较（Table 3）

论文表 3 的平均变化如下；负号表示对应违例或面积相对基线减少：

| 方法 | WNS 变化 | TNS 变化 | 面积变化 |
|---|---:|---:|---:|
| Single-shot Claude Opus | -2.4% | -2.8% | -0.7% |
| Single-shot GPT-5.3 | -1.2% | +0.3% | +0.6% |
| RTLRewriter | -4.9% | -6.3% | -3.1% |
| SymRTLo | -7.1% | -5.7% | -1.4% |
| **Dr. RTL** | **-21.3%** | **-16.9%** | **-5.8%** |

这里最有力的结论不是“Claude 比某模型强”，而是**带工具反馈的多轮搜索远强于一次性 prompt**。单次 Opus 和 GPT-5.3 都只获得小幅改进；Dr. RTL 的增益来自可定位反馈、并行候选、硬验证和跨轮记忆的组合。

#### 消融实验（Figure 6）

| 配置 | WNS 改善 | TNS 改善 | 面积降低 | SEC 通过率 |
|---|---:|---:|---:|---:|
| 完整系统 | 约 21% | 约 17% | 约 6% | 86% |
| 去掉寄存器级 slack 反馈 | 约 9% | 约 9% | 约 3% | — |
| 去掉多 Agent 分工 | 约 10% | 约 7% | 约 2% | — |
| 去掉 learned skills | 约 14% | 约 11% | 约 7% | 78% |

没有 skill 时面积平均值反而略好，但时序收益和 SEC 通过率下降。该消融支持 skill library 能提高有方向的探索效率与正确候选比例，但不能单独证明经验库会随运行时间持续产生复利。

#### 基础模型规模（Figure 8）

| 模型 | WNS 改善 | TNS 改善 | SEC 通过率 |
|---|---:|---:|---:|
| Qwen Coder 8B | 约 1% | 约 0% | 22% |
| Claude Haiku | 约 3% | 约 2% | 57% |
| Claude Sonnet | 约 12% | 约 9% | 73% |
| Claude Opus | 约 21% | 约 17% | 86% |

系统并不是“接上任何便宜小模型都会自动变强”。较弱模型首先在语义保持上失败，SEC 通过率低会让搜索预算大量浪费。迁移到其他 coding-agent 宿主时，skill 调用能力只是基础条件，模型理解跨模块 RTL、位宽、时序与状态语义的能力同样决定上限。

#### 不同 EDA 工具与阶段（Figure 9）

论文还比较了不同工具设置：Design Compiler 综合后评估约有 21%/17%/6% 的 WNS/TNS/面积收益；Yosys 综合后时序收益约 29%/28%，面积约 2%；Innovus 布局布线后仍保留约 14%/13% 的时序收益和约 4% 面积收益。单纯调 DC flow 选项的结果接近零，说明改 RTL 结构与调工具旋钮不是同一层次。

不过这些是影响研究，不代表 Agent 在 Yosys 或 Innovus 中完整闭环搜索。尤其 post-P&R 数字只说明迁移趋势，不能替代多角多模 signoff。

#### 运行时间与成本

作者报告 20 个设计约运行一周，LLM 使用费用约 50 美元，主要时间消耗来自综合与等价检查。这个数字不能直接理解成“复现实验只需 50 美元”：它不包含商业 EDA license、算力服务器、队列等待和工程环境搭建成本，也会随模型价格与缓存策略变化。

## 7. 创新点

### 创新点 1：用现成 coding agent 编排 EDA 优化闭环

Dr. RTL 没有另行实现通用 Agent runtime，而是在 Claude Code 工作流上叠加专职 Agent、EDA 脚本和 skill，使系统贡献集中在领域反馈、候选搜索与知识沉淀上。

### 创新点 2：用真实 EDA 结果替代语言模型自评

许多 LLM RTL 工作用编译错误或 testbench pass/fail 作反馈。Dr. RTL 把工业综合、STA 和 SEC 同时接入：优化方向由关键路径和 PPA 决定，正确性由形式工具决定。Agent 的自然语言分析只是提出假设，EDA 报告才是证据。

### 创新点 3：同父候选的组内相对学习

不同设计的面积、slack 与结构规模相差很大，直接比较绝对指标会产生大量伪规律。Dr. RTL 只在相同父设计、相同约束下比较并行候选，再提炼技能，近似构造低成本对照实验。它比只存“最佳 patch”更能识别失败边界。

### 创新点 4：同时维护正向 skill 与 avoid list

失败不是简单丢弃。系统记录“综合器本来就会做”“经常恶化时序”“容易破坏等价性”的模式，避免后续设计重复消耗昂贵 EDA 预算。对于自动研究或自动优化系统，**知道不该试什么**与知道该试什么同样重要。

### 创新点 5：把优化经验写成可审计工件

Skill 以可阅读、可版本控制的文本和代码模板保存，而不是写入模型权重。这使工程师能够检查适用条件、追踪证据并修订错误经验。

## 8. EDA 缩写表

| 缩写 | 全称 | 一句话解释 |
|---|---|---|
| RTL | Register-Transfer Level | 寄存器传输级硬件描述，是 Agent 直接修改的对象 |
| PPA | Power, Performance, Area | 功耗、性能、面积；本文实际评分重心是时序与面积，未做完整功耗闭环 |
| WNS | Worst Negative Slack | 最差负裕量；越接近 0 或转正越好 |
| TNS | Total Negative Slack | 所有违例路径负裕量之和；越接近 0 越好 |
| STA | Static Timing Analysis | 无需输入向量的静态时序分析，用于关键路径反馈 |
| SEC | Sequential Equivalence Checking | 顺序等价检查，验证改写前后跨时序状态行为是否等价 |
| DC | Design Compiler | Synopsys 商业逻辑综合工具 |
| JasperGold | Cadence JasperGold | 商业形式验证平台，可承担等价或属性验证 |
| Formality | Synopsys Formality | 公开仓库保留了 Formality LEC 脚本，但主运行入口注释掉该步骤，论文实验采用 JasperGold SEC |
| Innovus | Cadence Innovus | 物理设计工具，论文用来观察 post-P&R 收益 |
| QoR | Quality of Results | EDA 结果质量，通常包括时序、面积、功耗等 |
| Critical Path | 关键路径 | 限制时钟频率或产生最坏 slack 的路径 |
| High Fanout | 高扇出 | 一个信号驱动大量负载，可能造成缓冲、延迟与拥塞问题 |
| Skill Library | 技能库 | 带适用条件、动作、证据和风险的 RTL 优化经验集合 |
| Avoid List | 避免清单 | 已知低收益、高风险或综合器会自动完成的变换集合 |
| Group-relative | 组内相对 | 只比较同一父设计、同一轮、同一工具条件下的候选 |
| Tool-grounded | 工具落地/工具校准 | 结论由真实 EDA 执行结果支持，而非只由 LLM 自评 |
| LoC | Lines of Code | RTL 代码行数 |
| Pareto improvement | 帕累托改善 | 至少一项目标变好且其他目标不变坏；文中常指时序和面积同时更优 |

## 9. 与芯片流程的关系

### 9.1 在全流程中的位置

Dr. RTL 的核心价值链是：

```text
RTL 结构修改（①）
   → 逻辑综合获得门级映射与面积（③）
   → STA 暴露关键路径和违例（⑤）
   → SEC 保证行为不变（⑥）
   → 反馈到下一轮 RTL 修改（①）
```

这个闭环比只跑 lint/编译更接近真实前端优化，也比直接让 Agent 操作完整后端更容易控制变量。它正好占据架构设计完成、RTL 已可用，但综合 QoR 仍需工程师手工打磨的阶段。

### 9.2 “综合后 PPA 改善”和“能做成芯片”之间隔着什么

论文主结果来自 Nangate 45 nm 上的综合后 WNS、TNS 和面积。要进入真实芯片交付，还需要完成 floorplan、placement、CTS、routing、寄生提取、post-route STA、功耗与 IR Drop 分析、DRC/LVS 和多角多模签核。Figure 9 的 Innovus post-P&R 实验表明部分收益能够保留到后端，但论文没有公开完整后端约束和签核结果，因此不能把综合期改善解释成流片级改善。

### 9.3 与相邻工作的关系

#### ARES

[ARES](../ARES/论文深度讲解.md) 同样关注 Agent 驱动的 PPA 优化，但更强调成本感知与搜索预算。Dr. RTL 的辨识度在于 Claude Code 宿主、专职 Agent、同组相对 skill 学习，以及商业综合/SEC 的明确闭环。两者可以放在同一条“工具反馈式 EDA Agent”研究线上比较。

#### FluxBench

[FluxBench](../FluxBench/论文深度讲解.md) 主要回答“RTL-to-GDS Agent 应该怎样评测”，覆盖流程更广；Dr. RTL 回答“在 RTL PPA 优化这个窄而深的问题上，怎样真正搜索并积累经验”。前者偏 benchmark，后者偏方法系统。Dr. RTL 不能因为做了 post-P&R 实验就被视作完整 RTL-to-GDS Agent。

#### VPR-Evolve

[VPR-Evolve](../VPR-Evolve/论文深度讲解.md) 也体现让 Agent 在真实工具环境中迭代的范式，但工具栈、目标对象和搜索空间不同。把三者并列阅读，可以分辨“通用 Agent 框架创新”“领域工具接入”“记忆/技能机制”各自贡献了什么。

### 9.4 对 Agent 工作流的启示

将 Dr. RTL 的工作流迁移到其他 coding-agent 宿主时，可以保留以下领域层设计：

- 用一个项目级 skill 定义 RTL 优化 SOP、硬约束和报告格式；
- 用 MCP 或稳定的命令封装综合、STA、SEC 和作业队列；
- 按路径分析、候选生成、独立评估和技能提炼划分职责；
- 把所有候选、工具版本、约束摘要和父子关系落盘；
- 只有工具结果能升级技能置信度，LLM 自评不能；
- 对商业工具保留 license、远端环境和安全边界，不把工具凭据写入 skill。

该设计仍留下两个可继续研究的问题：skill 能否跨模型宿主、跨 EDA 工具和跨设计稳定迁移，以及怎样用可审计的证据与反例控制经验库污染。

## 10. 讨论与局限

### 10.1 论文自述的局限

1. **目标函数不含功耗**：论文明确说明，可靠功耗估计依赖工作负载，静态评估不足以支撑当前实验，因此实际优化目标只有 WNS、TNS 和面积。
2. **微架构保持不变**：方法允许组合变换和保持延迟的顺序重构，但固定原始流水级数，不搜索新的体系结构或吞吐率方案。
3. **时序优先**：论文展示的是 RTL timing optimization，不是完整 PPA、物理设计或 signoff 优化。

### 10.2 代码/复现层面的问题

1. **依赖商业 EDA**：完整流程需要 Synopsys Design Compiler 和 Cadence JasperGold；复现 Figure 9 的后端结果还需要 Innovus、对应许可证和远程 EDA 主机。
2. **评分公式存在公开材料不一致**：论文 Eq. 3 以带符号的 baseline 为分母；仓库 `CLAUDE.md`/`README.md` 对 WNS/TNS 写成绝对值分母，但同一文件的数值示例仍按带符号分母计算。仓库没有独立评分程序，评分由工作流指令约束，因此复现前必须先统一公式。
3. **LSTM 使用仿真特例**：公开 `run_design.py` 对多数设计运行 JasperGold SEC，但对 `LSTM` 特判为 VCS 仿真，并仍把结果写入 `SEC_result.txt`。这与“所有设计均使用 SEC”的论文总口径不完全一致。
4. **Formality 不是主运行路径**：仓库保留 `fm.tcl` 和 `run_lec()`，但主入口将 Formality 调用注释掉；论文实验明确写的是 Cadence Jasper SEC。
5. **缺少实验轨迹**：公开仓库描述了 `log/`、`history/` 和 `output/`，当前快照未包含论文实验的逐轮日志、候选 RTL 和原始报告，无法从仓库重新计算表 2、表 3 与 skill 统计。
6. **闭源 Agent 宿主影响可重复性**：Claude Code、Claude 模型版本和系统行为会更新，公开 Markdown 工作流不能保证逐次生成相同候选。

### 10.3 本资料包的批判性分析

1. **0.1 ns 时钟会放大相对改善**：所有设计都处于强负 slack 区间，百分比下降不等于 timing closure。论文表 2 给出绝对 WNS/TNS，阅读时应与相对百分比同时使用。
2. **设计规模仍有限**：20 个设计平均 812 行、3 个模块，尚未覆盖大型 SoC 的多时钟域、低功耗结构、memory/blackbox IP 和复杂时序例外。
3. **SEC 结论依赖建模边界**：reset、X 语义、memory 模型、时钟 gating 和未定义行为都会影响等价结果，只保存 pass/fail 布尔值不足以完整审计。
4. **固定加权分数隐藏设计偏好**：0.50/0.35/0.15 的 WNS/TNS/面积权重和 10% 面积阈值不一定适合面积受限或功耗受限项目。
5. **skill 归因样本较小**：每组仅 5 个候选，且一次候选可能包含多个编辑。组内比较减小了跨设计噪声，但不能单独证明某个变换与收益之间的因果关系。
6. **没有完整物理签核**：论文没有活动率驱动功耗、IR/EM、DRC/LVS 和多角多模 signoff；综合期面积或时序改善不保证流片指标同步改善。
7. **skill 与工具设置耦合**：某项变换在 DC/Nangate45 上有效，不代表在另一综合器、工艺库或约束下仍然有效，技能条目应同时记录工具与约束上下文。

## 12. 一分钟复述版

Dr. RTL（HKUST，ICCAD 2026）是一个不训练新模型、使用 Claude Code 编排商业 EDA 工具的 RTL 时序优化框架。核心流程可以概括为四步：

1. **路径分析**：从 Design Compiler 的综合后时序报告中提取关键路径，并映射回 RTL 瓶颈。
2. **并行改写**：每轮由优化 Agent 生成 5 个候选，分别尝试组合或保持延迟的顺序变换。
3. **工具验证**：用 WNS、TNS、面积评分，并以 JasperGold SEC 作为功能正确性门槛；最佳合法候选进入下一轮。
4. **技能提炼**：比较同一父设计下的候选，将成功、条件有效和失败策略整理为 47 个 pattern-strategy 条目。

实验覆盖 20 个设计，每个设计运行 10 轮 × 5 候选。在 Nangate 45 nm 和 0.1 ns 时钟约束下，平均 WNS/TNS 改善 21.3%/16.9%，面积降低 5.8%，SEC 通过率为 86%。

**边界**：结果主要是综合后时序与面积，不含功耗目标和完整物理签核；20 个设计规模仍有限；公开仓库缺少原始实验轨迹，评分公式文档存在符号不一致，完整复现还依赖商业许可证和闭源模型服务。
