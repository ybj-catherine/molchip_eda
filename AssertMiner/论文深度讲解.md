## 1. 一句话定位

**AssertMiner 用 AST 静态结构分析给 LLM 做「模块级」断言生成的导航：先把 RTL 解析成 AST，抽出模块调用图（MCG）、I/O 表、数据流图，再逆向遍历数据流图得到「从顶层输入一路传到子模块输出的跨模块信号链」，据此把大规格拆成「每个模块自己的规格」，最后引导 LLM 为模块级信号挖掘深度断言——解决「spec 方法只写顶层断言、模块级 Bug 晚暴露又难定位」的痛点，优于 AssertLLM / Spec2Assertion。**

这句话里的四个承重点：

1. **AST 静态结构三件套** — 模块调用图 MCG（谁实例化了谁）、I/O 表（每模块端口方向 + 连到父层哪个信号）、数据流图（信号在模块内/跨模块怎么传）。这是「结构落地」的地基。
2. **跨模块信号链** — 从顶层输入向后遍历数据流图，得到“信号从哪来、到哪去”的具体传播路径；内部信号在链简化时被剪掉，避免被可能有 bug 的内部数据流污染。这一表示与可控性、可观察性分析相关，但论文是否提供显式证明仍需核对原文。
3. **两阶段 LLM** — 先「模块级规格抽取」（prompt 含模块名/父名 + I/O 表 + 代表信号链 + 顶层 NL 规格，**刻意不喂模块内部 RTL 实现**，把规格推理和可能错的 RTL 解耦）；再「模块级断言挖掘」（规格 → 模块信号的定向深度断言）。
4. **四阶段工作流 + model-checking 评价** — 挖出的断言交模型检查工具，对照 golden RTL 评价。

## 3. 输入 / 输出

### 3.1 输入

| 输入项 | 说明 |
|---|---|
| **RTL 设计** | 待生成断言的模块化 RTL |
| **顶层 NL 规格** | 自然语言写的整体规格 |
| **LLM** | 现成 LLM（推理时，不微调） |

### 3.2 中间产物（AST 静态结构三件套）

- **MCG（Module Call Graph）**：节点 = 模块，边 = 实例化关系（谁包含谁）。
- **I/O 表**：每模块端口名 / 方向（in/out）/ 连到父层哪个信号。
- **数据流图**：信号在模块内、模块间的传播（基于赋值与依赖）。
- **跨模块信号链**：从顶层输入到子模块输出的具体传播路径（逆向遍历数据流图得到）。

### 3.3 输出

- 每模块一份「模块级规格」；
- 每模块的「模块级深度 SVA 断言」（比 AssertLLM / Spec2Assertion 更细、更靠近 bug 源头）。

## 4. 方法与架构

### 4.1 整体 Pipeline（四阶段）

```text
RTL ──▶ AST 解析
            │
            ▼
    ① 静态结构抽取
       ├─ MCG（模块调用图）
       ├─ I/O 表
       └─ 数据流图
            │
            ▼
    ② 跨模块信号链抽取（逆向遍历数据流图，剪掉内部信号）
            │
            ▼
    ③ 模块级规格抽取（LLM：模块名/父名 + I/O 表 + 信号链 + 顶层规格，不喂内部 RTL）
            │
            ▼
    ④ 模块级断言挖掘（LLM：规格 → 模块信号深度断言）
            │
            ▼
    ⑤ 对照 golden RTL，用 model-checking 评价
```

### 4.2 关键设计点

**（1）「不喂内部 RTL 实现」解耦** — 模块级规格抽取时，prompt 里刻意只放模块名/父名、I/O 表、代表信号链和顶层 NL 规格，不放模块内部 RTL 实现。这样规格推理不会被可能错误的 RTL 带偏，体现了答案应从规格独立推导而不是照抄 DUT 的原则。

**（2）剪掉内部信号** — 信号链简化时把内部信号剪掉，防止有 bug 的内部数据流污染链；但这也可能遗漏真正承担决策逻辑的内部节点，需要在精读原文时核对取舍。

**（3）AssertMiner-pro 的自顶向下改进** — 原版对每个子模块**孤立**生成规格，调用深度越深、越容易漏掉低层模块规格；**AssertMiner-pro 用自顶向下层级策略**，把规格意图逐层向下传播，并把 RTL 代码作为参考喂给 LLM，捕获更全的模块级信息，得到更细的深度断言和更高结构覆盖率。

## 5. 关键公式

论文以 prose + 图描述，无核心编号公式可摘。核心机制可概括为两个图运算：

- **逆向遍历数据流图**：从顶层输出/输入向后追，得到跨模块信号链；
- **内部信号剪枝**：链上只保留「跨模块边界」的信号，去掉模块内部信号。

## 6. 训练与实验设置

### 6.1 是否需要训练

**不需要。** 纯静态分析 + 推理时 LLM 提示，不微调模型。

### 6.2 评价

| 指标 | 说明 |
|---|---|
| 断言质量 | 对照 golden RTL + model-checking 判定 |
| 结构覆盖率 | 断言触达设计的比例 |
| 错误检出能力 | 能抓出多少注入/已有错误 |

### 6.3 关键结果（摘要级，待核）

- 模块级断言质量**优于 AssertLLM 和 Spec2Assertion**；
- 与这些方法**集成**后，能提升结构覆盖率、显著提升错误检出能力；
- AssertMiner-pro（自顶向下）得到更细粒度深度断言 + 更高结构覆盖率。

## 7. 创新点

### 创新点 1：模块级目标选择（相对顶层断言）

现有 spec 方法只写顶层断言，模块/子模块级 bug 晚暴露、难定位。AssertMiner 用 AST 静态结构把「该给哪些模块写断言」显式化，生成「模块级深度断言」，让断言**更早、更靠近 bug 源头**触发。

### 创新点 2：AST 三件套 + 跨模块信号链

MCG + I/O 表 + 数据流图 → 跨模块信号链，把「信号从哪来、到哪去」的结构证据喂给 LLM，是「结构落地」的一种具体做法。

### 创新点 3：规格推理与 RTL 实现解耦

模块级规格抽取时**不喂内部 RTL**，避免规格被错误实现带偏——呼应「oracle 必须独立」原则。

> ⚠️ **研究边界**：创新点 1 已覆盖模块级目标选择，但论文没有把目标选择建模为带困难负例的监督排序任务，也没有给出可控到可观察的完整路径证明或真实历史缺陷评测。

## 9. 与芯片流程的关系

AssertMiner 落在“写断言之前”的模块级目标导航环节，横跨 ② 仿真与 ⑥ 形式验证。它在生成验证工件之前选择目标，粒度是模块级，证据来自 AST 静态结构，而不是完整的可控到可观察因果路径。

## 10. 讨论与局限

### 10.1 论文自述局限（摘要级）

1. 原版对深调用层级可能漏掉低层模块规格（AssertMiner-pro 针对此改进）；
2. 效果依赖静态分析的准确性和顶层规格质量。

### 10.2 本资料包的批判性分析

1. **「跨模块信号链」仍是结构导航**：它剪掉内部信号并给出信号传播路径，但停留在数据流可达层面，不等于包含 controllability/observability 论证的因果路径证明。
2. **终局是 golden RTL + 结构覆盖**，不是「模型没见过的真实历史 Bug」。
3. **依赖 RTL 静态分析**：它需要读取 RTL，不适用于只有规格而无法查看实现的场景。
4. **实现细节待核**：本讲解基于摘要，四阶段工作流的具体步骤编号、实验 benchmark、model-checking 工具型号均需原文确认。

## 12. 一分钟复述版

AssertMiner（ASP-DAC 2026）用 AST 静态结构给 LLM 做「模块级」断言导航：AST → MCG + I/O 表 + 数据流图 → 逆向遍历得「跨模块信号链」（剪掉内部信号防污染）→ 先抽「每模块规格」（不喂内部 RTL，解耦实现）→ 再挖「模块级深度断言」→ model-checking 对照 golden RTL 评价。优于 AssertLLM / Spec2Assertion；AssertMiner-pro 用自顶向下策略进一步细化。

**研究定位**：它是模块级目标选择的直接相关工作；阅读原文时应重点确认跨模块信号链是否包含 controllability/observability 的显式证明。
