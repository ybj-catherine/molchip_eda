## 1. 一句话定位

**BugGen 是一个全自动的多 Agent LLM pipeline，用 4 个专职 Agent（Partitioner → Target Selector → Mutation Generator → Validator）协作在 RTL 代码中注入真实的 bug，在 5 个 OpenTitan IP 模块上生成 500 个 unique bugs（94% 功能准确率），发现 104 个 OpenTitan 回归测试未检出的 bug，比商业突变测试工具 Certitude 语法准确率高 2 倍。**

---

## 2. EDA 阶段映射（①-⑰）

| 阶段 | 覆盖 | 说明 |
|------|:---:|------|
| ① RTL 设计 | ✅ **核心** | 在已有 RTL 代码中注入 bug |
| ② 功能仿真 | ✅ **核心** | 用仿真验证 bug 是否可检测 |
| ③-⑰ | ❌ | 不涉及综合及后端流程 |

**覆盖率：2/17。** BugGen 专注 RTL 级别的 bug 注入与验证，不涉及综合或物理设计。


---

## 3. 输入 / 输出

### 3.1 输入

- **RTL 设计**：OpenTitan IP 模块（5 个：AES、HMAC、CSRNG、OTBN、Keymgr），SystemVerilog 代码，每个模块数百到数千行
- **Testbench**：OpenTitan 官方回归测试套件
- **验证工具**：Verilator（仿真）、Verible（语法检查）

### 3.2 中间产物

- **Module Partitions**：Partitioner Agent 将设计拆分为逻辑块
- **Mutation Target Regions (MTRs)**：Target Selector 选择需要注入 bug 的代码区域
- **Mutation Candidates**：Mutation Generator 生成的候选 bug 代码
- **Validation Reports**：Validator 的仿真/语法检查结果

### 3.3 输出

- **500 unique validated bugs**（每个 bug 包含：buggy RTL diff、触发条件、预期影响）
- **104 previously undetected OpenTitan bugs**（暴露了回归测试的覆盖盲区）
- **Bug 分类报告**（按模块和 bug 类型）

## 4. 方法与架构

### 4.1 整体 Pipeline

```
┌──────────────────────────────────────────────────────────────────┐
│                      BugGen Multi-Agent Pipeline                  │
│                                                                   │
│  ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐      │
│  │ Partitioner│ →│  Target  │ →│ Mutation │ →│ Validator│      │
│  │   Agent   │  │ Selector │  │ Generator│  │   Agent  │      │
│  └──────────┘   └──────────┘   └──────────┘   └──────────┘      │
│       │              │              │              │              │
│       ▼              ▼              ▼              ▼              │
│  拆分为逻辑块   选择 MTRs    生成 bug 代码   仿真+语法验证       │
│                              (多候选+       失败→回滚重试        │
│                              迭代优化)                           │
│                                                                   │
│  ◄──────────────── 失败时回滚到 Mutation Generator ──────────    │
│                                                                   │
└──────────────────────────────────────────────────────────────────┘
```

### 4.2 四个 Agent 详解

**Agent 1: Partitioner（分区器）**
- 做什么：将 RTL 设计按功能边界拆分为逻辑块
- 为什么：避免在一个超大模块中盲目搜索注入位置，提高效率
- 输入：完整 RTL 代码
- 输出：模块分区方案

**Agent 2: Target Selector（目标选择器）**
- 做什么：在每个分区中选择 Mutation Target Regions（MTR）
- 为什么：不是所有代码行都适合注入 bug（有些是 boilerplate、有些改了会导致语法错误）
- 输入：分区方案 + RTL 代码
- 输出：MTR 列表（代码行范围 + 功能描述）
- **关键指标**：95.87% 的 mutations 落在「工程师标记的功能有意义区域」

**Agent 3: Mutation Generator（突变生成器）**
- 做什么：在选定的 MTR 中生成具体的 bug 代码
- 为什么：需要生成功能上有意义的 bug（不是随机改），且需要保持语法正确
- 输入：MTR + 原始 RTL 代码
- 输出：多个候选 bug 版本
- **关键机制**：迭代式生成 + 自我修正

**Agent 4: Validator（验证器）**
- 做什么：验证生成的 bug 是否 (1) 语法正确（Verible 检查）、(2) 功能可检测（仿真对比）
- 为什么：过滤掉语法错误和「冗余突变」（改变代码但不影响仿真结果）
- 输入：buggy RTL + testbench
- 输出：PASS（bug 有效）/ FAIL（回滚到 Generator）

### 4.3 自我修正闭环

```
Mutation Generator 生成 8 个候选
        ↓
Validator 验证
        ↓
   ┌────┴────┐
   │          │
  PASS       FAIL
   │          │
   ▼          ▼
 入库     反馈错误信息给 Generator
           Generator 修正后重新生成
           (最多 3 轮重试)
```

### 4.4 模块职责矩阵

| 模块 | 输入 | 输出 | 用到的模型 | 是否需训练 |
|------|------|------|-----------|:---:|
| Partitioner | RTL 代码 | 模块分区 | LLM（GPT-4 级） | 否 |
| Target Selector | 分区 + RTL | MTR 列表 | LLM | 否 |
| Mutation Generator | MTR + RTL | buggy RTL 候选 | LLM | 否 |
| Validator | buggy RTL + TB | PASS/FAIL | Verilator + Verible | 否 |

## 6. 创新点

### 创新点 1：首个全自动 LLM Bug Synthesis Pipeline

与 Mantra（基于固定 mutation 算子）和人工注入不同，BugGen 让 LLM 自主决定在哪里注入什么样的 bug。这比固定规则更灵活，能生成更多样的 bug。

### 创新点 2：自我修正闭环

通过 Validator → 反馈 → Generator 重试的闭环，确保生成的 bug 语法正确 + 功能可检测。

### 创新点 3：验证盲区发现

不仅生成 bug，还能暴露 testbench 的盲区——104 个 OpenTitan 回归测试未检测到的 bug。

## 8. 与相关公开工作的关系

BugGen 的公开定位是多 Agent RTL 缺陷生成。它适合作为合成缺陷生成基线，但生成缺陷的语法与功能可触发性不能自动证明其分布等同于真实工程缺陷；跨方法比较必须单独报告真实性与多样性。

---

## 9. 讨论与局限

### 9.1 论文自述的局限

- 仅在 5 个 OpenTitan IP 模块上评估，覆盖面有限
- 依赖 LLM API（成本 + 稳定性）
- 不保证所有生成的 bug 在语义上是「有意义」的


- **核心盲区**：BugGen 不知道什么是「真实 bug 的机制」。它生成的 bug 只是「看起来真实」，没有机制层面的真实性保证。
- **没有分类学**：500 个 bugs 没有按任何机制维度分类，不知道生成分布是否匹配真实分布。
- **没有检测模型**：只有生成，没有训练检测模型，没有形成闭环。

---

## 10. 一分钟复述版

1. BugGen 是第一个全自动的 LLM 多 Agent RTL bug 合成 pipeline
2. 4 个 Agent：分区 → 选目标 → 生成 bug → 验证（失败回滚重试）
3. 500 bugs、94% 准确率、17.7 bugs/小时
4. 在 OpenTitan 上发现 104 个回归测试未检出的 bug
5. 证明了 LLM 能生成「看起来真实」的硬件 bug
6. 但它不知道真实 bug 的机制是什么
