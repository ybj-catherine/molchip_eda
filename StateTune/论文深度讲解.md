# StateTune 论文深度讲解

> **StateTune: Transforming LLM-Assisted EDA Flow Tuning into a Stateful, Closed-Loop Process**
> KunLong Li, Shangshang Yao, Su Zheng, Lingli Wang
> arXiv:2608.23601
> 原文：[2608.23601_StateTune.pdf](./2608.23601_StateTune.pdf) · [2608.23601_StateTune.txt](./2608.23601_StateTune.txt)

## 1. 一句话定位

**StateTune 把 LLM 辅助 EDA flow tuning 从临时 proposer 改成 stateful closed-loop：用 typed、evidence-gated persistent memory 同时驱动候选生成与 EHVI-guided、runtime-aware promotion；在 2 工艺 × 3 设计的工业矩阵上取得最强 hypervolume。**

这句话里的三个承重点：

1. **persistent memory** — 每次 evaluation 更新规则、敏感性和失败模式，不是用完即弃。
2. **evidence gating** — 防止错误规则污染记忆；移除后 HV 下降 43.4%。
3. **runtime-aware promotion** — 用单位 runtime 的预期 Pareto 前沿增益分配 scarce full-flow 预算。

## 3. 输入 / 输出

### 3.1 输入

- Cadence Genus/Innovus flow。
- ASAP7 与 NanGate45。
- JPEG、AES、IBEX。
- 参数空间、多目标指标和 quick-stage/full-flow 成本。

```text
statetune_input = {
  technology: ["ASAP7","NanGate45"],
  designs: ["JPEG","AES","IBEX"],
  objectives: ["hypervolume","WNS","area","power"],
  full_flow_cost_hours: 4
}
```

### 3.2 中间产物

- persistent memory $M_t$。
- evidence-gated rules 和 parameter sensitivities。
- quick-stage candidate ranking。

```text
memory_snapshot = {
  rule_1: "high utilization increases WNS risk",
  sensitivity: {"utilization": -0.18, "cts_target_skew": -0.07},
  failed_ranges: ["utilization>0.82"]
}
```

### 3.3 输出

```text
statetune_output = {
  best_hypervolume: "strongest on all six blocks",
  memory_ablation_hv_loss: "58.5%",
  gating_ablation_hv_loss: "43.4%",
  reproducibility: "CV<7% on five of six blocks"
}
```

## 4. 方法与架构

### 4.1 整体 Pipeline

```text
Evaluation results
          │
          ▼
Evidence-gated persistent memory M_t
          │
          ├──────────────────────┐
          ▼                      ▼
Candidate generation       Budget allocation
          │                      │
LLM proposal              EHVI + runtime-aware promotion
          │                      │
          └──────────┬───────────┘
                     ▼
          Quick-stage / full-flow evaluation
```

### 4.2 核心模块逐个详解

- **Persistent memory**：typed 存储规则、敏感性、失败范围，随 evaluation 更新。
- **Candidate generator**：LLM 从 memory 生成下一组配置。
- **Promotion policy**：用 EHVI 和 runtime cost 选择值得 full-flow 的 quick-stage 候选。
- **Evidence gate**：只接受有足够支持的新知识，防止 memory poisoning。

### 4.3 模块职责矩阵

| 模块 | 输入 | 输出 | 工具/模型 | 是否需训练 |
|---|---|---|---|---|
| Memory update | evaluation results | rules, sensitivities | typed store | 否 |
| Candidate generation | memory | candidate configs | LLM | 否 |
| Promotion | quick-stage results | ranked candidates | EHVI policy | 否 |
| Evaluation | configs | PPA | Cadence flow | 否 |

## 5. 关键公式

### 5.1 Memory update

$$
M_t=\mathrm{Update}(M_{t-1},x_t,y_t,g_t)
$$

- $M_t$：第 t 步持久记忆
- $x_t$：候选配置
- $y_t$：evaluation 结果
- $g_t$：evidence gate

### 5.2 Candidate generation

$$
x_{t+1}\sim \pi_{LLM}(\cdot \mid M_t)
$$

- $x_{t+1}$：下一候选
- $\pi_{LLM}$：LLM 生成策略

### 5.3 Runtime-aware promotion

$$
\mathrm{rank}(x)=\frac{EHVI(x)}{cost(x)}
$$

- $EHVI(x)$：expected hypervolume improvement
- $cost(x)$：该候选 runtime 成本

## 6. 训练与实验设置

### 6.1 是否需要训练

LLM 不训练，使用 closed-loop inference。模型只根据 persistent memory 生成候选，不更新权重；状态学习来自每次 evaluation 对 typed memory 的更新。

### 6.2 实验设置

- 6 blocks：ASAP7/NanGate45 × JPEG/AES/IBEX。
- baseline：qEHVI、Optuna-TPE、Random、RankTuner、CROP。
- 消融：persistent memory、evidence gating、memory poisoning、cross-design transfer、three-seed reproducibility。

### 6.3 关键实验结果

| 指标 | 结果 |
|---|---|
| Final hypervolume | 六个 block 全最优 |
| Removing memory | HV 下降 58.5% |
| Removing gating | HV 下降 43.4% |
| Reproducibility | 五个 block CV < 7% |

## 7. 创新点

1. 将 LLM 辅助 EDA tuning 重构为 stateful closed-loop。
2. 提出 typed、evidence-gated persistent memory 同时驱动 proposal 和 promotion。
3. 引入 EHVI-guided、runtime-aware promotion。

## 9. 与芯片流程的关系

### 9.1 在全流程中的位置

StateTune 位于 flow tuning 外层，横跨综合、floorplan、placement、CTS 和 routing。它接受 EDA 工具反馈，把经验提炼成 persistent memory，指导下一轮配置。

### 9.2 从“flow tuning 改善”到“能做成芯片”之间还缺什么

完整签核仍需 DRC/LVS、IR drop、多 corner 和制造验证；StateTune 目前优化 hypervolume、WNS、area 和 power，不覆盖这些 signoff 项目。

## 10. 讨论与局限

### 10.1 论文自述的局限

工业结果依赖 Cadence 工具和 PDK；六个 block 规模有限。论文的 cross-design transfer 和 reproducibility 分析说明主要结论稳定，但仍不能自动推广到任意工艺和设计。

### 10.2 代码/复现层面的问题

论文声明代码开源，但工业流程复现受工具许可和 PDK 限制。开源部分可能覆盖 memory、promotion 和 candidate generation，但 full-flow 结果仍需要 Cadence Genus/Innovus。

### 10.3 本资料包的批判性分析

memory 质量是关键；如果 evidence gate 设计不当或 quick-stage 与 full-flow 不一致，promotion 会错配昂贵预算。

## 12. 一分钟复述版

LLM 调 EDA 参数时，临时上下文会让经验用完就丢。StateTune 建立 typed、evidence-gated persistent memory，每次 evaluation 更新规则和敏感性；LLM 用 memory 生成候选，EHVI 按单位 runtime 的 Pareto 前沿增益分配 full-flow 预算。这样 tuning 从“生成配置”升级为会积累经验的 stateful closed-loop。
