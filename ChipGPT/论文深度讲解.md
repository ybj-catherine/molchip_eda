# ChipGPT 论文深度讲解

> **ChipGPT: Leveraging Large Language Models for Automated and Optimized SoC Floorplanning**
> Aswini S, Anto Kumar R P, Varun CM, Seenuvasan P, Dhanalakshmi R, G Sekar
> 2026 12th International Conference on Communication and Signal Processing (ICCSP)
> DOI: 10.1109/ICCSP68173.2026.11539254
> 原文：[ChipGPT_ Leveraging Large Language Models for.pdf](./ChipGPT_ Leveraging Large Language Models for.pdf) · [ChipGPT_ICCSP2026.txt](./ChipGPT_ICCSP2026.txt)

## 1. 一句话定位

**ChipGPT 把 SoC floorplanning 转化为“结构化文本 + LLM 迭代 proposal + 物理 cost 反馈”的闭环优化问题，不微调模型；在 IBM-HB+ 上相对 tuned SA 平均降低 39.5% wirelength，相对商业 auto-placer 平均降低 15.8%。**

这句话里的三个承重点：

1. **文本编码方案** — 将 netlist、宏属性、约束和当前布局状态编码成 LLM 可理解的结构化 prompt，使 LLM 把网表当作组件与连接的“语言”。
2. **交互式优化 loop** — LLM agent 每次只输出一个具体合法 action，cost engine 计算 HPWL、area 和 congestion 后把 `delta-cost` 回填给后续 prompt。
3. **不训练但能跨 benchmark 泛化** — 主实验使用 GPT-4-Turbo，局部验证 CodeLlama-34B-Instruct；同一核心 LLM 不重训即可处理 12 到 200+ 宏。

## 3. 输入 / 输出

### 3.1 输入

- 矩形宏集合、固定 die 尺寸、网表连接和设计约束。
- LLM 每次看到的当前 floorplan 状态、最近动作和成本变化。
- benchmark：IBM-HB+、GSRC、NanGate45。

```text
macro m1 { type=cpu, w=120, h=80, pins=[clk,addr,data] }
macro m2 { type=sram, w=64, h=64, pins=[addr,data] }
net n1 { m1.data, m2.data }
constraint { m1 near m2, io_blocks on north, aspect_ratio in [0.8,1.4] }
```

### 3.2 中间产物

LLM 输出的 action 文本和 evaluator 计算的 scalar cost：

```text
ACTION: Move SRAM m2 closer to CPU m1 to reduce bus latency
COST_BEFORE: 1.98e6
COST_AFTER: 1.90e6
DELTA: -0.08e6
ACCEPT: true
```

### 3.3 输出

- 最终合法 floorplan 的宏坐标和几何尺寸。
- wirelength、area、congestion 和 runtime。
- 可用于人工审查的文本 action log。

```text
floorplan {
  m1 { x=20, y=20, w=120, h=80 }
  m2 { x=160, y=20, w=64, h=64 }
  total_hpwl=1.45e6
  area=3.2e6
  peak_congestion=0.14
}
```

## 4. 方法与架构

### 4.1 整体 Pipeline

```text
Netlist + macros + constraints
            │
            ▼
Structured textual encoding
            │
            ▼
LLM agent proposes ONE action
            │
            ▼
Fast C++ cost engine evaluates
            │
            ▼
Feedback: Phi and delta-cost
            │
            ▼
Iteration controller accepts / rejects
            │
            ▼
Final floorplan
```

### 4.2 核心模块逐个详解

- **Textual Encoding**：每个宏记录名称、功能类型、尺寸、pin 列表；每条 net 描述 pin 到 pin 连接。这样可以自然表达硬约束和 soft 指令。
- **Prompt Protocol**：包含 system role、2-3 个 few-shot 示例、当前状态和最近 k 步历史，让 LLM 只输出一个 action。
- **Cost Engine**：C++ evaluator 在 $O(n)$ 内计算 HPWL，使用 10×10 grid 估计 congestion，同时检查 overlap 和边界。
- **Iteration Controller**：最多 300 次迭代，50 次无改善则早停；采用 hill-climbing，偶尔接受 cost-increasing 动作避免停滞。

### 4.3 模块职责矩阵

| 模块 | 输入 | 输出 | 工具/模型 | 是否需训练 |
|---|---|---|---|---|
| Text encoding | netlist, constraints | structured prompt | Python parser | 否 |
| LLM optimizer | prompt state | one floorplan action | GPT-4-Turbo / CodeLlama-34B | 否 |
| Cost evaluator | new macro coordinates | HPWL, area, congestion | C++ evaluator | 否 |
| Iteration controller | delta-cost | accept/reject | deterministic rule | 否 |

## 5. 关键公式

### 5.1 目标函数

$$
\Phi = \lambda_1 \cdot WL + \lambda_2 \cdot A + \lambda_3 \cdot CONG
$$

- $\Phi$：总 floorplanning cost
- $WL$：所有 net 的总半周长线长 HPWL
- $A$：布局 bounding box 面积
- $CONG$：局部 cell 密度超过阈值产生的 congestion penalty
- $\lambda_1,\lambda_2,\lambda_3$：三项目标的权重

**工程直觉**：floorplan 质量不只是线长，还要控制面积和局部拥挤，否则后续 placement/routing 会付出更高代价。

**为什么这么设计**：加权标量 cost 便于 LLM 和 iteration controller 比较“这次移动是否更好”。

### 5.2 HPWL

$$
WL = \sum_{e \in E} \left(\max_{i \in e} x_i - \min_{i \in e} x_i + \max_{i \in e} y_i - \min_{i \in e} y_i\right)
$$

- $E$：所有 net 集合
- $e$：单条 net
- $x_i,y_i$：pin 的坐标

## 6. 训练与实验设置

### 6.1 是否需要训练

不训练。LLM 使用 zero-shot/few-shot 推理；主实验通过 GPT-4-Turbo API，本地验证使用 CodeLlama-34B-Instruct。

### 6.2 实验设置

- 主指标：Total HPWL。
- 次指标：final area、peak congestion、runtime。
- 迭代预算：最多 300 次，50 次无改善早停。
- 硬件：API 实验使用 Intel Xeon CPU；本地 LLM 使用单张 NVIDIA A100。

### 6.3 关键实验结果

| Benchmark | ChipGPT WL | SA Baseline | Commercial Tool | ChipGPT Runtime |
|---:|---:|---:|---:|---:|
| ibm01 | 1.45e6 | +36% | +12% | 8.2 min |
| ibm02 | 3.21e6 | +40% | +17% | 12.5 min |
| ibm03 | 5.88e6 | +39% | +18% | 18.3 min |
| ibm04 | 9.12e6 | +43% | +16% | 25.1 min |
| Average | — | +39.5% | +15.8% | — |

上表说明 ChipGPT 在 IBM-HB+ 上明显低于 tuned SA 和商业 auto-placer 的 HPWL；其 runtime 高于单次 SA，但主要来自 LLM API latency。

## 7. 创新点

1. 用通用 LLM 作为 floorplanning 的核心优化 agent，而不是只做脚本生成或指标预测。
2. 提出面向 floorplanning 的结构化文本编码，使复杂约束和布局状态可进入 prompt。
3. 用 scalar physical cost 和 action history 形成闭环，few-shot 示例显著加速收敛。

## 9. 与芯片流程的关系

### 9.1 在全流程中的位置

ChipGPT 接手 netlist 与约束，产出 macro floorplan；后续标准单元 placement、CTS、routing 都以这个 floorplan 为输入。它解决的是 floorplan 阶段“搜索空间大、约束多、人工成本高”的问题。

### 9.2 从“仿真通过”到“能做成芯片”之间还缺什么

论文的 cost 只覆盖 HPWL、area 和粗粒度 congestion，没有真实 timing、power、DRC/LVS 和 routability。要进入真实芯片实现，必须把 LLM 输出接入 RTL-to-GDSII 工具，用 signoff 质量反馈替换当前轻量 cost engine。

## 10. 讨论与局限

### 10.1 论文自述的局限

- runtime 和 token cost 高于单次编译工具。
- 当前 monolithic encoding 不适合数千宏和百万标准单元的 full-chip scale。
- 尚未接入完整 RTL-to-GDSII 流程。

### 10.2 代码/复现层面的问题

- 论文没有公开代码，Fast C++ evaluator、prompt 模板和 action parser 无法直接复现。
- commercial tool baseline 匿名，不能验证其配置和版本。

### 10.3 本资料包的批判性分析

IBM-HB+ 上 SA baseline 可能是公开学术算法，但 commercial tool 的默认设置未必代表工程最优。论文的优势主要来自 few-shot 示例引导，若更换 benchmark 或约束集，需要重新设计示例，不能把结论直接推广到所有 SoC。

## 12. 一分钟复述版

ChipGPT 不让 LLM 直接输出整张 floorplan，而是让它每一步输出一个明确的布局调整动作。系统先把 netlist、宏属性和约束写成文本，LLM 提动作，快速 cost engine 评价 HPWL、面积和拥堵，再把结果和最近动作反馈给 LLM。IBM-HB+ 实验显示，它的 HPWL 平均比 tuned SA 低 39.5%，比商业 auto-placer 低 15.8%。局限是慢、贵、还没接入 signoff flow。
