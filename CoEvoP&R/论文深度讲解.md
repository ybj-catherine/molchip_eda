## 1. 一句话定位

**CoEvoP&R 把搜索对象从“布局器参数、优化器组件或宏单元动作”改成“DREAMPlace 中完整可读、可微、可执行的解析布局目标函数”：LLM 在受限 ObjectiveSpec/typed policy 接口中提出带状态初始化、状态更新和标量 loss 的目标程序，通过 AST/语法/physical-role/autograd 校验后嵌入 DREAMPlace，再按 Tier A/B 在 placement 执行阶段获取布局与 placement-stage timing proxy 反馈、按 Tier C 获取真实 router 反馈，并用带岛屿迁移与失败记忆的 MAP-Elites archive 引导下一轮提案。在 8 个 ChiP-Bench Nangate45 设计与 3 个 seed 上，相对 native DREAMPlace 把 post-route routed wirelength 减少 16.9%、拥塞减少 36.7%，WNS 提升 0.70 ns、TNS 提升 912 ns；在 8 个 ICCAD 2015 Superblue 设计上减少 5.4% rWL、23.2% congestion，提升 8.2 ns WNS 与 26,163 ns TNS。**

这句话里的四个技术承重点：

1. **LLM 演化“目标函数形式”，而不是工具代码或参数** — 已有 AutoDMP/HyperPlace 搜参数，EvoPlace 在 HPWL 反馈下演化初始化、预处理和优化器更新组件，但保留布局目标；CoEvoP&R 把可微 loss 本身作为搜索空间，并把 wirelength/density/routing pressure/pin pressure 等可微项交给 LLM 组合。
2. **受限接口保证可嵌入、可执行、可读** — 论文称目标必须经受限接口和自动验证后嵌入 DREAMPlace，生成的表达式需满足 finite-value、autograd、bounded 等要求；代码仓库把它实现为 `coevop/objectives/typed_policy_v1`、`ObjectiveSpec` lowering 与 `patches/dreamplace` 集成补丁。
3. **cost-scaled 反馈层级** — Tier A 在 DREAMPlace placement 执行中为每个合法候选记录 HPWL、overflow、runtime、convergence 与 objective traces；Tier B 不进入真实 router，而是在 placement 阶段对 eligible 候选做 placement-stage timing proxy，记录 proxy WNS/TNS movement；Tier C 才把精选 finalist 交给真实 router，记录 routed wirelength、congestion、WNS、TNS，避免对所有生成目标都付昂贵布线成本。
4. **MAP-Elites + 失败记忆让演化可追踪** — 每个候选按行为 feature 归入 cell，Pareto evidence 决定保留哪个 elite；负记忆存 parse failure、gradient failure、HPWL/density regression 等失败原因；岛屿迁移在多样化 objective mechanism 间交换精英。

参照 [芯片流程.md](../芯片流程.md) 的 17 阶段标准编号。CoEvoP&R 直接改进标准单元解析布局目标，并用下游布线/时序结果作为演化反馈。

| 阶段 | 覆盖 | 说明 |
|------|:---:|------|
| ① RTL 设计 | ❌ | 输入是 ChiPBench/ICCAD 2015 等物理设计网表与 benchmark collateral，不生成或修改 RTL。 |
| ② RTL 功能仿真 | ❌ | 不跑 RTL testbench。 |
| ③ 逻辑综合 | ❌ | 不设计综合算法；但输入 benchmark 已是综合/物理实现可用的网表、单元库与 floorplan 配置。 |

| ⑥ 形式验证 | ❌ | 不证明等价性。 |
| ⑦ 布局规划（Floorplan） | ✅ **由 DREAMPlace 流程执行** | FloorPlan 阶段由 DREAMPlace 流程实现并作为后续 placement benchmark；CoEvoP&R 不把 floorplan 当作 LLM 演化对象，而是在 DREAMPlace 已建立的版图框架上做标准单元/混合尺寸布局。 |
| **⑧ 标准单元摆放（Placement）** | ✅ **核心** | 论文在 DREAMPlace 内嵌入目标候选，目标含 smooth wirelength、density、routing pressure、pin pressure，演化结果直接改变解析布局优化轨迹。 |
| ⑨ 时钟树综合（CTS） | ❌ | 不做 CTS。 |
| **⑩ 布线（Routing）** | ✅ **下游评测** | 论文不改进 router，而是用真实路由流程（OpenROAD/ChiPBench flow）评估 post-route rWL、congestion、WNS、TNS，再把这些反馈用于 objective evolution。 |
| ⑪ 后仿真 | ❌ | 未使用 SPEF/SDF 后仿真。 |
| ⑫ 物理验证（DRC + LVS） | ❌ | 不涉及 DRC/LVS。 |

| ⑭-⑰ 流片到芯片 | ❌ | 纯布局目标搜索与 post-route 评测研究，无 tape-out。 |

**覆盖率：4/17。** CoEvoP&R 核心落在 ⑧ Placement，借助 ⑤ STA/timing 和 ⑩ Routing 作为闭环评测；⑦ FloorPlan 由 DREAMPlace 流程执行并作为 placement benchmark，但不是 LLM 演化对象。索引和 README 中“4/17”采用该口径，不是声称真实制造流程覆盖 4 个阶段。

> ⚠️ CoEvoP&R 的目标是“让 DREAMPlace 产生的布局在 OpenROAD/OpenTimer 等下游评测中更好”，不是完成真实 GDSII signoff。论文中 rWL/Cong/WNS/TNS 的 gain 都是相对 native DREAMPlace 的同一后处理/布线/时序流程，不等于所有 AI placers 都自动通过签核。

## 3. 输入 / 输出

### 3.1 输入

CoEvoP&R 的输入分为三个层次：

**(a) 物理设计任务**。一个超图网表 $G=(V,E)$ 描述标准单元、宏单元和端口的连接，配合固定设计 benchmark：ChiPBench Nangate45（`bp_fe`、`bp_be`、`swerv_wrapper`、`or1200`、`mor1kx`、`ethernet`、`dft68`、`vga_lcd`）、ICCAD 2015 Superblue（`sb1/3/4/5/7/10/16/18`）或 ASAP7（`gcd/ibex/ariane`）。输入布局坐标集为 $x=\{(x_i,y_i)\}_{i\in V}$。

**(b) archive-conditioned prompt packet**：

$\Pi_g = (I,B,p_g,H_g,M_g,\sigma)$

- $I$：受限 objective interface，例如仓库中的 `typed_policy_v1`/`ObjectiveSpec`。
- $B$：baseline context，例如 DREAMPlace native objective、benchmark 与 target technology。
- $p_g$：当前 generation 的 parent objective，附带 lineage。
- $H_g$：local archive evidence，包括 neighboring elites、component trajectories、metric deltas、failure lessons。
- $M_g$：measured feedback，来自 Tier A/B/C 的真实布局与布线结果。
- $\sigma$：LLM 输出 schema。

**(c) 候选目标程序的结构约束**。图 2 给出的 illustrative restricted program 使用 `term(...)` 绑定可微物理项、返回标量 loss 和 named components：

```python
# 论文 Figure 2 中的 illustrative restricted program，不是最终选中的 objective
def objective(features):
    wl = term("wirelength_wawl")
    den = term("density_electric")
    route = term("soft_rudy_pnorm")
    score = wl + den + 0.01 * log1p(route)
    return score, {"wl": wl, "den": den, "route": route}
```

候选必须同时给出：

```text
Required fields:
  - parent_lineage
  - state_initialization   (I_theta)
  - state_update           (U_theta)
  - scalar_objective       (F_theta over placement terms)
  - named_components
  - role_bindings
```

### 3.2 中间产物

- `I_\theta`：根据 design-specific calibration 初始化 schedule variables。
- `U_\theta`：每个 placement iteration 更新 schedule variables。
- `F_\theta`：把 wirelength、density、routing pressure、pin pressure 等可微项组合成目标。
- schedule variables：$h_t^{\mathrm{den}}$、$h_t^{\mathrm{route}}$、$h_t^{\mathrm{pin}}$、$h_t^{\gamma}$ 等。
- progress observables：$a_t$ 中的 iteration fraction、density overflow、HPWL trend、smoothing position、per-term calibration constants。
- DREAMPlace runtime objective traces、component traces、DEF placement artifact。

### 3.3 输出

**最终目标不是只给一个 loss 数值**，而是返回带 lineage 的可读 objective，例如包含 named components 的程序、schedule variables、state variables 与 measured placement evidence。公开仓库的 README 同时展示了它可输出的运行记录和比较表：

```text
run directory:
  resolved_config / objective_program / prompt_and_response_records
  candidate_metrics / component_and_state_traces / placement_artifacts
  routed_metrics / failure_records

comparison_table.csv:
  design, objective_id, seed, def_path
  routed_wirelength_delta, congestion_delta, WNS_gain, TNS_gain
```

论文最终报告的数字以相对 native DREAMPlace 的 mean improvement 形式给出：rWL 和 Cong. 的 reduction（越高越好）、WNS/TNS gain（越高越好）。

## 4. 方法与架构

### 4.1 整体 Pipeline

```text
             CoEvoP&R 主循环（Figure 1 重绘）

   ┌──────────────────────────────────────────────────────────────┐
   │ 1. ARCHIVE-CONDITIONED PROPOSAL                              │
   │ Π_g = (I,B,p_g,H_g,M_g,sigma)                                │
   │ LLM proposer 采样 y_g,k ~ q(lambda | Π_g)                    │
   └──────────────────────────────┬───────────────────────────────┘
                                  ▼
   ┌──────────────────────────────────────────────────────────────┐
   │ 2. CANDIDATE VALIDATION, EMBEDDING, EVALUATION               │
   │ ObjectiveSpec / AST + grammar lowering                       │
   │ finite-value + autograd gate → Embed_d(y) = c or reject      │
   │ Tier A: DREAMPlace placement                                 │
   │ Tier B: placement-stage timing proxy                         │
   │ Tier C: real router + post-route rWL/Cong/WNS/TNS            │
   └──────────────────────────────┬───────────────────────────────┘
                                  ▼
   ┌──────────────────────────────────────────────────────────────┐
   │ 3. ARCHIVE AND CLOSED-LOOP FEEDBACK                          │
   │ z = psi(c): MAP-Elites cell                                  │
   │ Pareto evidence update / elite retention / migration         │
   │ negative memory for failure reasons + repair notes           │
   └──────────────────────────────┬───────────────────────────────┘
                                  ▼
                    return Best(A_G): readable objective
```

### 4.2 核心模块逐个详解

#### 模块 1：Archive-Conditioned Objective Proposal

这个模块要解决“下一轮该试什么 objective”的问题。单靠 baseline 会让 LLM 反复生成类似组合；只给最终 score 又缺少失败原因。CoEvoP&R 将 parent objective、neighboring elites、component trajectories、metric deltas、failure lessons 和 measured feedback 全部放进 prompt。

每个 LLM response 必须给出一个完整候选：初始化函数、状态更新函数、标量 loss、named components 和 role bindings。这样候选不是一次性静态公式，而是可随 placement iteration 调整的状态机式 objective。

#### 模块 2：Candidate Validation and DREAMPlace Embedding

模块 2 负责把自然语言/代码形式的建议转成可执行程序。论文称通过 restricted objective interface 和语法/物理角色/可微性/runtime 检查做验证；代码仓库展示为 `ObjectiveSpec` lowering 和 `patches/dreamplace`。只有合法候选才进入 DREAMPlace。

DREAMPlace 内嵌目标形式包含 smooth wirelength、density、routing pressure、pin pressure 四类项，并由 schedule variables 控制相对权重和 smoothing scale。Density state 还更新 placer preconditioner，因此目标改变不仅影响 scalar loss，也改变优化轨迹。

#### 模块 3：Cost-Scaled Evaluation and Evidence Ranking

模块 3 解决“真实布线太贵，不能每个候选都跑”的问题。Tier A 对每个合法候选执行 DREAMPlace 解析布局并记录 HPWL、overflow、runtime、convergence 和 objective traces；Tier B 不进入真实 router，而是在 placement 阶段对 eligible candidates 做 placement-stage timing proxy，记录 WNS/TNS movement；Tier C 对 selected finalists 记录真实 post-route metrics。

论文用 Pareto evidence 排序，而不是单一 score。无效候选、nonfinite trace、robustness failure 在 ranking 前剔除；同 nondominated front 用 design coverage 和 runtime 排序。timing proxy 还需要 admission audit，防止代理指标与 HPWL/overflow 高度冗余。

#### 模块 4：Archive Update and Closed-Loop Feedback

模块 4 用 MAP-Elites 保存行为多样性。每个 admitted objective 被映射到 cell $z=\psi(c)$，feature 包含复杂度、mechanism family、HPWL behavior、overflow behavior、timing behavior。岛屿模型周期交换 elites，负记忆保存失败机制，供后续 prompt 规避。

### 4.3 模块职责矩阵

| 模块 | 输入 | 输出 | 用到的模型/工具 | 是否需训练 |
|---|---|---|---|---|
| Archive-conditioned proposal | prompt packet $\Pi_g$ | candidate objective $y_{g,k}$ | GPT/Claude/Qwen 系 LLM | 否 |
| ObjectiveSpec validation/embedding | 原始目标程序 | validated candidate $c$ 或 rejected | AST/grammar、finite-value + autograd gate | 否 |
| Tier A placement | candidate + design | HPWL、overflow、runtime、traces | DREAMPlace | 否 |
| Tier B timing proxy | selected candidate | proxy WNS/TNS movement | DREAMPlace 产出的 placement + OpenTimer/placement-stage timing interface | 否 |
| Tier C routing | selected finalist | rWL、Cong、post-route WNS/TNS | OpenROAD/ChiPBench flow | 否 |
| MAP-Elites archive | candidates + evidence | elite cells, lineage, failure memory | Pareto sorting + island migration | 否 |

CoEvoP&R 的主要搜索成本在 Tier A/Tier C 和 LLM API，而不是模型训练。

## 5. 关键公式

这一节只收录论文编号公式和必要的形式化说明。若某个量是论文用于解释流程但未编号的，我会明确说明。

### 5.1 DREAMPlace Native Objective

DREAMPlace 在 placement step $t$ 的原生目标：

$$
\mathcal{L}_{\mathrm{DP},t}(x)=\widetilde{W}_{\gamma_t}(x)+\lambda_t D(x)
$$

- $\mathcal{L}_{\mathrm{DP},t}(x)$：DREAMPlace 在第 $t$ 步的原生可微目标。
- $x$：当前布局坐标集。
- $\widetilde{W}_{\gamma_t}(x)$：wirelength smoothing 参数为 $\gamma_t$ 的可微线长近似。
- $D(x)$：静电密度惩罚。
- $\lambda_t$：控制线长与密度扩展之间的平衡。

### 5.2 HPWL

$$
\mathrm{HPWL}(x)=\sum_{e\in E}\left(\max_{i\in e}x_i-\min_{i\in e}x_i+\max_{i\in e}y_i-\min_{i\in e}y_i\right)
$$

- $\mathrm{HPWL}(x)$：半周长线长。
- $E$：所有 net 组成的 hyperedge 集合。
- $i\in e$：net $e$ 中的 pin/cell/port。
- $x_i,y_i$：对象 $i$ 的坐标。

HPWL 是布局阶段常用代理，但它没有 pin access、层分配、buffering 和真实时序路径信息。

### 5.3 Scalar and Bin-Map Observables

$$
\phi(x)\in\mathbb{R},\qquad \Phi(x)=\{\Phi_b(x)\}_{b\in\mathcal{B}}
$$

- $\phi(x)$：标量可微 observable，如 smooth wirelength、density penalty。
- $\Phi(x)$：bin-map observable，如 density map、RUDY-like routing map、pin-density map、long-net pressure map。
- $\mathcal{B}$：布局区域划分后的 bin 集合。
- $b$：一个 bin 的索引。

### 5.4 Smooth Reduction of a Nonnegative Map

$$
\rho_p(M)=\left(\frac{1}{|\mathcal{B}|}\sum_{b\in\mathcal{B}}(M_b+\epsilon)^p\right)^{1/p}
$$

- $\rho_p(M)$：把非负 map $M$ 归约为标量的 smooth reduction。
- $M_b$：bin $b$ 上的 map 值。
- $\epsilon$：防止表达式病态的正数，通常 $\epsilon>0$。
- $p$：控制 hotspot 敏感度的指数，通常 $p>1$。

### 5.5 General Differentiable Placement Objective

$$
\mathcal{L}(x)=F\left(\phi_1(x),\ldots,\phi_m(x),\rho_{p_1}(\Phi_1),\ldots,\rho_{p_n}(\Phi_n)\right)
$$

- $\mathcal{L}(x)$：包含多个标量 observable 和多个 map reduction 的通用可微布局目标。
- $F$：可微组合函数。
- $\phi_1,\ldots,\phi_m$：$m$ 个标量 observable。
- $\Phi_1,\ldots,\Phi_n$：$n$ 个 bin-map observable。

### 5.6 Trajectory-Aware Candidate Objective

$$
h_0=I_\theta(a_0),\qquad h_{t+1}=U_\theta(h_t,a_t),\qquad \mathcal{L}_{\theta,t}(x_t,d)=F_\theta(\mathcal{T}(x_t,d),h_t)
$$

- $h_0$：初始 schedule variables。
- $I_\theta$：由 design-specific calibration 设置初始状态。
- $U_\theta$：每步更新 schedule variables。
- $a_t$：当前 progress observables，如 density overflow、HPWL trend、smoothing position。
- $\mathcal{L}_{\theta,t}(x_t,d)$：候选 $\theta$ 在第 $t$ 步的目标。
- $\mathcal{T}(x_t,d)$：当前布局和设计 $d$ 下的可微 placement terms。
- $F_\theta$：候选目标的 scalar loss map。

### 5.7 Runtime Objective Embedded in DREAMPlace

$$
\mathcal{L}_{\theta,t}=\widetilde{W}_{\gamma_t}(x_t)+h_t^{\mathrm{den}}D(x_t)+h_t^{\mathrm{route}}R(x_t)+h_t^{\mathrm{pin}}P(x_t),\qquad \gamma_t=h_t^{\gamma}\gamma_t^{\mathrm{base}}
$$

- $\widetilde{W}_{\gamma_t}(x_t)$：当前 smoothing scale 下的 smooth wirelength。
- $D(x_t)$：density penalty。
- $R(x_t)$：可微 routing pressure term，例如 soft RUDY p-norm。
- $P(x_t)$：pin pressure term。
- $h_t^{\mathrm{den}}$、$h_t^{\mathrm{route}}$、$h_t^{\mathrm{pin}}$：density、routing、pin 项的 schedule coefficients。
- $h_t^{\gamma}$：smoothing scale 的 schedule coefficient。
- $\gamma_t^{\mathrm{base}}$：baseline smoothing scale。

### 5.8 Candidate Embedding

$$
\mathrm{Embed}_d(y)=
\begin{cases}
c, & y\in\mathcal{Y}_d,\\
\bot, & y\notin\mathcal{Y}_d.
\end{cases}
$$

- $\mathrm{Embed}_d(y)$：设计 $d$ 下的候选嵌入函数。
- $y$：LLM 提出的 symbolic objective program。
- $\mathcal{Y}_d$：通过 grammar、physical-role、differentiability、runtime 检查后可在设计 $d$ 中执行的程序集合。
- $c$：可执行候选。
- $\bot$：无效候选，不进入 DREAMPlace。

### 5.9 Pareto Evidence Order

论文用多目标改进证据判断候选好坏。对候选 $c$：

$$
v(c)=\left(\Delta\mathrm{HPWL}(c),\Delta\mathrm{ovf}(c),-\Delta\mathrm{WNS}(c),-\Delta\mathrm{TNS}(c)\right)
$$

$$
c_i\prec c_j \iff v_k(c_i)\leq v_k(c_j)\ \forall k\in K_{ij}
\quad\text{and}\quad v_k(c_i)<v_k(c_j)\ \exists k\in K_{ij}
$$

- $v(c)$：候选的 evidence vector，统一为 lower-is-better。
- $\Delta\mathrm{HPWL}(c)$：HPWL change。
- $\Delta\mathrm{ovf}(c)$：routing overflow change。
- $\Delta\mathrm{WNS}(c)$、$\Delta\mathrm{TNS}(c)$：WNS/TNS change；取负号使 timing 提升与 lower-is-better 对齐。
- $c_i\prec c_j$：$c_i$ Pareto 支配 $c_j$。
- $K_{ij}$：两个候选都测到的坐标集合。

archive 更新保留同一 feature cell 中 Pareto evidence 最优的 elite。论文未编号的证据向量和 archive update 也沿用此语义。

## 6. 训练与实验设置

### 6.1 是否需要训练

不需要训练或微调 LLM。CoEvoP&R 使用 inference-time LLM 采样、候选校验、DREAMPlace/OpenROAD/OpenTimer 评测和 archive 更新。论文默认 proposer 是 `gpt-5.4`，并在敏感性实验中测试 `gpt-4.1-mini`、`claude-opus-4-8`、`qwen3.7-max`。

### 6.2 实验设置

- **ChiPBench Nangate45**：`bp_fe`、`bp_be`、`swerv_wrapper`、`or1200`、`mor1kx`、`ethernet`、`dft68`、`vga_lcd`。
- **ICCAD 2015 Superblue**：`sb1`、`sb3`、`sb4`、`sb5`、`sb7`、`sb10`、`sb16`、`sb18`。
- **ASAP7**：`gcd`、`ibex`、`ariane`。
- **评测口径**：所有 Table 1/Table 2 数字是相对 native DREAMPlace 的 3-seed mean improvement；DREAMPlace 归一化为 0。
- **Baselines**：DREAMPlace、DREAMPlace 4.0、expert HPWL/density/RUDY/pin-density mixes、same-grammar BO-DSL with TPE、shared-pipeline reruns of AutoDMP、RoutePlacer、EvoPlace、LaMPlace。
- **变体**：
  - `CoEvoP&R-E`：用目标设计自身反馈演化。
  - `CoEvoP&R-L`：leave-one-design-out（LODO），目标设计被排除在演化与 prompt evidence 之外。
  - `CoEvoP&R-T`：把 ChiPBench 演化出的 best candidate 零样本迁移到跨设计/跨工艺评测。
- **硬件**：1 个 NVIDIA RTX A6000 48 GB GPU + 1 个 Intel Xeon Gold 5218R CPU，16 个 OpenROAD/OpenTimer worker processes。

### 6.3 关键实验结果

### 6.4 Timing Proxy Admission Audit

论文 Figure 4 在 100 到 2000 DBU perturbations 下审计 placement-stage timing proxy 与下游 WNS/TNS movement 的冗余度。结论是 WNS 与 HPWL movement 的 Pearson/Spearman 冗余较低，因此在 4 个 stress design 中 3 个被 Admit，成为主要 timing proxy；TNS 与 HPWL 更冗余，主要用作 tie-breaker。Ungated timing proxy 会比完整 admission 机制退化，说明不能无条件信任 placement-stage timing signal。

## 7. 创新点

### 创新点 1：LLM Objective Evolution

论文声称这是第一个“自动用 LLM 演化 analytical placement objective function，并把它与真实 placement/routing tools 集成”的框架。和 AutoDMP/HyperPlace 调参不同，它演化的是目标函数本身；和 EvoPlace 演化 optimizer components 不同，它保留 optimizer 但改变 objective。

### 创新点 2：Automated Validation

目标不是自然语言建议，而是受限 ObjectiveSpec/typed interface 下的可执行程序。候选必须在语法、physical role、differentiability、runtime 上通过检查，并被嵌入 DREAMPlace，解决 LLM 输出“听起来合理但不能跑”的问题。

### 创新点 3：Routing-Aware Feedback

反馈不只包含 HPWL/density 等 placement-stage proxy，还包含 timing proxy movement 和真实 router 后的 rWL/Cong/WNS/TNS。反馈层级还做了成本控制：不是所有候选都跑昂贵下游流程。

### 创新点 4：Archive-Guided Iteration

archive 保存每个候选的 objective、placement/routing/timing/failure feedback；MAP-Elites、island migration 和 negative memory 让后续 prompt 能避开失败机制并维持行为多样性。最终输出是 readable objective，不是黑盒 surrogate。

## 9. 与芯片流程的关系

### 9.1 在全流程中的位置

CoEvoP&R 放在 **Placement（⑧）** 和其下游 **Routing（⑩）/Timing（⑤）** 反馈之间。它接手综合/物理实现前的 benchmark netlist，通过 DREAMPlace 产出 placement，再用 OpenROAD 路由和 OpenTimer 时序结果决定哪些演化 objective 值得保留。

它解决的核心痛点是：HPWL/density 等 placement-stage metrics 和真实 routed/timing quality 不完全一致。论文不是训练另一个黑盒 PPA predictor，而是让目标形式本身随下游反馈演化。

### 9.2 “routed metric 改善”和“能做成芯片”之间隔着什么

论文实验使用 OpenROAD/ChiPBench/OpenTimer 等开源或公开物理设计流程，得到的 WNS/TNS 仍不是完整 signoff。真实芯片还需要 multi-corner/multi-mode timing、power、IR drop、DRC/LVS、制造规则、封装和测试约束；论文结论也明确把 multi-corner timing、power 和 signoff-accurate routing feedback 列为下一步。

此外，目标在 Nangate45/Superblue/ASAP7 上验证，不代表对任意技术节点、任意 lib 版本和任意 floorplan 都有效。CoEvoP&R 的 search 是 inference-time 演化，结果与设计、seed、prompt、LLM 版本和下游工具版本耦合。

## 10. 讨论与局限

### 10.1 论文自述的局限

论文正文没有单列 limitation 小节，但结论说明自然扩展是多 corner timing、power 和 signoff-accurate routing feedback。这说明当前评估流程仍然是简化的物理实现反馈，不是完整 signoff。

### 10.2 代码/复现层面的问题

- 公开仓库显示核心组件存在：`coevop/objectives`、`coevop/evolution`、`coevop/eval/openevolve_tier2.py`、`patches/dreamplace`、多组 config。
- 完整复现需要自行准备并安装外部依赖：DREAMPlace、ChiPBench、OpenROAD、OpenROAD-flow-scripts、ASAP7/OpenTimer collateral；仓库声明不重新分发 benchmark data 和工具。
- DREAMPlace 不是直接 pip 安装后即可用，README 要求先应用 `patches/dreamplace` source patch，再重新编译/安装，才能支持 trajectory-aware objective runtime、OpenTimer 接口和 mixed-size placement。
- 论文默认使用 `gpt-5.4`，所以完整 objective evolution 还需要对应 LLM API/模型访问；模型版本漂移可能影响复现数值。
- 本资料包归档了 arXiv PDF 和提取文本，已通过公开 GitHub 页面核验仓库入口，但未在本地执行完整流程。

### 10.3 本资料包的批判性分析

CoEvoP&R 的核心贡献是把“objective 搜索空间”向 LLM 打开，同时用 DSL、validation 和 cost-scaled feedback 把它约束住。需要谨慎看待三点：

1. **评测成本与 seed 统计**。3 seeds 能说明稳定性趋势，但演化搜索本身有随机性；完整实验还依赖 LLM provider、DREAMPlace 版本和 router 版本。
2. **迁移不是免费的**。CoEvoP&R-T 保留 46% 到 80% 的 Superblue gain，LODO 也比 target evolution 低；说明搜索结果存在设计/技术相关成分。论文承认 Superblue1 是 transfer-limit case。
3. **timing proxy 的可信度需要 audit**。论文专门做了 admission audit，说明 WNS/TNS 与 HPWL movement 的冗余度不同；若未来换更复杂 timing model，仍需重复这种 audit，不能直接把旧 proxy authority 复制到新工艺。

## 12. 一分钟复述版

1. 问题：解析布局器优化 HPWL/density 等 proxy，但这些 proxy 和真实布线、时序质量不一致。
2. 已有方法：人写 routability/timing term，或训练黑盒 surrogate；前者要专家重调，后者难解释难嵌入。
3. CoEvoP&R 改搜完整 objective：让 LLM 提出可读、可微、带状态更新和 named components 的目标程序。
4. 受限接口：候选要过 AST/grammar、physical role、finite-value、autograd 检查，合法后才嵌入 DREAMPlace。
5. 闭环反馈：Tier A 跑 DREAMPlace placement，Tier B 在 placement 阶段做 placement-stage timing proxy，Tier C 才让精选候选跑真实 router。
6. Archive：MAP-Elites 按行为保留精英，岛屿迁移维持多样性，负记忆记录失败原因。
7. 实验结果：ChiPBench Nangate45 上比 native DREAMPlace 改善 16.9% rWL、36.7% congestion、0.70 ns WNS、912 ns TNS。
8. 跨设计：LODO 保留大部分收益；Superblue 上 E 改善 5.4% rWL、23.2% congestion、8.2 ns WNS、26,163 ns TNS。
9. 消融：random/one-shot/score-only、Tier-A-only、direct Tier C、无 component traces 的 archive 都明显退化。
10. 边界：这是 placement objective search + routed feedback，不是完整 signoff；下一步应扩展到 multi-corner timing、power 和 signoff-accurate routing。
