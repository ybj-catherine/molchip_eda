# CHIP-MAP 论文深度讲解

> **CHIP-MAP: A Collaborative Optimization Framework for Macro Placement Using Large Language Models**
> Yiming Du, RenYe Yan, Yunfan Yang, Frank Qu, Jiajun Tan, ZhiYu Zheng, Yiming Gan, Ling Liang, Zongwei Wang, YiMao Cai
> DATE 2026
> 原文：[CHIP-MAP_ A Collaborative Optimization Framewo.pdf](./CHIP-MAP_ A Collaborative Optimization Framewo.pdf) · [CHIP-MAP_DATE2026.txt](./CHIP-MAP_DATE2026.txt)

## 1. 一句话定位

**CHIP-MAP 用四个 LLM agent 把宏布局拆成信息提取、宏分组、初始布局、验证反馈的闭环，并用 MWA 与 SCUS 两个量化工具指导精化；在 5 个 130nm/45nm 工业级 benchmark 上最高降低 1.5% 面积，平均修复 61.6% TNS。**

这句话里的三个承重点：

1. **多 Agent 协作** — Analysis Agent、Group Agent、Floorplan Agent、Verification Agent 顺序协作，输出统一为 JSON。
2. **双工具反馈** — MWA 量化模块间连接权重，SCUS 量化标准单元连续可用区域质量。
3. **闭环迭代** — Verification Agent 最多反馈 3 轮，直到 SCUS 最优且 DRC 满足。

## 3. 输入 / 输出

### 3.1 输入

- EDA 文件：LEF、LIB、SDC 和 Verilog netlist。
- 设计约束：core/die 面积、macro halo、orientation、clock domain、IO 位置。
- LLM backbone：GPT-4o 主实验，DeepSeek-R1 对比。

```text
core_area = [1150.0, 1150.0]
die_area = [1200.0, 1200.0]
macro_m1 = {size:[128.5,64.2], orientation:["R0","R180","MY"]}
constraint = {macro_m1 near macro_m2, macro_halo=10}
```

### 3.2 中间产物

- Analysis Agent 输出结构化 JSON。
- Group Agent 输出功能分组和时序分组策略。
- Floorplan Agent 输出宏坐标。
- Verification Agent 输出 SCUS score、问题和建议。

```text
group_agent_output = {
  "classification": {"Macro1":"Storage","Macro2":"Compute"},
  "strategies": {"functional": {...}, "timing": {...}},
  "selection": {"strategy":"functional","final_groups":[{"id":"group1","macros":["Macro2","Macro3"]}]}
}
```

### 3.3 输出

```text
macro_placement = {
  "m1": {"orientation":"MY","x":100,"y":200},
  "m2": {"orientation":"R0","x":52,"y":64}
}
```

最终还有 post-route PPA：TNS、WNS、power、wirelength、area、congestion、DRC、NVP 和 runtime。

## 4. 方法与架构

### 4.1 整体 Pipeline

```text
LEF + LIB + SDC + Verilog
          │
          ▼
Analysis Agent: structured data extraction
          │
          ▼
Group Agent: semantic macro grouping
          │
          ▼
Floorplan Agent: MWA-guided initial layout
          │
          ▼
Verification Agent: SCUS + DRC feedback
          │
          └── up to 3 rounds ──┘
          │
          ▼
Final macro placement
```

### 4.2 核心模块逐个详解

- **Analysis Agent**：脚本解析 Verilog 模块层级、实例关系和端口连接，输出 Spec List，避免直接把大 netlist 塞进 LLM。
- **Group Agent**：用 CoT 生成功能分组和时序分组，选择面积利用率更好的方案。
- **Floorplan Agent**：随机初始化后，用 MWA 权重决定组内和组间邻近关系，同时检查 overlap、halo 和 IO。
- **Verification Agent**：用 SCUS 评价标准单元连续区域，检测 notch、碎片和 misalignment，反馈给 Floorplan Agent。

### 4.3 模块职责矩阵

| 模块 | 输入 | 输出 | 工具/模型 | 是否需训练 |
|---|---|---|---|---|
| Analysis Agent | LEF/LIB/SDC/Verilog | structured data | Python parser + GPT-4o | 否 |
| Group Agent | structured data | groups JSON | GPT-4o | 否 |
| Floorplan Agent | groups + MWA | macro coordinates | GPT-4o + MWA | 否 |
| Verification Agent | coordinates + SCUS | score, suggestions | GPT-4o + SCUS | 否 |

## 5. 关键公式

### 5.1 MWA

$$
W(A,B)=\sum_{p \in P(A,B)} \sum_{i=1}^{|p|} \frac{\mathrm{bitwidth}(s_i)}{2^i}
$$

- $W(A,B)$：模块 A 到 B 的连接权重
- $P(A,B)$：从 A 到 B 的所有信号路径
- $|p|$：路径 p 的寄存器 hop 数
- $s_i$：路径中第 i 个信号段
- $\mathrm{bitwidth}(s_i)$：信号段位宽

**工程直觉**：距离越远、hop 越多、位宽越大的路径应该得到越强的邻近惩罚，因此用指数衰减表达时序和线长代价。

### 5.2 SCUS

$$
C_{\text{final}}=\alpha\cdot \max_{R \in \mathcal{R}} |R|+\beta\cdot\left(1-\frac{A_{\text{notch}}}{A_{\text{total}}}\right)
$$

- $C_{\text{final}}$：最终布局质量分
- $R$：标准单元连续区域
- $A_{\text{notch}}$：不可用 notch 面积
- $A_{\text{total}}$：芯片总面积
- $\alpha,\beta$：连续性与紧凑性权重

## 6. 训练与实验设置

### 6.1 是否需要训练

不训练。所有 agent 温度设为 0，使用 GPT-4o API；DeepSeek-R1 只做 backbone 对比。

### 6.2 实验设置

- 5 个 benchmark：BlackParrot、Ariane136、Swerv wrapper、Chameleon、Microwatt。
- baseline：OpenROAD、SA、DREAMPlace、ChiPFormer。
- 所有方法统一经过 OpenROAD RePlace、TritonCTS、TritonRoute。
- 10 次独立运行，每次最多 3 轮反馈。

### 6.3 关键实验结果

| Design | Method | TNS (ps) | WNS (ps) | WL (µm) | Area (µm²) |
|---|---|---:|---:|---:|---:|
| BlackParrot | CHIP-MAP GPT-4o | -60.25 | -1.56 | 8,145,856 | 810,234 |
| BlackParrot | OpenROAD | -71.88 | -1.96 | 8,209,505 | 810,360 |
| Ariane136 | CHIP-MAP GPT-4o | -3,053.54 | -1.28 | 6,782,462 | 783,253 |
| Ariane136 | OpenROAD | -3,204.87 | -1.32 | 7,176,803 | 792,446 |
| Swerv wrapper | CHIP-MAP GPT-4o | -515.07 | -0.63 | 4,008,348 | 673,169 |
| Swerv wrapper | OpenROAD | -751.62 | -0.98 | 4,015,115 | 675,207 |

表格说明 CHIP-MAP 在多数大型设计上同时改善 TNS、WNS、wirelength 和面积；在小型设计上 runtime 可能略高于 OpenROAD，但仍可接受。

## 7. 创新点

1. 用四个专门 agent 的 prompt-structured 闭环替代单一 LLM 一次性生成布局。
2. 提出 MWA，把路径 hop 和信号位宽编码为模块邻近权重。
3. 提出 SCUS，把标准单元连续区域和 notch 面积变成可反馈的布局质量指标。

## 9. 与芯片流程的关系

### 9.1 在全流程中的位置

CHIP-MAP 接受物理设计输入，输出宏坐标；这些坐标可直接替代 Hier-RTLMP 的宏布局结果，随后进入标准单元 placement、CTS 和 routing。

### 9.2 从“P&R 指标提升”到“能做成芯片”之间还缺什么

论文没有覆盖完整签核所需的功耗、噪声、IR drop、多 corner 时序和 LVS 修复；但 DRC/NVP 结果显示它已经在减少布局引入的结构违例。

## 10. 讨论与局限

### 10.1 论文自述的局限

小型 benchmark 上 CHIP-MAP 可能比 OpenROAD 慢；LLM API 调用带来额外 latency 和 token cost。

### 10.2 代码/复现层面的问题

论文没有提供公开代码链接，prompt 细节虽给出片段，但完整 Layout Experience Manual 和 parser 未公开。

### 10.3 本资料包的批判性分析

CHIP-MAP 的优势很大程度依赖 OpenROAD 后处理的一致性，不能独立证明宏布局算法在所有工艺和工具链上都更优。消融实验显示去掉 Group Agent、MWA 或 SCUS 后性能明显下降，说明闭环组件确实有贡献。

## 12. 一分钟复述版

直接让 LLM 生成宏布局会遇到约束误解、面积碎片化和无反馈三大问题。CHIP-MAP 把问题拆给四个 agent：Analysis 提取结构化数据，Group 做功能/时序分组，Floorplan 用 MWA 权重生成布局，Verification 用 SCUS 和 DRC 检查反馈。最多三轮迭代后，大型 benchmark 的 TNS、wirelength 和面积都比 OpenROAD 等 baseline 更好。
