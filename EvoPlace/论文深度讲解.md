# EvoPlace 论文深度讲解

> **EvoPlace: Evolution of Optimization Algorithms for Global Placement via Large Language Models**
> Xufeng Yao, Jiaxi Jiang, Yuxuan Zhao, Peiyu Liao, Yibo Lin, Bei Yu
> IEEE TCAD 2026 · arXiv:2504.17801
> 原文：[2504.17801_EvoPlace.pdf](./2504.17801_EvoPlace.pdf) · [2504.17801_EvoPlace.txt](./2504.17801_EvoPlace.txt)
> 代码：https://github.com/yaoxufeng/EvoPlace

## 1. 一句话定位

**EvoPlace 让 LLM 自动生成 global placement 优化算法的初始化、预条件处理和线搜索组件，并用 LLM-based genetic flow 演化这些代码；在 MMS、ISPD2005、ISPD2019 上平均 HPWL 分别改善 5.05%、5.29%、8.30%。**

这句话里的三个承重点：

1. **搜索算法本身** — 不是调 hyperparameter，而是生成可执行算法组件。
2. **LLM 遗传流** — 使用选择、交叉、变异，但基因是代码和运行反馈。
3. **跨 benchmark 泛化** — 发现的算法在多个 benchmark 上有效，并与参数调优方法互补。

## 3. 输入 / 输出

### 3.1 输入

- MMS、ISPD2005、ISPD2019 benchmark 网表。
- 目标指标 HPWL。
- 初始算法模板、LLM prompt、遗传参数。

```text
evoplace_input = {
  benchmarks: ["mms","adaptec1","superblue1"],
  objective: "HPWL",

```

### 3.2 中间产物

- 候选算法代码。
- 语法/接口校验结果。
- 每个候选在 benchmark 上的 HPWL。

```text

```

## 4. 方法与架构

### 4.1 整体 Pipeline

```text
LLM generates candidate optimization algorithms
          │
          ▼
Syntax / interface validation
          │
          ▼
Run candidate on placement benchmark
          │
          ▼
HPWL feedback
          │
          ▼
LLM-based genetic flow: select / crossover / mutate
          │
          ▼
Return best discovered algorithm
```

### 4.2 核心模块逐个详解

- **算法生成**：LLM 输出初始化、预条件处理和 line search 代码。
- **验证与嵌入**：检查接口和可执行性后放入 placer。
- **评估**：运行 placement，返回 HPWL。
- **遗传搜索**：用 HPWL 作 fitness，让 LLM 进行代码级 crossover 和 mutation。

### 4.3 模块职责矩阵

| 模块 | 输入 | 输出 | 工具/模型 | 是否需训练 |
|---|---|---|---|---|
| Algorithm proposal | templates + feedback | code candidates | LLM | 否 |
| Validation | code | accepted/rejected | Python/interface check | 否 |
| Placement evaluation | algorithm + benchmark | HPWL | analytical placer | 否 |
| Genetic flow | population + HPWL | next population | LLM operators | 否 |

## 5. 关键公式

### 5.1 Global placement 目标

$$
\mathcal{L}(x)=\lambda_1 WL(x)+\lambda_2 D(x)
$$

- $\mathcal{L}(x)$：placement 目标
- $WL(x)$：wirelength term
- $D(x)$：density penalty
- $\lambda_1,\lambda_2$：权重

### 5.2 HPWL

$$
HPWL(P)=\sum_{e\in E}\left(\max_{i\in e}x_i-\min_{i\in e}x_i+\max_{i\in e}y_i-\min_{i\in e}y_i\right)
$$

- $P$：placement
- $E$：net 集合
- $x_i,y_i$：pin 坐标

### 5.3 Fitness

$$
fitness(a)=-\Delta HPWL(a)
$$

- $a$：候选算法
- $\Delta HPWL(a)$：该算法相对 baseline 的 HPWL 变化

## 6. 训练与实验设置

### 6.1 是否需要训练

不训练。使用 LLM-based genetic flow 搜索算法代码。每个候选算法都是推理时生成的可执行组件，LLM 不更新参数；搜索成本来自多次 placement run。

### 6.2 实验设置

- benchmark：MMS、ISPD2005、ISPD2019。
- baseline：DREAMPlace 等 analytical placement 方法与参数调优方法。
- 指标：平均 HPWL improvement、单例 improvement、泛化性。

### 6.3 关键实验结果

| Benchmark | 平均 HPWL improvement |
|---|---:|
| MMS | 5.05% |
| ISPD2005 | 5.29% |
| ISPD2019 | 8.30% |

发现的算法在不同 benchmark 上泛化，并与已有 parameter-tuning 方法互补。

## 7. 创新点

1. 把 global placement 的优化算法组件作为 LLM 演化对象。
2. 提出 LLM-based genetic flow，利用代码语义和运行反馈产生新算法。
3. 发现算法跨 benchmark 泛化，且可与参数调优结合。

## 9. 与芯片流程的关系

### 9.1 在全流程中的位置

EvoPlace 位于 global placement 阶段，替换 placer 中的人工启发式组件，不影响 netlist、floorplan、detailed placement 和 routing。

### 9.2 从“HPWL 改善”到“能做成芯片”之间还缺什么

需要进一步验证 detailed placement、CTS、routing、timing、DRC/LVS 和 signoff；论文未报告这些指标。

## 10. 讨论与局限

### 10.1 论文自述的局限

搜索成本来自多次 placement run；LLM 生成的算法需要接口验证。若接口检查不足，生成代码可能无法嵌入 placer，或产生不稳定目标函数。

### 10.2 代码/复现层面的问题

代码公开，但依赖 LLM API 和具体 placer 环境。复现时需要固定模型版本、benchmark 配置和实验预算，否则算法种群和收敛曲线可能不同。

### 10.3 本资料包的批判性分析

HPWL 改善不等同于 PPA 改善；LLM 生成代码的可解释性和稳定性仍需人工审计。

## 12. 一分钟复述版

global placement 的质量受初始化、预条件处理和 line search 等人工组件影响很大。EvoPlace 让 LLM 生成这些组件代码，在公开 benchmark 上跑 HPWL，再用 LLM 驱动的遗传流选择、交叉、变异。最终得到的是可执行算法，而不是一组参数，因此可以跨 benchmark 泛化。
