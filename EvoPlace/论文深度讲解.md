## 1. 一句话定位

**EvoPlace 让 LLM 自动生成并演化 global placement 优化算法，重点搜索初始化、预处理和线搜索组件；在 MMS、ISPD2005、ISPD2019 上平均 HPWL 分别改善 5.05%、5.29%、8.30%，单例最高约 17%。**

## 3. 输入 / 输出

### 3.1 输入

- 网表与 benchmark：MMS、ISPD2005、ISPD2019。
- 目标指标：HPWL。
- 初始算法代码模板与 LLM 生成 prompt。
- 遗传演化所需的种群、交叉、变异规则。

```text
evoplace_input = {
  benchmarks: ["mms", "adaptec1", "superblue1"],
  objective: "HPWL",
  population_size: 20,
  generations: 10,
  backend: "GPT-4"
}
```

### 3.2 输出

- 可执行的 global placement 优化算法，包括初始化策略、预处理器和线搜索逻辑。
- 各 benchmark 的 HPWL。
- 泛化性和与参数调优方法的互补性分析。

```text
evoplace_output = {
  mms_hpwl_improvement: "5.05%",
  ispd2005_hpwl_improvement: "5.29%",
  ispd2019_hpwl_improvement: "8.30%",
  max_individual_improvement: "up to 17%"
}
```

## 4. 方法 / 架构 / 构建

```text
LLM generates candidate optimization algorithms
          |
Syntax / interface validation
          |
Run candidate on placement benchmark
          |
HPWL feedback
          |
LLM-based genetic flow: select / crossover / mutate
          |
Return best discovered algorithm
```

EvoPlace 不是调 baseline 的 hyperparameter，而是把 initialization、preconditioning 和 line search 等代码块作为基因。LLM 根据已运行算法的 HPWL 和代码结构提出新的候选，再通过遗传算子保持多样性和性能选择。

## 5. 关键公式

- Global placement 的可微目标：$L(x)=\lambda_1 WL(x)+\lambda_2 D(x)$，其中 $WL$ 是 wirelength，$D$ 是 density penalty。
- HPWL：$HPWL(P)=\sum_{e\in E}(\max_{i\in e}x_i-\min_{i\in e}x_i+\max_{i\in e}y_i-\min_{i\in e}y_i)$。
- 遗传选择可定义为最大化 fitness：$fitness(a)=-\Delta HPWL(a)$。
- 发现算法可输出初始化 $I$、预处理器 $P$ 和更新函数 $U$，组合为 $x_{t+1}=U(P(x_t),\theta_t)$。

## 6. 训练 / 实验 / 评测协议

- LLM 不训练，使用 LLM-based genetic flow 搜索算法代码。
- 基准覆盖 MMS、ISPD2005、ISPD2019。
- 指标为平均 HPWL improvement、单例 improvement、跨 benchmark 泛化性。
- 与现有参数调优方法比较，验证算法级搜索具有互补性。

## 7. 创新点

1. 把 global placement 优化算法本身作为 LLM 演化对象，而不是只调参数。
2. 提出 LLM-based genetic flow，利用代码语义和运行反馈产生高质量算法变体。
3. 发现的算法跨 benchmark 泛化，并与参数调优方法互补。

## 9. 与芯片流程的关系

EvoPlace 位于 standard-cell/mixed-size global placement 阶段。它不改变 netlist、floorplan 或 router，而是替换 placement solver 中的人工启发式组件。更优的 HPWL 可直接作为后续 detailed placement、routing 和 timing 的起点。

## 10. 讨论与局限

- 主要指标为 HPWL，未完整覆盖 timing、power 和 post-route congestion。
- LLM 生成的算法需要接口验证，否则可能无法嵌入 placer。
- 搜索成本来自多次 placement run，仍需谨慎控制种群和 generation 预算。
- 发现的算法可解释性比手工规则弱，但对代码结构的人工审计仍可行。

## 12. 一分钟复述

global placement 的好与坏很大程度上取决于初始化、预条件处理和 line search 这些人工组件。EvoPlace 让 LLM 生成这些组件的代码，在公开 benchmark 上跑出 HPWL，再用遗传算子让表现好的算法互相组合、变异。搜索结果是可执行算法，而不只是一组参数，因此能发现新的优化策略。
