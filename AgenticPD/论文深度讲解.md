# AgenticPD 论文深度讲解

> **AgenticPD: A Stage-Aware Agentic Framework for Physical Design QoR Optimization**
> Shuo Ren, Zijin Cheng, Yaohui Han, Libo Shen, Leilei Jin, Wanting Tian, Rongliang Fu, Chao Wang, Bei Yu, Tsung-Yi Ho；arXiv:2607.04758
> 原文：[2607.04758_AgenticPD.pdf](./2607.04758_AgenticPD.pdf) · [2607.04758_AgenticPD.txt](./2607.04758_AgenticPD.txt)

## 1. 一句话定位

**AgenticPD 把物理设计 QoR 优化组织成 FP、PL、CTS、Routing 四个 stage 的结构化多 agent 问题，由 Judge Agent 选择分支、复用 checkpoint，并把所有候选都送到 post-route signoff 评估；相比 flat tuning 和 LLM script generation 更贴近真实阶段依赖。**

## 3. 输入 / 输出

### 3.1 输入

- 物理设计任务、工艺与 PDK、OpenROAD flow 环境。
- 各 stage 工具、参数空间和 checkpoint。
- 优化历史、QoR guardrail 和每次运行预算。

```text
agenticpd_input = {
  design: "JPEG_ASAP7",
  stages: ["FP","PL","CTS","RT"],
  llm_backend: "DeepSeek-V3.2",
  evaluation_budget: 20
}
```

### 3.2 输出

- 带分支的优化树和 stage-local actions。
- 可复用 checkpoint。
- 每个候选的 post-route PPA：timing、power、area。

```text
agenticpd_output = {
  best_WNS_ps: 50.6,
  power_mW: 2.6,
  area_um2: 0.046,
  improvement_vs_vanilla: {performance: "2.4%", area: "2.2%", power: "1.1%"}
}
```

## 4. 方法 / 架构 / 构建

```text
Judge Agent
   |
   +-> FP Agent + FP Tool
   +-> PL Agent + PL Tool
   +-> CTS Agent + CTS Tool
   +-> GR/RT Agent + GR Tool
   |
Optimization Branch Tree + Checkpoint Store
   |
Post-route signoff QoR feedback
```

AgenticPD 把“重跑全流程”拆成 stage 边界上的分支。Judge Agent 从历史 QoR 判断下一轮应从哪里继续；stage agent 只在本地 stage 内行动，并复用前一阶段 checkpoint。所有反馈都来自 post-route signoff，而不是中间代理。

## 5. 关键公式

- 流程定义：$S=(FP,PL,CTS,RT)$。
- 动作空间：$\Theta=\Theta_{FP}\times\Theta_{PL}\times\Theta_{CTS}\times\Theta_{RT}$。
- 每次迭代动作：$a_k=(a_{FP},a_{PL},a_{CTS},a_{RT})$。
- 优化目标：$\max_{k\in\{1,\dots,K\}} Q(a_k)$，其中 $Q$ 是 post-route QoR。
- 候选接受采用 Pareto dominance：$u\succ v$ 当所有 guardrail 不劣于且至少一项更优。

## 6. 训练 / 实验 / 评测协议

- LLM 不训练，使用结构化 observation、执行历史和 agent context。
- 与 vanilla LLM、OpenROAD、AutoTuner、ORFS-Agent 比较。
- 在 ASAP7 和 NanGate45 的 JPEG、AES、IBEX 等 benchmark 上运行。
- 统一 20-evaluation budget，所有指标均来自 post-route signoff。

## 7. 创新点

1. 把物理设计 QoR 优化建模为 stage-aware 的分支决策问题。
2. 用 checkpoint 复用避免每次尝试都从 RTL 重跑。
3. Judge Agent 与 stage agents 分离，使全局探索和本地优化职责清晰。

## 9. 与芯片流程的关系

AgenticPD 覆盖 physical design 中从 FP 到 routing 的主要可控阶段，并把 signoff 评估作为闭环边界。它直接对接 OpenROAD 工具，能够优化真实 PPA，而不是只生成脚本或抽象 plan。

## 10. 讨论与局限

- 每个候选仍需 post-route 评估，计算成本较高。
- 当前实验以 OpenROAD/开放 PDK 为主，工业工具和更大设计还需验证。
- LLM 驱动的分支选择依赖历史 QoR 质量，早期冷启动时可能选择不佳。
- stage 内工具和参数空间庞大，agent 可能只探索有限局部动作。

## 12. 一分钟复述

传统调参把 P&R 当成黑盒，每次试验都跑全流程。AgenticPD 让 Judge Agent 看历史 QoR，决定下一轮从 FP、PL、CTS 还是 routing 分支；stage agent 只修改本阶段动作并复用前面 checkpoint。这样搜索更符合物理设计的多阶段依赖，也能在有限预算内拿到更好的 post-route PPA。
