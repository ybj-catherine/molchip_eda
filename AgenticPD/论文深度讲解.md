# AgenticPD 论文深度讲解

> **AgenticPD: A Stage-Aware Agentic Framework for Physical Design QoR Optimization**
> Shuo Ren, Zijin Cheng, Yaohui Han, Libo Shen, Leilei Jin, Wanting Tian, Rongliang Fu, Chao Wang, Bei Yu, Tsung-Yi Ho
> arXiv:2607.04758
> 原文：[2607.04758_AgenticPD.pdf](./2607.04758_AgenticPD.pdf) · [2607.04758_AgenticPD.txt](./2607.04758_AgenticPD.txt)

## 1. 一句话定位

**AgenticPD 把物理设计 QoR 优化组织为 FP、PL、CTS、Routing 四阶段多 Agent 系统，由 Judge Agent 选择分支并复用 checkpoint，所有候选都在 post-route signoff 评估；相比 vanilla LLM 和 SOTA tuner 取得更强 timing。**

这句话里的三个承重点：

1. **stage-aware 分支搜索** — 不是每次全流程重跑，而是从先前 intermediate state 继续。
2. **Harness + stage skills** — 给 agent 提供结构化 observation、执行历史和 agent context。
3. **signoff 评估** — 所有反馈和报告指标都来自 post-route，不用中间代理指标误导搜索。

## 4. 方法与架构

### 4.1 整体 Pipeline

```text
Judge Agent
   │
   ├── FP Agent  ── FP Tool
   ├── PL Agent  ── PL Tool
   ├── CTS Agent ── CTS Tool
   └── GR/RT Agent ── GR Tool
              │
        Branch Tree + Checkpoint Store
              │
        Post-route signoff QoR feedback
```

### 4.2 核心模块逐个详解

- **Judge Agent**：分析优化历史，决定下一轮从哪个 stage 分支。
- **Stage Agents**：在本地 stage 内调用工具和参数，输出结构化 action。
- **Harness**：管理 observation、执行历史、checkpoint 和 agent context。
- **Signoff evaluator**：每个 candidate 都跑完 detailed routing 后评估真实 QoR。

### 4.3 模块职责矩阵

| 模块 | 输入 | 输出 | 工具/模型 | 是否需训练 |
|---|---|---|---|---|
| Judge Agent | history | branch decision | LLM | 否 |
| FP/PL/CTS/RT Agent | stage state | tool actions | LLM | 否 |
| Harness | actions | observations, checkpoints | Python/OpenROAD | 否 |
| Signoff evaluator | routed layout | QoR | OpenROAD signoff | 否 |

## 5. 关键公式

### 5.1 Flow 定义

$$
S=(FP,PL,CTS,RT)
$$

- $S$：物理设计阶段序列
- $FP$：floorplanning
- $PL$：placement
- $CTS$：clock tree synthesis
- $RT$：routing

### 5.2 Action space

$$
\Theta=\Theta_{FP}\times\Theta_{PL}\times\Theta_{CTS}\times\Theta_{RT}
$$

- $\Theta$：完整动作空间
- $\Theta_{FP},\Theta_{PL},\Theta_{CTS},\Theta_{RT}$：各 stage 动作空间

### 5.3 优化目标

$$
\max_{k\in\{1,\dots,K\}} Q(a_k)
$$

- $K$：评估预算
- $a_k$：第 k 次完整动作 tuple
- $Q(a_k)$：post-route QoR

## 6. 训练与实验设置

### 6.1 是否需要训练

LLM 不训练，使用 agentic inference。框架主要依赖预训练语言模型的工具调用和上下文推理能力，不更新模型权重；不同 LLM backend 仅影响分支决策和工具动作质量。

### 6.2 实验设置

- benchmark：ASAP7、NanGate45；JPEG、AES、IBEX。
- baseline：vanilla LLM、OpenROAD、AutoTuner、ORFS-Agent。
- 预算：统一 20 evaluation。

### 6.3 关键实验结果

| 对比 | 结果 |
|---|---|
| vs vanilla LLM | 最佳 post-route timing，power/area 保持 competitive |
| vs AutoTuner / ORFS-Agent | 更强 timing，避免牺牲 power/area |

## 7. 创新点

1. 把 PD QoR 优化建模为 stage-aware 分支决策问题。
2. 用 checkpoint 复用避免每轮全流程重跑。
3. Judge Agent 与 stage agents 分离，使全局搜索与局部工具调用职责清晰。

## 9. 与芯片流程的关系

### 9.1 在全流程中的位置

AgenticPD 覆盖物理设计从 FP 到 routing 的主要可控阶段，直接调用 OpenROAD 工具，用 post-route signoff 结果做闭环。

### 9.2 从“agentic 优化”到“能做成芯片”之间还缺什么

论文未覆盖完整 DRC/LVS、IR drop、多 corner 和制造签核；但 post-route 评估比脚本生成和中间代理指标更接近真实质量。

## 10. 讨论与局限

### 10.1 论文自述的局限

每个候选仍需 post-route 评估，计算成本高；分支选择依赖历史质量。论文明确这是相对 flat tuning 的代价，换来的是更贴近真实阶段依赖的搜索结构。

### 10.2 代码/复现层面的问题

未公开完整 agent 实现和 LLM prompt。论文给出系统框图和关键 workflow，但 stage skill、judge prompt 和 checkpoint 管理代码不足以直接复现。

### 10.3 本资料包的批判性分析

stage-aware 搜索的优势依赖 checkpoint 复用和可靠 signoff feedback；若 stage 工具配置差异大，分支收益可能被评估噪声抵消。

## 12. 一分钟复述版

传统调参把 P&R 当成黑盒，每次全流程重跑。AgenticPD 让 Judge Agent 看优化历史，决定下一轮从 FP、PL、CTS 还是 routing 分支；stage agent 只修改本阶段动作，复用 checkpoint。这样搜索更符合物理设计阶段依赖，也能在有限预算内拿到更好 post-route timing。
