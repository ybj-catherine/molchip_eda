## 1. 一句话定位

**SoberDSE 把 HLS Design Space Exploration（DSE）从“设计更好的单一搜索算法”改成“根据每个 benchmark 的特征自动选择已有 DSE 算法”**：先用 ECoGNN 预测 QoR，在 20 个训练 benchmark 上运行 7 种启发式与 3 种 RL 算法建立 ground truth，再用“监督模型初始化 + PPO 精调”的协同推荐模型输出算法 ID；相比 SOTA 启发式 DSE 最高提升 5.7×、相比 SOTA learning-based DSE 最高提升 4.2×，并比常规分类模型在少样本场景平均提升 35.57% 的推荐准确率。

这句话里的四个承重点：

1. **显式引入 algorithm selection** — 论文先用 NSGA-II/SA/ACO/PSO 等实验证明 no-single-algorithm-wins，因此把问题定义为 `算法 ID -> benchmark`，而不是继续堆叠新的 DSE 搜索算子。
2. **用 CDFG/ProgramL 风格图编码 benchmark** — 将高层 C 程序经 LLVM IR 转为带 HLS pragma 信息的 Benchmark Feature Graph（BFG），让推荐模型看到控制流、数据依赖与配置入口，而不是只用简单统计量。
3. **监督到强化学习的 warm-start** — 少样本下纯监督易过拟合，纯 RL 样本效率差；论文用监督 softmax 概率初始化 PPO 状态，以 ADRS 相对偏差设计奖励，兼顾准确率与样本效率。
4. **推荐结果可以立即执行** — 推荐出的不是代理分数，而是可运行的 NSGA-II/SA/ACO/PSO/Lattice/HGBO-DSE/MOEDA/AC/PG/QL-MOEA 算法；SoberDSE 的最终输出是这些算法在 benchmark 上找到的 Pareto front。

## 3. 输入 / 输出

### 3.1 输入

第一类输入是 HLS kernel 与其 pragma 配置：

```c
// 示意：HLS DSE 搜索的对象不是源代码功能，而是配置组合
void gemm(float A[I][K], float B[K][J], float C[I][J]) {
#pragma HLS INTERFACE m_axi port = A depth = 1024
#pragma HLS INTERFACE m_axi port = B depth = 1024
#pragma HLS INTERFACE m_axi port = C depth = 1024
    for (int i = 0; i < I; i++)
        for (int j = 0; j < J; j++)
#pragma HLS PIPELINE II = 1
            for (int k = 0; k < K; k++)
                C[i][j] += A[i][k] * B[k][j];
}
```

第二类输入是论文在“算法选择”任务中使用的环境/元数据：

```text
benchmark: atax
source: Polyhedral
feature_graph: BFG(benchmark)          # LLVM IR -> ProgramL + HLS pragma nodes
algorithm_suite:
  - NSGA-II
  - SA
  - ACO
  - PSO
  - Lattice
  - HGBO-DSE
  - MOEDA
  - IRONMAN-PRO (AC)
  - IRONMAN-PRO (PG)
  - QL-MOEA
ground_truth_target: argmin_ADRS(algorithm)
```

### 3.2 中间产物

关键中间表示是 benchmark feature graph（BFG）：先由 LLVM 生成 IR，再用 ProgramL 风格方法抽取控制/数据依赖图，并按 GNN-DSE 的思路加入 `icmp` 等 pragma 相关节点。该图被 ECoGNN encoder 编码为：

$$
h_G = \mathrm{GNNEncoder}(\mathrm{BFG})
$$

- $h_G$：benchmark 的图嵌入。
- $\mathrm{BFG}$：带 HLS 配置信息的 benchmark 特征图。
- $\mathrm{GNNEncoder}$：QoR 预测模型 ECoGNN 的 encoder 部分。

### 3.3 输出

推荐模型最终给出算法 ID，例如：

```text
recommendation: {
  benchmark: "jacobi-2d",
  algorithm_id: "HGBO-DSE",
  supervised_probabilities: [0.01, 0.03, ..., 0.42, ...],
  ppo_adjusted_decision: "HGBO-DSE",
  output: Pareto_front(configurations)
}
```

如果配置由推荐算法继续搜索，则输出每个 benchmark 的一组非支配配置，而不是只输出单个 PPA 点。

## 4. 方法与架构

### 4.1 整体 Pipeline

```text
     A. Dataset Generator                     E. Inference / Recommendation
  ┌──────────────────────────┐                ┌──────────────────────────────┐
  │ 20+ training benchmarks   │                │ 9 inference benchmarks       │
  │ + 9 inference benchmarks  │                │ -> BFG graph                 │
  │ -> run 10 DSE algorithms  │                └──────────────┬───────────────┘
  │ -> ECoGNN QoR prediction  │                                ▼
  │ -> compute ADRS           │                ┌──────────────────────────────┐
  │ -> ground-truth algo ID   │                │ C+D: Supervised + PPO select │
  └──────────────┬────────────┘                │      recommended algorithm   │
                 ▼                             └──────────────┬───────────────┘
  B. Benchmark Feature Graph Generator                         ▼
  ┌──────────────────────────┐                Execute selected DSE algorithm
  │ LLVM IR -> ProgramL ->   │                and return its Pareto front
  │ pragma-aware BFG         │
  └──────────────┬───────────┘
                 ▼
  C. Supervised Recommendation Model
  D. PPO Recommendation Model
```

### 4.2 核心模块逐个详解

#### 模块 1：Dataset Generator

模块 1 负责把算法选择问题变成有监督训练数据。论文实现 7 个启发式 DSE（NSGA-II、SA、ACO、PSO、Lattice、HGBO-DSE、MOEDA）和 3 个 RL DSE（IRONMAN-PRO 的 AC/PG、QL-MOEA），并用预训练 ECoGNN 对探索到的设计配置做 QoR 预测。每个 benchmark 的 ground truth 是 ADRS 最低的算法 ID。

#### 模块 2：Benchmark Feature Graph Generator

模块 2 解决“算法选择器必须从程序本身看到可迁移特征”的问题。普通统计特征不足以区分控制流复杂但数据流规则、数据流复杂但控制流简单等不同 benchmark；BFG 用 LLVM IR + ProgramL 抽取数据/控制依赖，再把 pragma 插入作为图节点。

#### 模块 3：Collaborative Recommendation Model

模块 3 先用监督 MLP head 输出 10 类算法概率，再用 PPO agent 做第二层决策。论文给 state 的定义是 `[h_G; p_sup]`，让 RL 能利用监督模型的先验，而不是从头学特征表示。奖励由算法实际 ADRS 与最优 ADRS 的偏差决定。

### 4.3 模块职责矩阵

| 模块 | 输入 | 输出 | 用到的模型/工具 | 是否需训练 |
|---|---|---|---|---|
| Dataset Generator | HLS benchmark + pragma 空间 | 每个算法的 ADRS 与最优算法 ID | ECoGNN QoR predictor、10 个 DSE 算法 | ECoGNN 已预训练 |
| BFGG | HLS C-like 源码 | BFG | LLVM、ProgramL、pragma inserter | 否 |
| Supervised model | BFG | 算法概率 $p_{sup}$ | GNN encoder + MLP head | 是，250 epochs |
| PPO model | $[h_G;p_{sup}]$ | 算法 ID | Actor/Critic MLP | 是，1000 epochs |
| Inference | BFG | recommended algorithm + Pareto front | 上述模型 + 被推荐 DSE 算法 | 否 |

## 5. 关键公式

### 5.1 算法选择的问题目标

$$
\min_{F} \mathrm{Loss}\left(H'(B), H(B)_{\min}\right)
$$

- $F$：算法推荐函数。
- $H'(B)$：推荐函数对 benchmark $B$ 的近似性能。
- $H(B)_{\min}$：候选算法集合在该 benchmark 上的最优性能。

### 5.2 Pareto 前沿配置

$$
a(d_{P_f}) \le a(d_I), \qquad l(d_{P_f}) \le l(d_I)
$$

- $d_{P_f}$：Pareto 前沿中的配置。
- $d_I$：设计空间 $I$ 中的任意配置。
- $a(\cdot)$：资源利用率。
- $l(\cdot)$：延迟。

### 5.3 ADRS 指标

$$
\mathrm{ADRS}(\Gamma,\Omega)=\frac{1}{|\Gamma|}\sum_{\lambda\in\Gamma}\min_{\mu\in\Omega} f(\lambda,\mu)
$$

- $\Gamma$：参考 Pareto 最优集。
- $\Omega$：算法得到的近似 Pareto 最优集。
- $f(\lambda,\mu)$：参考点 $\lambda$ 与近似点 $\mu$ 之间的距离。
- $\mathrm{ADRS}$ 越低越好。

### 5.4 监督推荐模型

$$
p(A|\mathrm{BFG})=\mathrm{softmax}\left(W_2 \cdot \mathrm{ReLU}(W_1 h_G+b_1)+b_2\right)
$$

- $A$：候选 DSE 算法集合。
- $W_1,W_2$：MLP head 权重。
- $b_1,b_2$：MLP head 偏置。
- $h_G$：GNN encoder 输出。

### 5.5 PPO 策略与价值函数

$$
\pi_\theta(a_t|s_t)=\mathrm{softmax}\left(\mathrm{MLP}_a(s_t)\right)
$$

$$
V_\phi(s_t)=\mathrm{MLP}_c(h_G)
$$

- $a_t$：第 $t$ 步选择的算法。
- $s_t=[h_G;p_{sup}]$：PPO 状态。
- $\pi_\theta$：actor 策略。
- $V_\phi$：critic 对状态的估计。

### 5.6 奖励与 PPO 损失

$$
r_t=\frac{\left|m(a_t)-\bar{m}\right|}{\bar{m}}
$$

$$
L_{\mathrm{PPO}}=L_{\mathrm{policy}}+c_1 L_{\mathrm{value}}-c_2 L_{\mathrm{entropy}}
$$

- $m(a_t)$：算法 $a_t$ 的 ADRS。
- $\bar{m}$：当前 benchmark 上最优算法的 ADRS。
- $L_{\mathrm{policy}}$：clipped policy gradient。
- $L_{\mathrm{value}}$：critic 价值函数损失。
- $L_{\mathrm{entropy}}$：探索熵奖励项。

论文还使用 GAE 计算 advantage：

$$
A_t=\sum_{l=0}^{\infty}(\gamma\lambda)^l \delta_{t+l}
$$

- $A_t$：广义优势估计。
- $\gamma$：折扣因子。
- $\lambda$：GAE 参数。
- $\delta_t$：TD residual。

## 6. 训练与实验设置

### 6.1 是否需要训练

需要两阶段训练：

- ECoGNN QoR 预测器独立预训练，且论文强调其训练 benchmark 与算法推荐模型的 benchmark 分离。
- 监督推荐模型：hidden size 256、learning rate 0.0003、250 epochs。
- PPO 推荐模型：hidden size 256、learning rate 0.0005、1000 epochs。

### 6.2 实验设置

- 训练/推荐数据来自 MachSuite 与 Polyhedral 的高层 C 类 benchmark。
- 推理集包含 `nw`、`stencil`、`atax-medium`、`bicg-medium`、`correlation`、`jacobi-2d`、`mvt`、`symm-opt`、`syrk`，其中设计空间可到百亿规模以上。
- 对比基线包括 RF、XGBoost、K-NN、SVM 等分类器，以及只使用监督模型、不使用 PPO 的 SFM。
- DSE 对比基线是 7 种启发式与 3 种 RL 方法。
- 硬件为 Xilinx Alveo U200 FPGA、250 MHz；框架用 PyTorch。

## 7. 创新点

### 创新点 1：把 HLS DSE 问题显式重定义为 algorithm selection

此前研究通常提出一个新的 DSE 算法并希望其通用；SoberDSE 先把多个公开算法统一到同一 ADRS 评测口径，再用 benchmark 特征推荐算法。它的贡献不是某个搜索算子更强，而是承认 NFL 并构建选择机制。

### 创新点 2：监督概率 warm-start 提升 RL 少样本效率

纯分类在有限 benchmark 上易过拟合，纯 RL 在小样本场景收敛慢。SoberDSE 用监督模型概率初始化 RL state，使得 PPO 不必从随机动作重新学习“什么 benchmark 该配什么算法”。

### 创新点 3：可执行的 DSE 算法套件与 QoR 代理组合

论文把 ECoGNN 作为 DSE 内部评估器，从而在小时/天级的 HLS 仿真成本之外形成可重复的大规模评测；推荐结果可以直接驱动下游真实 DSE 算法。

## 9. 与芯片流程的关系

### 9.1 在全流程中的位置

HLS 把高层 kernel 映射到 RTL，再进入逻辑综合。SoberDSE 位于 HLS 工具链的最前端：在综合前搜索 pragma 配置，并尝试用算法选择替代“每次跑新的 HLS 流程试配置”。因此它接手的是高层软件/算法描述，交棒给 HLS 综合入口。

### 9.2 从“推荐算法优”到“可流片”之间隔着什么

论文的优化目标是 ADRS，ADRS 又依赖 ECoGNN 预测的 latency/resource。代理模型误差、FPGA 目标与真实 ASIC 综合差异、物理设计阶段的时序/功耗变化都不会被该流程修正；因此不能把 SoberDSE 的搜索结果当成 signoff-ready PPA。

## 10. 讨论与局限

### 10.1 论文自述局限

论文未来方向是扩大算法套件、在更多 benchmark 上训练，说明当前选择器依赖 benchmark 覆盖和训练分布；有限 benchmark 上训练出的 selector 仍可能对新 benchmark 失效。

### 10.2 代码/复现层面问题

- 代码入口是匿名评审仓库，公开地址稳定性需以最终发表版为准。
- ECoGNN、ProgramL、HLS 工具链和 FPGA 评估环境都是复现门槛。
- 论文正文未展示完整 21 行训练表的每行解析结果，表 1 的 PDF 排版较密，逐行核对时仍需依赖源文件。

### 10.3 本资料包的批判性分析

该工作的强项是评测协议统一，弱点是“算法选择上限受候选算法套件限制”：如果套件里没有任何适合某类 benchmark 的算法，selector 只能选相对较好者。另一个问题是 recommendation accuracy 只统计是否选出最优算法，不区分次优算法与最差算法的损失，未来应补充更细的 regret metric。

## 12. 一分钟复述版

1. HLS DSE 配置空间巨大，但没有任何一个 DSE 算法在所有 benchmark 上最好。
2. SoberDSE 不是发明第 11 种搜索算法，而是构建 10 种算法的选择器。
3. benchmark 被 LLVM/ProgramL 转成带 pragma 的 BFG，用 ECoGNN encoder 得到特征。
4. 监督模型先在有限样本上输出算法概率，再交给 PPO 精调。
5. 奖励用算法 ADRS 与最优 ADRS 的相对偏差设计。
6. 推理时推荐算法并执行它，返回 Pareto 配置集。
