# LITE 论文深度讲解

> **LITE: Enhancing Test Efficiency through Automated ATPG-Aware Lightweight Scan Instrumentation**  
> Sudipta Paria, Md Rezoan Ferdous, Aritra Dasgupta, Atri Chatterjee, Swarup Bhunia  
> Department of ECE, University of Florida  
> **ITC 2025 (IEEE International Test Conference)** · arXiv: 2505.19418v1（2025-05-26）

---

## 1. 一句话定位

LITE 是一种**轻量级 scan 仪表化技术**，通过复用 scan chain 中已有的功能 Flip-Flop（而非插入专用测试点），以极低硬件开销同时提升 ATPG 和随机向量测试的可控性/可观测性。在 ISCAS89 + ITC99 基准上，ATPG 测试向量数**降低约 31%**，硬件开销远低于传统 TPI（Test Point Insertion）。

LITE **不涉及 ML/LLM**——它是纯电路级的 DFT 结构创新，适合作为 AI4EDA 知识库中 DFT 方向的**基准对照论文**。

---

## 2. EDA 阶段映射（①-⑰）

LITE 位于芯片流程中**综合之后**的 DFT 插入阶段：

```
③ 逻辑综合 → [LITE: scan chain 仪表化] → ⑧ 布局布线 → ... → ⑯ 封装+ATE测试
                   ↑
            在综合后的门级网表上
            对 scan FF 插入 XOR+MUX 逻辑
            提升可测性但几乎不增加面积/延时
```

传统 TPI 需要插入专用 FF + 门控逻辑，硬件开销大。LITE 直接在现有 scan FF 的 D 输入端和 Q 输出端附加 XOR+MUX，不增加 FF，硬件开销极低。

**覆盖率：2/17**（③ 逻辑综合后 DFT + ⑯ ATE 测试）

---

## 3. 输入 / 输出

### 输入
- **门级网表**（已含 scan chain，来自综合工具）
- **配置选择 θ**：Config1 Obs / Config2 Obs / Config1 Obs CC / Config2 Obs CC

### 输出
- **LITE 增强网表**（可被 ATPG 工具直接使用，生成更少向量、更高覆盖率）

### 例子

**输入网表（简化）：**
```verilog
// 原始 scan FF: 内部节点 obs1 不可直接观测
SDFF scan_ff_1 (.D(internal_net), .SI(scan_in), .SE(se), .Q(q_out), .CLK(clk));
```

**输出网表（LITE Config1 Obs）：**
```verilog
// 增加 XOR+MUX: 使 obs1 在测试模式下可观测
wire xor_out = obs1 ^ obs2;
MUX2 mux_lite (.I0(internal_net), .I1(xor_out), .S(sel), .O(mux_out));
SDFF scan_ff_1 (.D(mux_out), .SI(scan_in), .SE(se), .Q(q_out), .CLK(clk));
```

## 4. 方法与架构

### 4.1 整体流程

```
┌──────────────┐    ┌──────────────────┐    ┌──────────────────┐
│ 门级网表 IN   │ → │ Hypergraph 生成   │ → │ 拓扑排序 GT       │
│ (含 scan chain)│   │ G = (V, E)       │    │ (避免组合环)       │
└──────────────┘    └──────────────────┘    └────────┬─────────┘
                                                      │
                                              ┌───────▼─────────┐
                                              │ SCOAP 可测性分析  │
                                              │ CC0 / CC1 / CCobs│
                                              └───────┬─────────┘
                                                      │
                              ┌───────────────────────▼──────────────────────┐
                              │              LITE 插入（4 种配置）             │
                              │  Config1 Obs / Config2 Obs                   │
                              │  Config1 Obs CC / Config2 Obs CC             │
                              └───────────────────────┬──────────────────────┘
                                                      │
┌──────────────┐    ┌──────────────────┐    ┌────────▼─────────┐
│ ATPG 工具     │ ← │ LITE 增强网表 SN  │ ← │ 写回 Verilog      │
│ 生成更少向量   │    │ (标准单元库兼容)   │    │ (MUX+XOR 仅用    │
│ 更高覆盖率     │    │                   │    │  标准单元)       │
└──────────────┘    └──────────────────┘    └──────────────────┘
```

### 4.2 四种 LITE 配置

| 配置 | 提升目标 | 电路结构 |
|------|---------|---------|
| **Config1 Obs** | 可观测性 | 2 个低可观测节点 → XOR → MUX（插入到 scan FF 的 D 输入前） |
| **Config2 Obs** | 可观测性 | 1 个低可观测节点 + 原始逻辑 → XOR → MUX |
| **Config1 Obs CC** | 可观测性 + 可控性 | Config1 Obs + scan FF 的 Q 输出端附加 MUX（可控节点） |
| **Config2 Obs CC** | 可观测性 + 可控性 | Config2 Obs + scan FF 的 Q 输出端附加 MUX（可控节点） |

### 4.3 为什么选 XOR + MUX

XOR 门的等概率掩码特性确保输出不偏向特定值（AND/OR 门有偏差），在随机测试向量下覆盖效果更好。MUX 实现正常模式/测试模式的零开销切换。所有逻辑由标准单元库实现，适用于**任何工艺、任何标准单元库**。

### 4.4 SCOAP 可测性分析

SCOAP（Sandia Controllability and Observability Analysis Program）为每个节点计算：
- **CC0/CC1**：控制到 0/1 的难度值
- **CO**：观测难度值

低可控/可观测节点被纳入候选列表，LITE 优先针对这些节点插入仪表化逻辑。

## 5. 关键概念与术语

### 5.1 Scan-based DFT 原理

Scan chain 将电路内所有 FF 串联，测试时：
- **Shift 阶段**：通过 scan_in 串行移入测试向量
- **Capture 阶段**：一个时钟周期捕获电路响应
- **Shift 阶段**：通过 scan_out 串行移出结果

### 5.2 TPI（Test Point Insertion）的局限

传统 TPI 为每个测试点插入：
- 1 个专用 control/observe FF
- 组合逻辑门（AND/OR/MUX）
→ 硬件开销大、影响关键路径延时、面积增加显著

### 5.3 LITE 的改进

LITE 不插入新 FF，而是：
- 在现有 scan FF 的 **D 输入端**加 XOR+MUX → 提升可观测性
- 在现有 scan FF 的 **Q 输出端**加 MUX → 提升可控性
→ 硬件开销极低（仅若干 XOR/MUX 门）、不影响 scan chain 结构

### 6.2 主要结果

**ATPG 测试向量改善：**
- 平均 ATPG 向量数降低约 **31%**
- 10 个基准中多数在测试向量数和测试周期上均取得显著改善

**随机向量测试改善：**
- LITE 有效解决了 random-pattern-resistant（RPR）故障的覆盖率瓶颈
- 对 BIST 和 3D IC 测试场景尤为有效

## 7. 创新点

1. **复用 scan FF 而非插入新 FF**：核心创新——利用 scan chain 中已有 FF 的 D 输入和 Q 输出端口附加轻量级逻辑
2. **XOR+MUX 低成本电路结构**：XOR 的等概率特性使随机测试也能受益，区别于传统 TPI 的 AND/OR 结构
3. **自动化插入算法**：基于 hypergraph 拓扑排序 + SCOAP 分析的自动化工具流，无需人工介入
4. **兼容所有 ATPG/BIST 流程**：LITE 增强网表可直接被商用 EDA 工具（如 Synopsys TetraMAX）使用
5. **4 种灵活配置**：可单独提升可观测性，或同时提升可控性+可观测性

## 9. 与芯片流程的关系

```
③ 逻辑综合 ──→ [LITE: scan 仪表化] ──→ ATPG ──→ ⑧ 布局布线 ──→ ... ──→ ⑯ ATE 测试
     │                                          │
     │  门级网表 + scan chain                    │  LITE 增强网表
     │                                          │  直接用于 ATPG
     │  SCOAP 分析低可测节点                     │  向量数 ↓31%
     │  XOR+MUX 仪表化                          │  覆盖率 ↑
     │                                          │
     └──────────────────────────────────────────→ 与物理设计流程无缝衔接
```

LITE 在标准 DFT 流程中插入，不改变 RTL 设计、不改变 scan chain 结构、不影响后续布局布线。

## 10. 讨论与局限

1. **非 ML/AI 方法**：LITE 是纯电路/算法级 DFT 创新，不涉及机器学习——放入 AI4EDA 知识库是作为 DFT 方向的**基准对照**
2. **基准规模有限**：最大设计 b19 约 6 万 FF、63 万门——尚未在现代 SoC 规模（千万门级以上）验证
3. **仅提升可测性**：不改变设计功能，也不能修复 RTL 级 DFT 违规（与 VeriRAG 互补）
4. **依赖 SCOAP 启发式**：节点选择基于 SCOAP 值，可能存在更优的选择策略（如 ML-guided）
5. **需要 scan chain 已存在**：LITE 假设 scan insertion 已完成，不适用于纯组合逻辑或无 scan 设计
6. **未评估对时序收敛的影响**：虽然声称开销低，但没有 STA 分析数据
