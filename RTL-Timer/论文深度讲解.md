## 1. 一句话定位

**RTL-Timer 是一个"细粒度"的 RTL 级时序预测器：它不满足于给整个设计报一个 WNS/TNS 数字，而是预测每一个寄存器端点（精确到信号的每一位）的到达时间，并直接把这些预测标注回 Verilog 代码上，用来指导早期优化。**

要理解它为什么重要，先要理解一个背景：**时序分析（STA）需要寄生参数（R、C），而这些只有到布局后才有**。所以越早的阶段越难做时序分析：

- 版图阶段：能精确 STA；
- 网表阶段：没有线长信息，工业 STA 工具都报不准（Xie et al. 2022 已经证明）；
- **RTL 阶段：传统 STA 工具连"猜"都不给**——因为 RTL 是 HDL 代码，连网表都不是。

但 RTL 恰恰是"灵活性最高、改动成本最低"的阶段。于是论文提出一个关键问题：**能不能在 RTL 阶段就预测出"哪些寄存器的时序最差"，从而让设计师/工具在改起来最便宜的时候就知道该改哪里？**

在此之前的工作（2022 年才开始有人做）要么只预测整个设计的 TNS/WNS 一个数，要么只接受小规模组合逻辑、要么不能泛化到新设计。**RTL-Timer 自称是第一个"通用的、细粒度的"RTL 时序估计器**。

## 2. EDA 阶段映射

RTL-Timer 不是流程里的某个阶段，而是一个**跨阶段预测模型**：输入在①（RTL），预测目标在③（逻辑综合后）与⑤（静态时序分析）。

| 阶段 | 是否覆盖 | RTL-Timer 中的角色 |
|---|:---:|---|
| ① RTL 设计 | ✅ 输入 | Verilog/VHDL/Chisel/SpinalHDL 作为预测输入 |
| ③ 逻辑综合 | ✅ 目标 | 预测的是"综合后"网表的时序；并被用来指导综合（group_path / retime） |
| ⑤ 静态时序分析 | ✅ 目标 | 标签来自综合后网表的 STA（PrimeTime），预测的也是到达时间/slack |
| ⑥ 形式验证 | ❌ | 不涉及等价检查 |
| ⑦–⑩ 物理设计 | ⚠️ 下游 | 论文验证了"综合期优化在布局后仍保留收益"，但预测本身不碰物理阶段 |
| ⑪–⑰ | ❌ | 不做签核 |

一句话：**RTL-Timer 是"在①读代码、预测③⑤的结果、再回头反哺③的优化"**。

## 3. 输入、输出与任务定义

### 3.1 两个正式问题

设 Verilog 设计为 \(\mathcal{V}\)，综合后门级网表为 \(\mathcal{N}\)。每个寄存器端点记为 \(ep_i\)（由于 RTL 时序信号与网表寄存器一一对应，\(ep_i\) 两边都存在）。

- **问题 1（数值回归）**：\(\forall ep_i \in \mathcal{V},\ F_{AT}(ep_i) \rightarrow AT_{\mathcal{N}}(ep_i)\)，预测每个端点的到达时间值；
- **问题 2（排序预测）**：\(\forall ep_i,\ F_{Rank}(ep_i) \rightarrow Rank_{\mathcal{N}}(ep_i)\)，预测端点的"关键性排序"。

为什么要有"问题 2"？因为到达时间的**精确数值很难回归准**，但"谁比谁更关键"这个**相对排序**对优化决策往往更有用。所以论文同时做了回归 + 排序（learning-to-rank）两个任务。

### 3.2 三个粒度

1. **位级（bit-wise）**：每个寄存器端点 = 每一位一个预测；
2. **信号级（signal-wise）**：一个多 bit 信号取"最长的那一位"的到达时间；
3. **设计级（overall）**：由负 slack 汇总出整个设计的 TNS / WNS。

粒度从细到粗，逐层聚合。

### 3.3 输出

- 每个寄存器端点的到达时间 + 关键性排序分组；
- 整个设计的 TNS / WNS；
- 一个**自动标注工具**：把预测值直接写回 HDL 代码注释（`// predicted slack: ...`），可做成 IDE 插件；
- 用于指导综合的两条命令：`group_path`（分组优化）和 `retime`（寄存器重定时）。

## 4. 方法与关键设计

### 4.1 挑战一：HDL 代码没法直接喂给模型 → BOG 布尔算子图

RTL 是代码，STA 工具和 ML 模型都吃不了。已有的表示（BDD、CNF、AIGER）都是为逻辑综合/验证设计的，不面向 ML。

论文提出 **BOG（Boolean Operator Graph，布尔算子图）**：一种**位级**通用表示，把每个寄存器位当作节点、每个布尔算子（AND/NOT/OR/XOR/MUX）当作算子节点。选不同的算子集合就能特化成不同变体：

- **SOG**（simple-operator graph）：算子种类多，最接近真实网表；
- **AIG**（AND-inverter graph）：只有 AND 和 NOT，最基础；
- **AIMG、XAG**：介于两者之间。

论文用**四种变体做集成学习（ensemble）**，取它们预测的最大/最小/平均，大幅降低跨设计的方差（表 5 显示标准差从 ~0.2 降到 0.08）。

关键点：BOG 还是一种"**伪网表**"——寄存器位和算子可以被当成 liberty 文件里的"伪标准单元"，于是能直接在 BOG 上跑传统 STA（伪 STA）。

### 4.2 挑战二：RTL 信号对不上网表单元 → 寄存器一致性 + 采样路径

RTL 信号和综合后网表的 cell/net 之间**没有直接映射**，导致 BOG 内部算子没有标签可学。论文的解法分两步：

1. **寄存器一致性**：RTL 时序信号位 ↔ 网表位级寄存器是一一对应的，所以每个端点 \(ep_i\) 能从网表 STA 拿到标签（到达时间）。内部算子没标签，没关系。
2. **面向寄存器端点的路径采样**：受 STA"到达时间沿路径传播、取最大值"的启发，从每个端点 \(ep_i\) 回溯到所有驱动寄存器，得到它的输入锥（input cone）\(C\)，然后采样两类路径：
   - **最慢路径** \(S_{*\rightarrow i}\)：在 BOG 上做伪 STA，找到最慢的那条；
   - **随机路径** \(\{L_{*\rightarrow i}^{(k)}\}\)：随机采样 K 条（K 正比于驱动寄存器数）。

**为什么要随机采样其他路径？** 因为综合会做逻辑优化/技术映射，BOG 里"不是最慢"的路径，综合后可能变成"最慢"。只看 BOG 的最慢路径会漏掉真正的瓶颈。

### 4.3 自定义损失 `retain_max_every_n`

位级到达时间预测取所有采样路径预测的**最大值**：

$$
AT_i^{predict} = \max\Big(F_{AT}(S_{*\rightarrow i}),\ \{F_{AT}(L_{*\rightarrow i}^{(k)})\}\Big)
$$

$$
Loss_i = LossFunc(AT_i^{predict},\ AT_i^{label})
$$

这个"先取 max 再算 loss"的结构对模型 \(F_{AT}\) 可导，能端到端训练。**它强制模型去学"最大到达时间"这个量，而不是学平均路径**——这正是 STA 的语义。

### 4.4 特征工程（三级）

- **设计级**：端点排名百分比、时序/组合/总单元数等（用于跨设计比较）；
- **锥级**：输入锥的驱动寄存器数（R≈0.45）；
- **路径级**：伪 STA 到达时间、路径级数、算子数、扇出、负载电容、slew 等（R≈0.38~0.56）。

### 4.5 模型探索

- 位级：**XGBoost（树模型）最好**，超过 MLP 和 Transformer。作者归因于"特征工程把 RTL 变成了表格数据，树模型天生擅长表格"（Grinsztajn 2022 的结论）；
- 信号级排序：用 **LambdaMART（pairwise learning-to-rank）**，把每个设计当 query、端点当 document、关键性等级当 label；
- 设计级 TNS/WNS：又一个树模型回归。

### 4.6 优化应用（这是论文的"落地"亮点）

预测出的细粒度排序被用来控制综合的两个选项：

- **group_path**：把端点按预测排序分成 4 组，分别给不同优化力度 → 主要改善 TNS；
- **retime**：对 top 5% 关键端点做寄存器重定时 → 主要改善 WNS。

**这两个命令都需要指定"具体的寄存器名"——没有细粒度预测根本做不到。**

## 5. 实验与主要结果

### 5.1 设置

- **数据**：21 个开源 RTL 设计（ITC'99、OpenCores、Chipyard、VexRiscv），6K~510K 门，VHDL/Verilog/Chisel/SpinalHDL 四种 HDL；
- **标签**：Synopsys Design Compiler 综合 + Cadence Innovus 布局，Synopsys Prime Time 做 STA，NanGate 45nm；
- **评估**：10 折交叉验证，训练/测试是**严格不同的设计**（跨设计泛化）；
- **指标**：R（相关系数）、R²、MAPE、COVR（关键性分组覆盖率）。

### 5.2 建模精度（表 4）

| 粒度 | 指标 | 数值 |
|---|---|---|
| 位级（bit-wise） | R / MAPE / COVR | 0.88 / 12% / 66% |
| 信号级回归 | R / MAPE | 0.89 / 15% |
| 信号级排序 | COVR | **80%** |
| 设计级 WNS | R / R² | 0.91 / 0.86 |
| 设计级 TNS | R / R² | **0.98 / 0.97** |

对比基线：SNS 的 WNS 只有 R=0.73，MasterRTL（Fang et al. 2023，同组前作）TNS R=0.96。RTL-Timer 全面超越，且是唯一做到"细粒度"的。

### 5.3 消融（三个关键设计都有效）

- **去掉随机采样路径**（只看最慢路径）：树模型 R 从 0.80 掉 0.08；
- **去掉位级预测**（直接建模信号）：回归 R 从 0.89 掉到 0.56，排序 COVR 从 80% 掉到 39%——**位级是核心**；
- **去掉 LTR 排序模型**：COVR 从 80% 掉到 71%。

### 5.4 集成与方差（表 5）

四种 BOG 变体单独平均 R 都在 0.75~0.85，但方差大（Std R 0.18~0.26）；集成后 R 提到 0.88~0.89，Std R 降到 0.06~0.08。**集成的主要贡献是"稳"，不是"准一点"。**

### 5.5 优化收益（表 6）

用预测排序指导 `group_path + retime`：

- TNS 改善最高 **33.5%**，平均 **9.9%**；
- WNS 改善最高 **16.4%**，平均 **3.1%**；
- 功耗和面积几乎不受影响；
- **布局后收益仍在**：placement 后 WNS 平均 +4.6%、TNS +6%；post-placement 时序优化后仍 +3.1% / +6.8%；
- 关键：**用预测排序的优化效果，与用"真值排序"（oracle）相当甚至更好**。

### 5.6 运行时

建模只占默认综合运行时的约 4%（BOG 构造 3.2% + 面向寄存器处理 0.9% + 推理 <0.1 秒）。但指导优化会让综合总时长平均 +45%（因为分组/重定时要分开跑）。

## 6. 主要创新点

1. **首个通用细粒度 RTL 时序估计器**：从"整设计一个数"到"每个寄存器位一个数"，且能泛化到任意新设计；
2. **BOG 布尔算子图**：位级通用表示，可特化成 SOG/AIG/AIMG/XAG 四种，且能当伪网表跑伪 STA；
3. **寄存器一致性 + 采样路径 + `retain_max_every_n` 损失**：解决了"RTL 信号对不上网表单元"这一标签缺失难题，并让模型学到 STA 的"取最大到达时间"语义；
4. **回归 + 排序双任务**：承认精确数值难、但相对排序够用，用 learning-to-rank 补足；
5. **真正的优化落地**：首次把细粒度时序预测**反哺进综合工具**（group_path / retime），而不是只停在"预测得更准"。

## 7. 关键术语与缩写

| 缩写/术语 | 全称 | 含义 |
|---|---|---|
| RTL | Register-Transfer Level | 寄存器传输级，HDL 描述的抽象层次 |
| STA | Static Timing Analysis | 静态时序分析，无需输入向量 |
| WNS | Worst Negative Slack | 最差负裕量 |
| TNS | Total Negative Slack | 总负裕量（所有违例之和） |
| AT | Arrival Time | 信号到达时间 |
| slack | 裕量 | 要求时间 − 到达时间，负值即违例 |
| BOG | Boolean Operator Graph | 布尔算子图，位级 RTL 表示 |
| SOG / AIG / AIMG / XAG | — | BOG 的四种算子特化变体 |
| endpoint | 端点 | 时序路径终点，主要是寄存器（少量是 PO 引脚） |
| input cone | 输入锥 | 驱动某端点的所有输入逻辑 |
| pseudo-STA | 伪 STA | 在 BOG 伪网表上跑的传统 STA 算法 |
| COVR | Coverage | 关键性分组覆盖率（预测与真值分组交集比例） |
| MAPE | Mean Absolute Percentage Error | 平均绝对百分比误差 |
| LTR / LambdaMART | Learning to Rank | 学习排序（pairwise 排序模型） |
| group_path | — | 综合工具按路径分组给不同优化力度的命令 |
| retime / retiming | 重定时 | 移动寄存器穿过组合逻辑以平衡时序 |

## 9. 局限性与风险

1. **假设固定时钟频率**：到达时间决定 slack 的前提是时钟固定；未覆盖多时钟域、异步路径、false path、multicycle 等真实约束。
2. **标签只到综合后网表**：预测的是"综合后"时序，不是"布局后/签核"时序。虽然论文验证了布局后收益仍在，但那不是同一个预测目标。
3. **21 个设计偏少**：跨设计泛化是 10 折交叉验证，但绝对样本量仍有限，且排除了小设计（<5K 门）和内存主导的设计。
4. **商业工具依赖**：标签与优化都靠 DC/Innovus/PrimeTime，开源复现困难。
5. **优化收益高度依赖工具语义**：group_path / retime 是商业工具的特定命令，换工具（Yosys）未必有对应能力。
6. **信号级是"最长位"聚合**：这种 max 聚合会丢失某些信息（比如多 bit 信号的内部结构），但论文已证明对优化足够。

## 11. 一分钟总结

RTL-Timer 解决"RTL 阶段没有时序信息"这个老大难：它把 Verilog 转成**位级布尔算子图 BOG**（四种变体集成），利用**寄存器在 RTL 和网表间的一一对应**给每个端点打标签，再用**"采样多条路径取最大到达时间"的自定义损失**训练，从而预测每个寄存器位的到达时间和关键性排序——未知设计上相关系数 0.89、排序覆盖率 80%，设计级 TNS/WNS 达到 0.98/0.91 的 SOTA。

真正让它从"预测论文"里跳出来的，是**把预测用起来了**：按预测排序给综合工具下发 `group_path` 和 `retime` 命令，平均改善 TNS 约 10%、WNS 约 3%，且布局后收益仍在。这回答了本仓库最关心的问题之一：**早期（RTL）的细粒度时序预测，能可靠地指导后端优化决策。**
